LogBrew utilise un seul terme pour chaque concept du produit. Les champs
d’API, les options de la CLI, les valeurs d’enum, les noms d’événements et les
clés d’attributs restent identiques dans toutes les langues.

## <span id="observability-and-monitoring">Observabilité et surveillance</span>

| Terme | Signification |
| --- | --- |
| Observabilité | Comprendre le comportement d’une application à partir des preuves qu’elle produit. |
| Télémétrie | Les signaux qu’une application envoie, comme les logs, les traces et les métriques. |
| Surveillance (monitoring) | Vérifier des conditions connues, par exemple une valeur mesurée par rapport à un seuil. |
| `o11y` | Abréviation de l’anglais « observability » (observabilité). Le nombre compte les 11 lettres entre `o` et `y`. |

Pour choisir un signal et voir des exemples détaillés, lisez
[Télémétrie](/fr/concepts/telemetry).

## <span id="ai-agents">Agents IA</span>

| Terme | Signification |
| --- | --- |
| Serveur MCP | Le serveur LogBrew hébergé pour le Model Context Protocol. Les agents IA l’utilisent pour lire les projets autorisés et, si vous le permettez, pour les modifier. |
| Client MCP | Une application qui connecte un agent IA à un serveur MCP, comme Claude Code. |
| Projet autorisé | Un projet que vous avez sélectionné en donnant l’accès à un client MCP. Le client peut utiliser uniquement les projets autorisés. |
| Connexion MCP | L’accès que vous donnez à 1 client MCP quand vous l’autorisez. Il prend fin après 30 jours sans utilisation, après 90 jours ou quand vous le révoquez. La CLI l’appelle un « grant ». |
| Scope | Ce qu’une connexion peut faire. `read` lit les projets autorisés. `write` peut aussi les modifier. Vous choisissez `write` quand vous autorisez la connexion. |

Pour connecter un client, lisez
[Connecter un agent IA avec MCP](/fr/guides/mcp).

## <span id="observability-signals">Signaux d’observabilité</span>

<AccordionGroup>
  <Accordion title="Problème">
    Un échec regroupé qui peut contenir plusieurs occurrences. Une occurrence
    est une instance capturée de ce problème. `first_seen_at` est l’heure de
    la première occurrence. `last_seen_at` est l’heure de l’occurrence la plus
    récente.
  </Accordion>

  <Accordion title="Log">
    Un enregistrement horodaté d’un événement (une entrée de journal). Un log
    peut porter une gravité, un service, une version, un environnement, un
    contexte de trace et des attributs limités par les règles de
    confidentialité.
  </Accordion>

  <Accordion title="Trace et span">
    Une trace suit le travail effectué au cours d’une requête ou d’une
    opération. Un span est une opération chronométrée dans cette trace. Une
    corrélation avec une trace est une preuve de contexte partagé ; ce n’est
    pas une preuve de cause.
  </Accordion>

  <Accordion title="Métrique">
    Une mesure d’exécution avec une unité, un type, une agrégation et une
    période définis. Les points de métrique ne sont pas interchangeables avec
    les nombres de logs, de traces ou de problèmes.
  </Accordion>

  <Accordion title="Version">
    Une version déployée d’une application ou d’un service, signalée avec la
    télémétrie. Une version n’est pas le même objet qu’un projet ou un dépôt.
  </Accordion>

  <Accordion title="Action">
    Un événement produit classé, comme une inscription, un paiement, un import
    ou une tâche en échec. Les analyses produit classent une action comme une
    vue de page, une vue d’écran ou une interaction. Une action n’est pas une
    commande automatique exécutée par LogBrew.
  </Accordion>
</AccordionGroup>

## <span id="issue-investigation">Investigation des problèmes</span>

Toutes les occurrences ne contiennent pas tous les champs.

| Terme | Signification |
| --- | --- |
| Gravité | L’urgence d’un signal : `info`, `warning`, `error` ou `critical`. Elle est distincte du statut du problème. |
| Statut du problème | L’état d’un problème regroupé dans le workflow : `unresolved`, `resolved` ou `archived`. Ce n’est pas le résultat d’une requête. |
| Problème archivé | Un problème que l’équipe a retiré du triage actif. Les anciennes réponses appellent ce statut `ignored`. |
| Priorité du problème | L’ordre de triage d’un problème regroupé : `high`, `medium` ou `low`. Elle suit la gravité jusqu’à ce qu’une personne la définisse. |
| Origine de la priorité | D’où vient la priorité. `derived` suit la gravité : `error` et `critical` donnent `high`, `warning` donne `medium` et `info` donne `low`. `manual` est une priorité définie par une personne. |
| Responsable du problème | Le compte ou l’équipe qui s’occupe de l’étape suivante d’un problème regroupé. Un problème en a 1 au plus. Un compte doit pouvoir lire le projet. Une équipe doit appartenir à l’organisation du projet. |
| Équipe | Un groupe de membres d’une organisation, qui porte un nom. Vous pouvez attribuer des problèmes à une équipe, et les règles de propriété peuvent la désigner. Une équipe ne donne à ses membres aucun accès aux projets. |
| Règle de propriété | Une règle du projet qui associe un chemin de frame de pile, un module, une route, un service ou un tag aux comptes ou aux équipes propriétaires des problèmes qui correspondent. |
| Propriétaire suggéré | Un compte ou une équipe que LogBrew propose pour un problème, d’après une règle de propriété, une ligne du fichier CODEOWNERS ou l’activité récente. C’est une suggestion, pas une attribution. |
| Boîte de réception | La liste des problèmes que d’autres personnes vous ont attribués, à vous ou à vos équipes. LogBrew n’envoie pas d’e-mail pour cette liste. |
| Trace de pile | La preuve capturée des appels de fonctions pour une erreur. Elle est différente d’une trace distribuée. |
| Frame de pile | Une entrée d’une trace de pile. Elle peut identifier une fonction, un module, un fichier, une ligne ou une colonne. |
| Chaîne d’exceptions | Des exceptions liées, signalées ensemble, comme une erreur et sa cause. Des entrées manquantes, masquées ou tronquées limitent les preuves. |
| Frame applicatif | Un frame de pile marqué comme code de l’application. Il montre du code à examiner. Il ne prouve pas la faute. |
| Breadcrumb | Un court événement enregistré avant une occurrence de problème. Les breadcrumbs ne sont pas un enregistrement complet d’une session. |
| Exception gérée | Une exception que l’application a signalée comme gérée. Elle ne prouve pas que l’opération a réussi. |
| Source map | Un artefact de build qui associe les emplacements du JavaScript généré aux emplacements du code source d’origine. |
| Frame symbolisé | Un frame dont l’emplacement généré a été résolu en informations du code source d’origine. |
| Occurrence de référence | L’occurrence capturée utilisée comme référence pour la reproduction. |
| Provenance | D’où vient une évaluation. `backend_observed` signifie que LogBrew l’a observée. `application_reported` signifie que l’application l’a signalée et que LogBrew ne l’a pas vérifiée. |
| Préparation à la reproduction | Indique si l’occurrence de référence contient les preuves nécessaires pour tenter une reproduction. Ce n’est pas un test de reproduction réussi. |

Pour l’ordre de lecture et les champs de la réponse, consultez le guide
[Investiguer un problème](/fr/guides/investigate-an-issue).

## <span id="identity-and-correlation">Identité et corrélation</span>

Une valeur manquante ne prouve pas que l’activité associée n’a pas eu lieu.

| Terme | Signification |
| --- | --- |
| Contexte de trace | Les identifiants de trace et de span qui relient le travail entre les signaux. |
| Span racine | Le span qui démarre une trace et n’a pas de span parent. Le premier span renvoyé n’est pas forcément la racine. |
| Span enfant | Un span qui a un span parent dans la même trace. |
| Corrélation | Une relation exacte renvoyée par LogBrew, comme un ID de trace partagé. Elle ne prouve pas la cause. |
| Utilisateur identifié | Un sujet fourni par l’application, avec un ID stable et le type `user`. |
| Sujet anonyme | Un sujet fourni par l’application, avec le type `anonymous`. Les décomptes le séparent des utilisateurs identifiés. |
| Type d’identité inconnu | Un sujet sans type connu. Il n’est pas compté comme utilisateur identifié. |
| Sujet manquant | Un événement sans sujet. C’est différent d’un sujet dont le type est inconnu. |

Le type d’identité montre comment l’application a classé son sujet. Il ne
prouve pas que les données sont anonymes. Un ID stable peut quand même relier
des activités.

## <span id="scope-and-data-quality">Périmètre et qualité des données</span>

| Terme | Signification |
| --- | --- |
| Projet | La principale limite de produit que vous possédez. Un projet peut contenir plusieurs services ou composants de dépôt. |
| Service | Un runtime ou un composant qui envoie des données, au sein d’un projet. |
| Environnement | Un contexte d’envoi exact, comme production ou staging. |
| Clé d’ingestion | Une clé de projet qui envoie de la télémétrie à un seul projet. Elle ne peut pas lire la télémétrie. |
| Clé de lecture | Une clé de projet qui lit la télémétrie d’un seul projet. Elle ne peut pas envoyer de télémétrie, modifier des données ni se connecter. Consultez [Types de clés de projet](/fr/guides/verify-setup#project-key-kinds). |
| Ingéré | Accepté selon le contrat d’ingestion. Cela ne garantit pas une conservation illimitée. |
| Indexé | Disponible pour l’index ou la requête indiqués. Ce n’est pas un synonyme d’ingéré. |
| Conservé | Présent dans la période de données évaluée et dans la durée de conservation des données du compte. |
| Échantillonné | Une partie de la télémétrie a été sélectionnée avant ou pendant la collecte. |
| Couverture | Une proportion mesurée, avec un numérateur et un dénominateur explicites. |
| Tronqué | La réponse a atteint une limite. Les données omises ne sont pas forcément absentes. |
| Approximatif | Estimé selon la méthode documentée plutôt que compté exactement. |
| Période | Le laps de temps exact qu’une requête évalue. |

## Forfaits et organisations

| Terme | Signification |
| --- | --- |
| Forfait | Un ensemble fixe de quotas mensuels avec une durée de conservation. Les forfaits sont Free, Pro, Business et Enterprise. |
| Quota | La quantité d’un type de télémétrie qu’un forfait inclut en 1 mois de facturation, par exemple les octets de logs ou les spans de trace. |
| Conservation des données | Le nombre de jours pendant lesquels LogBrew conserve la télémétrie d’un compte. LogBrew supprime la télémétrie plus ancienne. Ce n’est pas la rétention de l’analytique produit. |
| Offre des nouveaux comptes | Les quotas de Pro que les comptes créés avant le 2026-10-26 reçoivent gratuitement pendant 6 mois. Ensuite, le compte utilise son forfait propre. |
| Organisation | Un espace partagé pour les membres, les équipes et les projets. Chaque forfait a des organisations sans limite de membres ni de projets. |

Pour les quotas et la durée de conservation de chaque forfait, lisez [API de compte](/fr/reference/account-api).

## <span id="measurements-and-time">Mesures et temps</span>

| Terme | Signification |
| --- | --- |
| Point de données | Une valeur à une heure donnée. Lisez le nom et l’unité de la métrique avant de comparer des points de données. |
| Série temporelle | Les valeurs d’une même mesure, classées dans l’ordre chronologique. Un trou ne signifie pas que la valeur était nulle. |
| Durée | Le temps écoulé pendant une opération. C’est différent du moment où l’opération a eu lieu. |
| Agrégation | Un calcul défini sur plusieurs mesures, comme une somme ou une moyenne. |
| Intervalle | Une tranche de temps dans un graphique ou un résultat groupé. Son début et sa fin définissent son étendue. |
| Période incomplète | Une période qui n’est pas encore terminée. Ce n’est pas une période terminée sans activité. |

N’additionnez pas les durées de spans enfants qui se chevauchent pour obtenir
la durée totale d’une requête. Ne comparez pas un nombre d’événements avec un
nombre d’utilisateurs identifiés.

## <span id="evidence-states">États des preuves</span>

Ces états ne sont pas interchangeables :

- **Capturé :** la preuve est présente.
- **Manquant :** la preuve n’a pas été capturée.
- **Masqué :** la preuve a été volontairement cachée.
- **Tronqué :** la preuve a dépassé une limite de réponse ou de capture.
- **Indisponible :** la lecture n’a pas pu fournir la preuve.

`Likely cause` (cause probable) et `likely fix area` (zone de correction
probable) décrivent des preuves de diagnostic limitées, pas une cause racine
prouvée. `Reported impact` (impact signalé) est fourni par l’application qui
envoie les données, sauf si un contrat décrit explicitement une mesure
LogBrew.

## <span id="product-analytics">Analyses produit</span>

| Terme | Signification |
| --- | --- |
| Événement | Une activité produit classée, avec un nom stable exact. |
| Propriété | Une clé de contexte utilisée pour décrire ou filtrer un événement. |
| Session | Une visite ou une session d’application, pas une personne. |
| Cohorte | Un groupe limité, défini par des critères exacts. |
| Entonnoir | Des étapes ordonnées qui mesurent la progression ou la conversion. |
| Rétention | Le comportement de retour, mesuré avec une période et un dénominateur explicites. |
| Parcours | Les parcours de session avant ou après un événement sélectionné. |
| Cycle de vie | Classe les sujets identifiés de chaque période comme : nouveau dans l’historique observé, récurrent, réactivé ou inactif. |
| Nouveau dans l’historique observé | Actif sans événement sélectionné antérieur dans la période d’historique limitée. Cela ne désigne pas un nouveau client. |

Les périodes incomplètes, les identités manquantes, la capture incomplète des
propriétés, l’échantillonnage et la troncature nuancent le résultat. LogBrew
affiche ces limites au lieu de les transformer en zéro ou en certitude.

Pour les règles de comptage, lisez
[Analyses produit](/fr/concepts/product-analytics). Pour envoyer une activité
classée et une identité typée, utilisez
[Capture d’événements produit](/fr/guides/product-events).
