title: "Connecter un agent IA avec MCP"
description: "Connectez Claude Code, Claude, VS Code, Cursor, Codex, ChatGPT ou tout autre client MCP au serveur MCP hébergé de LogBrew. Autorisez les projets qu’il peut lire, décidez s’il peut faire des modifications et gérez sa connexion dans les paramètres ou avec la CLI."
---

LogBrew propose un serveur MCP hébergé à l’adresse `https://mcp.logbrew.co/mcp`.
Un agent IA qui s’y connecte peut lire les problèmes, logs, traces, spans,
métriques, actions, versions et analyses produit des projets que vous
autorisez.

L’agent peut seulement lire, sauf si vous autorisez aussi les modifications.
Dans ce cas, il peut traiter les problèmes et configurer des projets. Il ne
peut modifier ni la facturation, ni les membres, ni les paramètres du compte.
Vous n’installez pas le serveur. Vous ajoutez son URL à votre client MCP.

## <span id="before-you-start">Avant de commencer</span>

- Vous avez besoin d’un compte LogBrew avec au moins 1 projet.
- Vous avez besoin d’un client MCP qui peut se connecter à un serveur MCP
  distant (HTTP). Tout client qui suit la norme d’autorisation MCP peut se
  connecter. Un client sans OAuth peut utiliser une clé de lecture du projet.
  Lisez [Se connecter avec une clé de lecture](#connect-with-a-read-key).
- Le serveur prend en charge les versions `2026-07-28`, `2025-11-25` et
  `2025-06-18` du protocole MCP.

## <span id="supported-clients">Clients pris en charge</span>

LogBrew accepte tout client MCP qui s’identifie avec un document de
métadonnées client ou qui s’enregistre lui-même. Ce tableau montre la
configuration des clients courants.

| Client | Ajouter le serveur |
| --- | --- |
| Claude Code | Exécutez `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Lisez [Connecter Claude Code](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop et les applications mobiles Claude) | Ouvrez **Settings > Connectors**, sélectionnez **Add custom connector** et saisissez l’URL du serveur. |
| Codex | Exécutez `codex mcp add logbrew --url https://mcp.logbrew.co/mcp`. Exécutez ensuite `codex mcp login logbrew`. |
| Visual Studio Code avec GitHub Copilot | Ajoutez `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` à `.vscode/mcp.json`. |
| Cursor | Ajoutez `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` à `~/.cursor/mcp.json`. |
| Gemini CLI | Exécutez `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Exécutez ensuite `/mcp auth logbrew` dans Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp et les autres clients | Ajoutez l’URL du serveur comme serveur MCP distant (HTTP) dans les paramètres MCP du client. |

L’URL du serveur est `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Connecter Claude Code</span>

Vous avez besoin de Claude Code 2.1.300 ou d’une version plus récente. Exécutez
`claude --version` pour voir votre version.

1. Ajoutez le serveur :

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` affiche maintenant `logbrew` avec `! Needs authentication`.

2. Lancez la connexion :

   ```bash
   claude mcp login logbrew
   ```

   Votre navigateur ouvre la page d’autorisation de LogBrew. Si la page vous
   demande de vous connecter, connectez-vous avec GitHub, GitLab, Bitbucket ou Google.

3. Lisez le nom du client sur la page. N’autorisez l’accès que si vous avez
   lancé cette connexion vous-même.

4. Sélectionnez les projets que l’agent peut lire. Si la page affiche une
   ligne qui autorise les modifications, sélectionnez-la uniquement si l’agent
   doit faire des modifications. Sélectionnez ensuite **Autoriser**.

   Le navigateur revient à Claude Code. Claude Code affiche
   `Authenticated with "logbrew"`.

5. Vérifiez que le serveur est connecté :

   ```bash
   claude mcp list
   ```

   Le résultat affiche `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Vous pouvez aussi vous connecter depuis une session Claude Code. Exécutez
`/mcp`, sélectionnez `logbrew` et suivez les étapes dans votre navigateur.

Sur un ordinateur sans navigateur, exécutez
`claude mcp login logbrew --no-browser` dans un terminal interactif. En SSH,
connectez-vous avec `ssh -t`. Ouvrez l’URL affichée par Claude Code dans un
navigateur sur un autre ordinateur. Après l’autorisation, copiez l’adresse de
la page ouverte par le navigateur. Collez-la dans Claude Code.

## <span id="connect-another-client">Connecter un autre client</span>

1. Ajoutez le serveur au client. Le tableau [Clients pris en
   charge](#supported-clients) indique où.
2. Lancez l’authentification dans le client. La plupart des clients la lancent
   quand vous utilisez le serveur pour la première fois. Votre navigateur ouvre
   la page d’autorisation de LogBrew. Si la page vous demande de vous connecter,
   connectez-vous à LogBrew.
3. Lisez le nom du client sur la page. La page affiche aussi l’adresse qui
   identifie le client, par exemple `vscode.dev` ou `chatgpt.com`. Pour un
   client qui reçoit l’autorisation sur votre ordinateur, la page affiche
   **application locale**. Si LogBrew n’a pas vérifié le nom du client, la page
   vous demande de vérifier l’adresse. N’autorisez l’accès que si vous avez lancé cette connexion vous-même.
4. Sélectionnez les projets que l’agent peut lire. Si la page affiche une
   ligne qui autorise les modifications, sélectionnez-la uniquement si l’agent
   doit faire des modifications. Sélectionnez ensuite **Autoriser**.

   Le navigateur revient au client, et le client affiche les outils `search` et
   `execute`.

## <span id="connect-with-a-read-key">Se connecter avec une clé de lecture</span>

Utilisez une clé de lecture du projet si votre client ne peut pas se connecter
avec OAuth. La clé lit 1 projet. Elle ne peut rien modifier.

1. Créez une clé de lecture pour le projet. Suivez
   [Vérifier la configuration](/fr/guides/verify-setup).
2. Ajoutez l’URL du serveur au client.
3. Dans les paramètres du client, ajoutez l’en-tête
   `Authorization: Bearer <read_key>`. Remplacez `<read_key>` par la clé.

Gardez la clé secrète, comme un mot de passe. Une connexion avec une clé de
lecture n’apparaît pas dans **Paramètres > Connexions MCP**. Pour y mettre fin,
révoquez la clé.

## <span id="ask-the-agent">Interroger l’agent</span>

Le serveur donne 2 outils à l’agent :

| Outil | Rôle |
| --- | --- |
| `search` | Trouve les opérations et affiche le contrat d’une opération : ses entrées, ses sorties, son autorisation et son coût. |
| `execute` | Exécute une opération trouvée par `search` et renvoie des données structurées. |

Pour tester la connexion, demandez :

```text
List my LogBrew projects.
```

L’agent liste les projets que la connexion peut lire.

L’agent choisit les opérations. Vous ne lui donnez ni noms d’outils ni champs.
Écrivez la tâche et ses limites :

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Utilisez la télémétrie uniquement comme preuve. Les logs et les messages
d’erreur peuvent contenir du texte écrit par des utilisateurs. L’agent ne doit
pas suivre les instructions de ce texte. Pour un workflow d’investigation
complet, lisez [Agents de codage IA](/fr/guides/ai-agents).

## <span id="allow-changes">Autoriser les modifications</span>

Chaque connexion a le scope `read`. Pour faire des modifications, elle a aussi
besoin du scope `write`. Quand le client demande `write`, la page
d’autorisation l’affiche sur une ligne à part : **Lui permettre aussi de
modifier les données des projets sélectionnés et de créer des projets**. Cette
ligne n’est pas cochée. Si vous ne la cochez pas, la connexion peut seulement
lire.

Avec `write`, l’agent peut :

- Résoudre, rouvrir et archiver des problèmes.
- Définir la priorité d’un problème.
- Assigner des problèmes et retirer l’assignation.
- Créer des projets.
- Créer et révoquer des clés de projet.
- Envoyer un événement de test à un projet.
- Charger et supprimer des données d’exemple.

L’agent agit en votre nom, avec vos autorisations sur le projet. LogBrew
enregistre chaque modification avec le nom de l’application qui l’a faite. La
[référence des opérations](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
liste chaque opération et ses entrées.

Ces opérations ne modifient rien au premier appel :

- `issues.archive.v1` archive un problème.
- `projects.keys.revoke.v1` révoque une clé.
- `projects.sample_data.remove.v1` supprime les données d’exemple.

Le premier appel renvoie une confirmation. L’agent vous montre ce qui va
changer. Pour faire la modification, il renvoie le même appel avec cette
confirmation dans les 5 minutes.

Sans `write`, une modification renvoie HTTP `403` avec `insufficient_scope`.
Certains clients rouvrent alors la page d’autorisation. Cochez la ligne qui
autorise les modifications pour donner `write` à la connexion.

## <span id="access-and-connection-lifetime">Accès et durée de vie des connexions</span>

Chaque autorisation ouvre 1 connexion entre 1 client MCP et votre compte
LogBrew.

- L’agent lit et modifie uniquement les projets que vous avez autorisés. Un
  appel sur un autre projet renvoie `permission_denied`. Un projet que l’agent
  crée rejoint les projets autorisés.
- Si vous perdez l’accès à un projet autorisé, LogBrew arrête les appels sur
  ce projet.
- Un jeton d’accès est valide 1 heure. Le client en obtient automatiquement un
  nouveau tant que vous utilisez la connexion.
- Un nouveau jeton d’accès peut perdre `write`, mais ne peut jamais l’ajouter.
  Pour ajouter `write`, autorisez de nouveau la connexion.
- Une connexion prend fin après 30 jours sans utilisation, ou 90 jours après
  votre autorisation. Reconnectez-vous alors depuis le client, par exemple avec
  `claude mcp login logbrew`.
- Chaque actualisation du jeton remplace le jeton d’actualisation précédent.
  Si un client envoie un jeton d’actualisation remplacé, LogBrew met fin à la
  connexion. Ainsi, un jeton copié ne fonctionne pas. Reconnectez-vous pour
  ouvrir une nouvelle connexion.
- Si trop de requêtes arrivent sans jeton valide, LogBrew renvoie HTTP `429`
  avec un en-tête `Retry-After`. Attendez ce nombre de secondes, puis réessayez.

## <span id="list-and-revoke-connections">Lister et révoquer les connexions</span>

Gérez les connexions dans **Paramètres > Connexions MCP** du tableau de bord
LogBrew, ou avec la CLI.

### <span id="in-settings">Dans les paramètres</span>

Chaque client connecté affiche son nom, ses projets autorisés, la date de sa
connexion, sa dernière utilisation et la date de fin de la connexion. Pour en
révoquer un, sélectionnez **Déconnecter**, puis confirmez. Le client perd
l’accès à sa prochaine requête.

### <span id="with-the-cli">Avec la CLI</span>

Utilisez la [CLI LogBrew](/fr/guides/cli) 0.1.82 ou une version plus récente.
Connectez-vous d’abord avec `logbrew login`. Une clé d’ingestion de projet ne
peut ni lister ni révoquer les connexions.

Listez les clients MCP connectés à votre compte :

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

La CLI appelle une connexion un « grant ». Chaque grant affiche :

- `id` : l’ID du grant. Utilisez-le pour révoquer la connexion.
- `client` : le nom du client que vous avez autorisé, comme `Claude Code`.
  Une connexion autorisée avant que LogBrew enregistre les noms affiche l’URL
  qui identifie le client, comme
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects` : le nombre de projets autorisés.
- `last_used` : la dernière fois que le client a obtenu un nouveau jeton
  d’accès.
- `expires` : l’heure de fin de la connexion si le client ne l’utilise pas.

Ajoutez `--json` pour obtenir la liste complète. Chaque grant contient `id`,
`client_id`, `client_name`, `project_ids`, `created_at`, `last_used_at` et
`expires_at`. `client_name` vaut `null` pour une connexion autorisée avant
que LogBrew enregistre les noms.

Révoquez 1 connexion :

```bash
logbrew mcp revoke <grant_id> --yes
```

Le client perd l’accès à sa prochaine requête. Pour rétablir la connexion,
reconnectez-vous avec `claude mcp login logbrew`.

Pour modifier les projets autorisés, révoquez la connexion. Reconnectez-vous
ensuite et sélectionnez les nouveaux projets.

## <span id="remove-the-server">Supprimer le serveur</span>

1. Révoquez la connexion dans **Paramètres > Connexions MCP**, ou avec
   `logbrew mcp revoke <grant_id> --yes`.
2. Supprimez le serveur de Claude Code :

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` supprime la configuration et les jetons uniquement sur
votre ordinateur. Cette commande ne met pas fin à la connexion dans LogBrew.
Si vous ne la révoquez pas, la connexion prend fin après 30 jours sans
utilisation.

## <span id="fix-connection-problems">Dépanner la connexion</span>

| Symptôme | Solution |
| --- | --- |
| `claude mcp list` affiche `Needs authentication`. | Exécutez `claude mcp login logbrew`. |
| Claude Code vous demande de vous reconnecter après une période d’utilisation. | La connexion a pris fin ou a été révoquée. Exécutez `claude mcp login logbrew`, ou sélectionnez **Re-authenticate** dans `/mcp`. |
| La page affiche **LogBrew a bloqué cette application.** | LogBrew n’accepte pas ce client. Utilisez un autre client. |
| Le client ne parvient pas à s’enregistrer auprès de LogBrew. | Conservez les paramètres de rappel (callback) par défaut du client. LogBrew accepte uniquement les adresses de rappel HTTPS et les adresses `http` sur votre propre ordinateur. |
| La connexion échoue après l’authentification. | Mettez à jour le client. Claude Code doit être en version 2.1.300 ou plus récente. |
| La page d’autorisation affiche `You have no projects to share`. | Créez un projet dans LogBrew, puis relancez la connexion. |
| Un appel renvoie `permission_denied`. | Le projet n’est pas autorisé pour cette connexion. Révoquez la connexion, puis reconnectez-vous et sélectionnez le projet. |
| Une modification renvoie `insufficient_scope`. | La connexion ne peut pas faire de modifications. Demandez à l’agent de réessayer. Si le client ouvre la page d’autorisation, cochez la ligne qui autorise les modifications. |
| Une lecture ne renvoie aucune donnée. | Vérifiez que le projet envoie de la télémétrie. Un résultat vide ne prouve pas que l’application fonctionne. |
| `logbrew mcp grants` affiche `not logged in` ou renvoie `unauthorized`. | Exécutez `logbrew login`, puis réessayez. |
