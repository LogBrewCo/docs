LogBrew は、プロダクトの1つの概念に1つの用語を使います。API のフィールド、CLI のフラグ、enum の値、イベント名、属性キーは、どの言語でも変わりません。

## Observability とモニタリング

| 用語 | 意味 |
| --- | --- |
| Observability（可観測性） | アプリケーションが生成する証拠から、その動作を理解すること。 |
| テレメトリ | アプリケーションが報告するシグナル。ログ、トレース、メトリクスなどです。 |
| モニタリング | 測定値としきい値の比較など、既知の条件を確認すること。 |
| `o11y` | observability の短縮形。数字は、`o` と `y` の間にある 11文字を数えたものです。 |

シグナルの選び方と具体例については、[テレメトリ](/ja/concepts/telemetry)を参照してください。

## AI エージェント

| 用語 | 意味 |
| --- | --- |
| MCP サーバー | Model Context Protocol のための、ホスト型の LogBrew サーバー。AI エージェントは、承認済みプロジェクトの読み取りと、許可した場合はその変更に使います。 |
| MCP クライアント | Claude Code など、AI エージェントを MCP サーバーに接続するアプリケーション。 |
| 承認済みプロジェクト | MCP クライアントにアクセス権を与えたときに選んだプロジェクト。クライアントが使えるのは、承認済みプロジェクトだけです。 |
| 接続 | 1つの MCP クライアントを承認したときに与えるアクセス権。30日間使われないとき、90日が経ったとき、または無効化したときに終了します。CLI では grant と呼びます。 |
| スコープ | 接続でできること。`read` は承認済みプロジェクトを読み取ります。`write` はそれらの変更もできます。`write` を与えるかどうかは、接続を承認するときに選びます。 |

クライアントを接続するには、[MCP で AI エージェントを接続する](/ja/guides/mcp)を参照してください。

## Observability のシグナル

<AccordionGroup>
  <Accordion title="課題">
    複数の発生事象を含むことがある、グループ化された問題です。発生事象は、その課題を取得した1件の事例です。`first_seen_at` は最初の発生事象の時刻です。`last_seen_at` は最新の発生事象の時刻です。
  </Accordion>

  <Accordion title="ログ">
    タイムスタンプ付きの1件のイベントの記録です。ログには、重大度、サービス、リリース、環境、トレースコンテキスト、プライバシーの範囲内の属性を持たせられます。
  </Accordion>

  <Accordion title="トレースとスパン">
    トレースは、リクエストや処理にまたがる作業をたどります。スパンは、そのトレース内で時間を計測した1つの処理です。トレースとの相関は、コンテキストを共有していることの証拠です。原因の証明ではありません。
  </Accordion>

  <Accordion title="メトリクス">
    単位、種類、集計、期間が定義された、実行時の測定値です。メトリクスのポイントは、ログ、トレース、課題の件数と置き換えられません。
  </Accordion>

  <Accordion title="リリース">
    テレメトリとともに報告される、デプロイされたアプリケーションやサービスのバージョンです。リリースは、プロジェクトやリポジトリとは別のものです。
  </Accordion>

  <Accordion title="アクション">
    サインアップ、チェックアウト、インポート、失敗したジョブなど、分類されたプロダクトイベントです。分析では、アクションをページビュー、スクリーンビュー、インタラクションのいずれかに分類します。アクションは、LogBrew が実行する自動のコマンドではありません。
  </Accordion>
</AccordionGroup>

## 課題の調査

すべての発生事象にすべてのフィールドがあるとは限りません。

| 用語 | 意味 |
| --- | --- |
| 重大度 | シグナルの緊急度。`info`、`warning`、`error`、`critical` のいずれかです。課題のステータスとは別のものです。 |
| 課題のステータス | グループ化された課題のワークフローの状態。`unresolved`、`resolved`、`archived` のいずれかです。1件のリクエストの結果ではありません。 |
| アーカイブ済みの課題 | チームが、進行中のトリアージから外した課題。以前のレスポンスでは、このステータスを `ignored` と呼びます。 |
| 課題の優先度 | グループ化された課題をトリアージする順序。`high`、`medium`、`low` のいずれかです。人が設定するまでは重大度に従います。 |
| 優先度の設定元 | 優先度がどこから来たか。`derived` は重大度に従います。`error` と `critical` は `high`、`warning` は `medium`、`info` は `low` です。`manual` は人が設定した優先度です。 |
| 課題の担当者 | グループ化された課題の次の手順を受け持つ、1つのアカウントまたは1つのチーム。アカウントはそのプロジェクトを読み取れる必要があります。チームはプロジェクトが属する組織のチームである必要があります。 |
| チーム | 組織のメンバーをまとめた、名前の付いたグループ。課題をチームに割り当てたり、オーナーシップルールでチームを指定したりできます。チームに入っても、プロジェクトへのアクセス権は付与されません。 |
| オーナーシップルール | スタックフレームのパス、モジュール、ルート、サービス、タグを、一致した課題のオーナーであるアカウントやチームに結び付ける、プロジェクトのルール。 |
| オーナー候補 | LogBrew が課題に対して提案するアカウントまたはチーム。オーナーシップルール、CODEOWNERS の行、最近の操作をもとに選ばれます。提案であり、割り当てではありません。 |
| 受信トレイ | ほかの人があなたやあなたのチームに割り当てた課題の一覧。LogBrew はこれについてメールを送信しません。 |
| スタックトレース | エラーについて取得した、関数呼び出しの証拠。分散トレースとは別のものです。 |
| スタックフレーム | スタックトレースの1つのエントリー。関数、モジュール、ファイル、行、列を示すことがあります。 |
| 例外チェーン | エラーとその原因など、一緒に報告された、互いに結び付いた例外。未取得、秘匿済み、一部省略のエントリーがあると、証拠は限られます。 |
| アプリケーションフレーム | アプリケーションコードとして印が付いたスタックフレーム。確認すべきコードを示します。不具合を証明するものではありません。 |
| 直前の手順（ブレッドクラム） | 課題の発生事象の前に記録された短いイベント。直前の手順は、セッションの完全な記録ではありません。 |
| 処理済みの例外 | アプリケーションが処理済みとして報告した例外。処理が成功したことを証明するものではありません。 |
| ソースマップ | 生成された JavaScript の位置を、元のソースの位置に対応付けるビルド成果物。 |
| シンボル化済みフレーム | 生成された位置が、元のソースの情報に解決されたフレーム。 |
| 基準とする発生事象 | 再現の基準として使う、取得済みの発生事象。 |
| 出所 | 評価がどこから来たか。`backend_observed` は、LogBrew が観測したことを示します。`application_reported` は、アプリが報告し、LogBrew が検証していないことを示します。 |
| 再現の準備状況 | 基準とする発生事象に、再現を試すのに必要な証拠があるかどうか。再現テストに合格したという意味ではありません。 |

読む順序とレスポンスのフィールドについては、[課題を調査する](/ja/guides/investigate-an-issue)を参照してください。

## 識別と相関

値がないことは、関連する活動が起きなかったことの証明にはなりません。

| 用語 | 意味 |
| --- | --- |
| トレースコンテキスト | シグナルをまたいで作業を結び付ける、トレースとスパンの識別子。 |
| ルートスパン | トレースを開始し、親スパンを持たないスパン。返された中で最も早いスパンが、ルートとは限りません。 |
| 子スパン | 同じトレース内に親スパンを持つスパン。 |
| 相関 | 共有されたトレース ID など、LogBrew が返す正確な関係。原因を証明するものではありません。 |
| 識別済みユーザー | アプリが渡したサブジェクトのうち、変わらない ID と種類 `user` を持つもの。 |
| 匿名サブジェクト | アプリが渡したサブジェクトのうち、種類が `anonymous` のもの。件数では、識別済みユーザーと分けて数えます。 |
| 不明な識別の種類 | 既知の種類を持たないサブジェクト。識別済みユーザーとしては数えません。 |
| サブジェクトなし | サブジェクトを持たないイベント。種類が不明なサブジェクトとは別のものです。 |

識別の種類は、アプリがサブジェクトをどう分類したかを示します。データが匿名であることを証明するものではありません。変わらない ID からは、活動を結び付けられることがあります。

## 範囲とデータの品質

| 用語 | 意味 |
| --- | --- |
| プロジェクト | 所有するプロダクトの主な境界。1つのプロジェクトに、複数のサービスやリポジトリのコンポーネントを含められます。 |
| サービス | プロジェクト内で報告を行うランタイムやコンポーネント。 |
| 環境 | 本番環境やステージング環境など、報告が行われた具体的なコンテキスト。 |
| 取り込みキー | 1つのプロジェクトにテレメトリを送信するプロジェクトキー。テレメトリは読み取れません。 |
| 読み取りキー | 1つのプロジェクトのテレメトリを読み取るプロジェクトキー。テレメトリの送信、データの変更、サインインはできません。[プロジェクトキーの種類](/ja/guides/verify-setup#project-key-kinds)を参照してください。 |
| 取り込み済み | 取り込みの仕様に従って受け付けられた状態。無期限の保持を約束するものではありません。 |
| インデックス済み | 指定したインデックスやクエリで利用できる状態。取り込み済みと同じ意味ではありません。 |
| 保持済み | 評価するデータの期間内に存在し、アカウントのデータ保持期間内にある状態。 |
| サンプリング済み | 収集の前または途中で、テレメトリの一部が選ばれた状態。 |
| カバレッジ | 分子と分母を明示して測定した割合。 |
| 一部省略 | レスポンスが上限に達した状態。省略されたデータが存在しないとは限りません。 |
| 概算 | 正確に数えたのではなく、記載された方法で推定した値。 |
| 期間 | クエリが評価する正確な時間の範囲。 |

## プランと組織

| 用語 | 意味 |
| --- | --- |
| プラン | 月ごとの使用量の上限と保持期間を固定で定めたもの。プランは Free、Pro、Business、Enterprise です。 |
| 使用量の上限 | プランが請求月 1 か月に含む、1 種類のテレメトリの量。たとえばログのバイト数やトレースのスパン数です。 |
| データ保持期間 | LogBrew がアカウントのテレメトリを保管する日数。LogBrew は、これより古いテレメトリを削除します。プロダクト分析の再訪とは別のものです。 |
| ベータ特典 | 2026-10-26 より前に作成したアカウントが 6 か月間無料で受け取る Pro の使用量の上限。その後、アカウントは自身のプランを使います。 |
| 組織 | メンバー、チーム、プロジェクトで共有する場所。どのプランにも組織があり、メンバー数とプロジェクト数に上限はありません。 |

各プランの使用量の上限とデータ保持期間は、[アカウント API](/ja/reference/account-api)を読んでください。

## 測定と時間

| 用語 | 意味 |
| --- | --- |
| データポイント | 報告された時刻における1つの値。データポイントを比較する前に、メトリクスの名前と単位を確認します。 |
| 時系列 | 同じ測定の値を時間順に並べたもの。データの欠けている部分は、値が 0 だったことを意味しません。 |
| 所要時間 | 処理にかかった時間。処理が発生した時刻とは別のものです。 |
| 集計 | 合計や平均など、測定値に対して定義された計算。 |
| 時間バケット | グラフやグループ化された結果の1つの集計区間。開始と終了で範囲が決まります。 |
| 部分期間 | まだ終わっていない期間。アクティビティが 0 で終わった期間ではありません。 |

リクエスト全体の時間を求めるために、重なり合う子スパンの所要時間を足さないでください。イベントの件数を、識別済みユーザーの数と比較しないでください。

## 証拠の状態

これらの状態は置き換えられません。

- **取得済み**：証拠があります。
- **未取得**：証拠は取得されませんでした。
- **秘匿済み**：証拠は意図的に隠されました。
- **一部省略**：証拠がレスポンスまたは取得の上限を超えました。
- **利用不可**：読み取りで証拠を提供できませんでした。

`Likely cause`（推定原因）と `likely fix area`（推定修正箇所）は、範囲の限られた診断の証拠を表します。証明された根本原因ではありません。`Reported impact`（報告された影響）は、LogBrew の測定であると仕様に明記されていない限り、報告元のアプリケーションが提供した値です。

## プロダクト分析

| 用語 | 意味 |
| --- | --- |
| イベント | 正確で変わらない名前を持つ、分類されたプロダクトのアクティビティ。 |
| プロパティ | イベントの説明や絞り込みに使うコンテキストのキー。 |
| セッション | 1回の訪問またはアプリのセッション。人ではありません。 |
| コホート | 正確な条件で定義された、範囲の限られたグループ。 |
| ファネル | 進行やコンバージョンを測定するための、順序の付いたステップ。 |
| 再訪 | 期間と分母を明示して測定した、ユーザーが戻ってくる行動。 |
| パス | 選んだイベントの前後にあるセッションの経路。 |
| ライフサイクル | 期間ごとに、識別済みのサブジェクトを観測履歴内で新規、継続、再アクティブ化、休眠に分類します。 |
| 観測履歴内で新規 | 範囲の限られた履歴の期間内に、選んだイベントがそれ以前にない状態でアクティブなこと。初めての顧客という意味ではありません。 |

部分期間、識別の欠落、不完全なプロパティの取得、サンプリング、一部省略は、結果に条件を付けます。LogBrew はこれらの制限を 0 や確定した値に変えず、そのまま表示します。

数え方のルールについては、[プロダクト分析](/ja/concepts/product-analytics)を参照してください。分類されたアクティビティと型付きの識別情報を送信するには、[プロダクトイベントの取得](/ja/guides/product-events)を使います。
