The LogBrew mobile app shows new telemetry and issues from your account when
you are away from a computer. The CLI and API remain the full workflow for
investigations and for coding agents.

To send telemetry from your own iOS, Android, or React Native app, install
its SDK instead. Start with the [SDK ingestion guide](/guides/sdk-ingestion).

## <span id="what-the-app-shows">What the app shows</span>

| Feature | Use it for |
| --- | --- |
| Live stream | New log, issue, trace span, and action events. |
| Push notifications | Alerts for important unresolved issues and release activity. |
| Issue triage | The issue status, release, environment, and occurrence count. |
| Release context | The release that sent the telemetry. |

The project is the access scope. The service is the app or process that sent
an event. If one view is empty, another signal type can still have data.

## <span id="live-event-names">Live stream</span>

The live stream shows new events while the app is open. A live indicator
means that the app listens for new events. It does not mean that every
project has recent data. A lost connection does not show that the project
stopped sending telemetry.

For a custom client, the
[response shapes reference](/reference/telemetry-response-shapes) defines the
live event names and formats.

## Triage an issue

1. Read the project, service, severity, and status.
2. Read the environment and release before you compare deployments.
3. Open a trace only when the issue has a trace link. An issue without trace
   context is different from a trace that failed to load.
4. Resolve the issue only after you read its evidence. Resolving changes the
   issue status. It does not delete events or show that the code is fixed.

## <span id="how-it-fits-with-agents">Continue with the CLI</span>

Copy the issue or trace ID from the app, then use the [CLI](/guides/cli):

```bash
logbrew read issue "<issue_id>" --json
logbrew read trace "<trace_id>" --json
logbrew explain issue "<issue_id>" --json
```

Keep credentials, ingest keys, customer data, and private source out of
prompts and support reports. When the CLI reports evidence as missing,
unavailable, redacted, or truncated, keep that state in the handoff.
