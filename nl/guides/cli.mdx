Met de LogBrew-opdrachtregelinterface (CLI) lees je logs, issues, traces en
acties vanuit een terminal. De CLI kan ook de issuestatus wijzigen. Gebruik
`--json` voor gestructureerde uitvoer naar scripts en AI-agents.

Vervang elke placeholder tussen punthaken voordat je een opdracht uitvoert.
Gebruik project-, issue- en trace-ID's die LogBrew heeft teruggegeven.

## <span id="install-the-cli">De CLI installeren</span>

Kies één installatiemethode.

macOS of Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
```

Homebrew:

```bash
brew install LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install logbrew-cli
```

Op Windows kun je ook de MSI installeren uit de
[nieuwste release](https://github.com/LogBrewCo/cli/releases/latest).

<Note>
  Cargo heeft Rust 1.87 of nieuwer nodig. De andere methoden installeren een
  native binary en hebben geen Rust nodig.
</Note>

## <span id="update-the-cli">De CLI bijwerken</span>

De CLI werkt zichzelf niet bij. Gebruik dezelfde methode waarmee je de CLI hebt
geïnstalleerd.

Homebrew:

```bash
brew update && brew upgrade LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install --locked logbrew-cli
```

Heb je de shell- of PowerShell-installer gebruikt? Voer de installer dan
opnieuw uit.

Lees daarna de versie. Vergelijk die met de
[nieuwste release](https://github.com/LogBrewCo/cli/releases/latest):

```bash
logbrew version --json
```

De JSON bevat `ok`, `name`, `version`, `binary`, `os` en `arch`.

## <span id="sign-in-and-verify-the-session">Inloggen en de sessie controleren</span>

Lees uit welk account deze terminal gebruikt:

```bash
logbrew status --json
logbrew whoami --json
```

Toont `whoami` het verwachte account? Ga dan verder. Zo niet, log dan in. Een
persoon rondt het inloggen bij de provider af in de browser. Een coding agent
moet een persoon vragen om deze stap te doen.

```bash
logbrew login --provider github
```

De provider is `github` (standaard), `gitlab`, `bitbucket` of `google`.

Op een machine die geen browser kan openen, zoals een SSH-sessie, een
container of een CI-job, log je in via een ander apparaat:

```bash
logbrew login --device
```

De CLI toont een link en een korte code. Open de link op een willekeurig
apparaat, zoals je telefoon of laptop. Controleer of de pagina dezelfde code
toont en keur daarna goed. De CLI wacht maximaal 10 minuten. Kan de CLI geen
browser openen, dan schakelt hij automatisch over op inloggen via een ander
apparaat. `--no-open` doet hetzelfde als `--device`.

Met `--json` toont de CLI de link en de code als één JSON-regel, en daarna het
resultaat als tweede JSON-regel. Een coding agent kan de link en de code aan
een persoon geven en wachten.

Voer na het inloggen opnieuw `status` en `whoami` uit. Zet geen
toegangsgegevens van je account in een prompt, rapport of bronbestand.

## <span id="set-up-a-project">Een project installeren</span>

Ga naar de map met het pakket- of buildmanifest van de app. Kies in een
monorepo één app of service. Voer daarna uit:

```bash
logbrew setup
```

Setup kiest of maakt een project, installeert de SDK, schrijft de
ingest-sleutel naar het env-bestand en voegt de initialisatiecode toe. Het laat
elke bestandswijziging zien en vraagt je om te bevestigen. Daarna verzendt het
een testevent dat LogBrew terugleest. Zie [Installeren met één
opdracht](/nl/quickstart#set-up-with-one-command).

Agents en scripts voegen `--yes --json` toe. Deze opties voegen stappen toe:

| Optie | Effect |
| --- | --- |
| `--mcp` | Voegt de gehoste MCP-server toe aan de projectconfiguratie van Claude Code, Cursor en VS Code. |
| `--project <project_id>` | Gebruikt een bestaand project. |
| `--sample-data` | Laadt voorbeelddata in een project zonder events. |

## <span id="plan-sdk-setup">De SDK-installatie plannen</span>

Om het installatieplan te lezen zonder iets te wijzigen, voer je uit:

```bash
logbrew setup --json
```

Lees `detected`, `install_ready`, `install_plan` en `next`. Het plan noemt de
runtime, het framework, de pakketbeheerder en de installatieopdracht. De CLI
installeert geen pakketten en wijzigt geen bestanden. `logbrew init`,
`install`, `configure` en `sdk` geven hetzelfde plan.

<Warning>
  Zet een ingest-sleutel van het project in de SDK-configuratie. Gebruik nooit
  toegangsgegevens van je account als SDK-sleutel. Houd ingest-sleutels buiten
  versiebeheer.
</Warning>

Zie [SDK-integratie](/nl/guides/sdk-ingestion) voor de stappen per runtime.
Voer `logbrew examples` uit voor een korte lijst met veelgebruikte opdrachten.

## <span id="read-create-and-configure-projects">Projecten lezen, aanmaken en instellen</span>

Toon de actieve projecten in je account:

```bash
logbrew projects --json
```

Kies een project-ID uit het resultaat. Gebruik dat ID voor sleutels en
leesacties.

Wil je een ingest-sleutel maken voor een bestaand project? Kies dan een nieuw
bestand buiten versiebeheer. De CLI schrijft de sleutel naar dat bestand, dat
alleen voor de eigenaar toegankelijk is. De CLI toont de sleutel en het
bestandspad niet.

```bash
logbrew projects keys create "<project_id>" --ingest-key-file "<private_key_file>" --json
```

| Optie | Waarde |
| --- | --- |
| `--kind` | `sdk` (standaard), `browser`, `server`, `cli`, `artifact` of `read`. Met een `artifact`-sleutel upload je source maps en native debugbestanden. Telemetrie verzenden kan er niet mee. Een `read`-sleutel leest de telemetrie van 1 project en kan geen telemetrie verzenden. Zie [Soorten projectsleutels](/nl/guides/verify-setup#project-key-kinds). |
| `--label` | Een naam voor de sleutel, maximaal 120 tekens. De standaardwaarde is `CLI-created SDK key`. |

Het JSON-resultaat bevat `status`, `project_id`, `ingest_key`, `checks` en
`next`. `ingest_key` bevat de `id`, `label`, `kind`, `created_at` en
`expires_at` van de sleutel. Zie
[Een ingest-sleutel roteren](/nl/guides/rotate-ingest-key) om een sleutel te
vervangen.

Trek een sleutel in met de `id` uit dat resultaat:

```bash
logbrew projects keys revoke "<project_id>" "<key_id>" --yes --json
```

De sleutel werkt niet meer vanaf het volgende request.

Deze opdracht maakt toegangsgegevens aan. Controleer of het project klopt
voordat je de opdracht uitvoert. Is het resultaat onzeker? Voer dan dezelfde
opdracht opnieuw uit. De CLI hergebruikt dan de lopende poging. Gebruik
`--abandon-retry` alleen om een nieuwe poging te starten.

Volg de [snelstart](/nl/quickstart) om een nieuw project te maken. Die gebruikt
`logbrew projects create "<name>" --ingest-key-file "<private_key_file>"`, dat
de eerste sleutel op dezelfde manier opslaat. Voer
`logbrew setup --create-project` uit om de helptekst voor het maken van een project
te lezen. Die opdracht maakt geen project aan.

Na een installatiestap kun je die stap voor het project registreren. De waarde
van `--source` is `api`, `cli` of `sdk`:

```bash
logbrew projects setup "<project_id>" --source cli --environment production --json
```

Lees daarna of het project klaar is:

```bash
logbrew doctor --project "<project_id>" --json
```

Exitcode `0` betekent niet dat alle controles zijn geslaagd. Lees de `status`
van het rapport en elke controle. Zie de [referentie voor het
doctor-rapport](/nl/reference/cli#read-a-project-doctor-report).

## <span id="read-account-usage">Accountgebruik lezen</span>

Lees je gebruik en je limieten. Dit verandert niets aan je account of je
facturering.

```bash
logbrew usage --json
```

`logbrew account usage --json` geeft hetzelfde resultaat. De response bevat je
abonnement, de status van je quotum, de resetdatum, het totale gebruik per
project en per soort telemetrie, en een volgende stap. Velden zijn onder meer
`plan`, `state`, `reset_at`, `by_project`, `by_stream` en `next`.

## <span id="common-investigations">Veelvoorkomende onderzoeken</span>

Filter elke leesactie op project. Voeg filters voor release, omgeving, tijd
of ernst toe als de opdracht ze ondersteunt. Zie
[Filters](/nl/reference/cli#filters).

<CardGroup cols={2}>
  <Card title="Issues in een release" icon="tag">
    ```bash
    logbrew read issues --project "<project_id>" --release api@1.2.3 --status unresolved --json
    ```
  </Card>

  <Card title="Eén mislukt request" icon="route">
    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Card>

  <Card title="Logs van een release" icon="file-text">
    ```bash
    logbrew read logs --project "<project_id>" --release api@1.2.3 --since 24h --json
    ```
  </Card>

  <Card title="Issues die aan jou zijn toegewezen" icon="user">
    ```bash
    logbrew read issues --project "<project_id>" --assignee me --status unresolved --json
    ```
  </Card>
</CardGroup>

## <span id="watch-live-events">Live-events volgen</span>

Gebruik watch om nieuwe events te zien terwijl je een wijziging test. Druk op
Ctrl+C om te stoppen.

```bash
logbrew watch --severity error,critical --json
```

Watch streamt alleen JSON. Zonder `--json` stopt de opdracht met een fout.
Voeg `logs`, `issues` of `actions` toe om één type te volgen, zoals
`logbrew watch logs --json`. Watch ondersteunt geen traces of spans.

Watch heeft geen filter voor project, release of omgeving. Gebruik voor één
project de leesacties hierboven. Zie [Live volgen](/nl/reference/cli#live-watch)
voor de ondersteunde resources en filters.

## <span id="explain-before-you-change-code">Eerst de uitleg lezen, dan code wijzigen</span>

Lees de context voordat je een fix voorstelt.

<Steps>
  <Step title="Lees het issue">
    ```bash
    logbrew read issue "<issue_id>" --json
    ```
  </Step>

  <Step title="Lees de trace">
    Doe deze stap alleen als het issue een trace-ID heeft. Een issue zonder
    trace is ook geldig.

    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Step>

  <Step title="Lees de uitleg">
    ```bash
    logbrew explain issue "<issue_id>" --json
    ```

    Gebruik voor een log `logbrew explain log "<log_id>" --json`. Gebruik voor
    een actie `logbrew explain action "<action_id>" --json`.
  </Step>

  <Step title="Los het issue op na verificatie">
    ```bash
    logbrew set issue "<issue_id>" resolved --json
    ```

    Wil je de status, prioriteit of toewijzing van veel issues wijzigen? Zie
    [Issuestatus en prioriteit wijzigen](/nl/reference/cli#change-issue-status-and-priority)
    en de [issueworkflow](/nl/guides/issue-workflow).
  </Step>
</Steps>

## <span id="json-output">JSON-uitvoer</span>

- Zet `--json` vóór of na de opdracht, zoals `logbrew --json status` of
  `logbrew status --json`.
- Lees de exitcode voordat je de uitvoer gebruikt.
- JSON-fouten bevatten `ok`, `error`, `message` en `next`. Een time-out bewijst
  niet dat een schrijfactie is mislukt. Lees de regels voor nieuwe pogingen
  voordat je een schrijfactie herhaalt.
- Automatiseer niet met uitvoer zonder `--json`. Die uitvoer kan veranderen.

Zie [Resultaten en fouten lezen](/nl/reference/cli#read-results-and-errors) voor
exitcodes en voorbeelden van fouten.
