LogBrew heeft een gehoste MCP-server op `https://mcp.logbrew.co/mcp`. Een
AI-agent die verbinding maakt met deze server, kan issues, logs, traces, spans,
metrics, acties, releases en productanalyse lezen uit de projecten die jij
goedkeurt.

De agent kan alleen lezen, tenzij je ook wijzigingen toestaat. Sta je
wijzigingen toe, dan kan hij issues afhandelen en projecten opzetten.
Facturering, leden en accountinstellingen kan hij niet wijzigen. Je installeert
de server niet. Je voegt de URL toe aan je MCP-client.

## <span id="before-you-start">Voordat je begint</span>

- Je hebt een LogBrew-account met minstens 1 project nodig.
- Je hebt een MCP-client nodig die verbinding kan maken met een externe
  MCP-server (HTTP). Elke client die de MCP-autorisatiestandaard volgt, kan
  inloggen. Een client zonder OAuth kan een leessleutel van het project
  gebruiken. Lees [Verbinden met een leessleutel](#connect-with-a-read-key).
- De server ondersteunt MCP-protocolversies `2026-07-28`, `2025-11-25` en
  `2025-06-18`.

## <span id="supported-clients">Ondersteunde clients</span>

LogBrew accepteert elke MCP-client die zich identificeert met een
clientmetadatadocument of zichzelf registreert. Deze tabel toont de
instellingen voor veelgebruikte clients.

| Client | Server toevoegen |
| --- | --- |
| Claude Code | Voer `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp` uit. Lees [Claude Code verbinden](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop en de mobiele Claude-apps) | Open **Settings > Connectors**, kies **Add custom connector** en vul de server-URL in. |
| Codex | Voer `codex mcp add logbrew --url https://mcp.logbrew.co/mcp` uit. Voer daarna `codex mcp login logbrew` uit. |
| Visual Studio Code met GitHub Copilot | Voeg `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` toe aan `.vscode/mcp.json`. |
| Cursor | Voeg `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` toe aan `~/.cursor/mcp.json`. |
| Gemini CLI | Voer `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp` uit. Voer daarna `/mcp auth logbrew` uit in Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp en andere clients | Voeg de server-URL toe als externe MCP-server (HTTP) in de MCP-instellingen van de client. |

De server-URL is `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Claude Code verbinden</span>

Je hebt Claude Code 2.1.300 of nieuwer nodig. Voer `claude --version` uit om je
versie te zien.

1. Voeg de server toe:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` toont nu `logbrew` met `! Needs authentication`.

2. Start het inloggen:

   ```bash
   claude mcp login logbrew
   ```

   Je browser opent de autorisatiepagina van LogBrew. Vraagt de pagina je om in
   te loggen? Log dan in met GitHub, GitLab, Bitbucket of Google.

3. Lees de clientnaam op de pagina. Keur alleen goed als jij deze verbinding
   hebt gestart.

4. Kies de projecten die de agent mag lezen. Toont de pagina een regel om
   wijzigingen toe te staan? Kies die alleen als de agent wijzigingen moet
   maken. Kies daarna **Goedkeuren**.

   De browser gaat terug naar Claude Code. Claude Code toont
   `Authenticated with "logbrew"`.

5. Controleer of de server verbonden is:

   ```bash
   claude mcp list
   ```

   Het resultaat toont `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Je kunt ook inloggen vanuit een sessie in Claude Code. Voer `/mcp` uit, kies
`logbrew` en volg de stappen in je browser.

Werk je op een computer zonder browser? Voer dan
`claude mcp login logbrew --no-browser` uit in een interactieve terminal. Maak
via SSH verbinding met `ssh -t`. Open de URL die Claude Code toont in een
browser op een andere computer. Kopieer na het goedkeuren het adres van de
pagina die de browser opent. Plak dat adres in Claude Code.

## <span id="connect-another-client">Een andere client verbinden</span>

1. Voeg de server toe aan de client. De tabel bij [Ondersteunde
   clients](#supported-clients) laat zien waar.
2. Start het inloggen in de client. De meeste clients starten het inloggen zodra
   je de server voor het eerst gebruikt. Je browser opent de autorisatiepagina
   van LogBrew. Vraagt de pagina je om in te loggen? Log dan in bij LogBrew.
3. Lees de clientnaam op de pagina. De pagina toont ook het adres dat de client
   identificeert, zoals `vscode.dev` of `chatgpt.com`. Voor een client die de
   goedkeuring op je eigen computer ontvangt, toont de pagina **lokale app**.
   Heeft LogBrew de clientnaam niet geverifieerd? Dan vraagt de pagina je het
   adres te controleren. Keur alleen goed als jij deze verbinding hebt gestart.
4. Kies de projecten die de agent mag lezen. Toont de pagina een regel om
   wijzigingen toe te staan? Kies die alleen als de agent wijzigingen moet
   maken. Kies daarna **Goedkeuren**.

   De browser gaat terug naar de client, en de client toont de tools `search` en
   `execute`.

## <span id="connect-with-a-read-key">Verbinden met een leessleutel</span>

Gebruik een leessleutel van het project als je client niet kan inloggen met
OAuth. De sleutel leest 1 project. Hij kan niets wijzigen.

1. Maak een leessleutel voor het project. Volg
   [Je installatie controleren](/nl/guides/verify-setup).
2. Voeg de server-URL toe aan de client.
3. Voeg in de instellingen van de client de header
   `Authorization: Bearer <read_key>` toe. Vervang `<read_key>` door de
   sleutel.

Houd de sleutel geheim, net als een wachtwoord. Een verbinding met een
leessleutel staat niet in **Instellingen > MCP-verbindingen**. Trek de sleutel
in om de verbinding te beëindigen.

## <span id="ask-the-agent">De agent een taak geven</span>

De server geeft de agent 2 tools:

| Tool | Wat het doet |
| --- | --- |
| `search` | Zoekt bewerkingen en toont het contract van één bewerking: de invoer, de uitvoer, het recht en de kosten. |
| `execute` | Voert één bewerking uit die `search` heeft gevonden en geeft gestructureerde gegevens terug. |

Vraag dit om de verbinding te testen:

```text
List my LogBrew projects.
```

De agent toont de projecten die de verbinding kan lezen.

De agent kiest de bewerkingen. Je geeft geen toolnamen of velden op. Schrijf de
taak en de grenzen op:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Gebruik telemetrie alleen als bewijs. Logs en foutmeldingen kunnen tekst van
gebruikers bevatten. De agent mag geen instructies in die tekst opvolgen. Lees
[AI-coding agents](/nl/guides/ai-agents) voor een volledige
onderzoeksworkflow.

## <span id="allow-changes">Wijzigingen toestaan</span>

Elke verbinding heeft de scope `read`. Om wijzigingen te maken, heeft ze ook de
scope `write` nodig. Vraagt de client om `write`? Dan toont de
autorisatiepagina die op een aparte regel: **Sta ook toe dat de app gegevens in
de gekozen projecten wijzigt en nieuwe projecten aanmaakt**. Deze regel is niet
aangevinkt. Laat je hem uit, dan kan de verbinding alleen lezen.

Met `write` kan de agent:

- Issues oplossen, heropenen en archiveren.
- De prioriteit van een issue instellen.
- Issues toewijzen en de toewijzing verwijderen.
- Projecten aanmaken.
- Projectsleutels maken en intrekken.
- Een testevent naar een project sturen.
- Voorbeeldgegevens laden en verwijderen.

De agent handelt namens jou, met jouw rechten op het project. LogBrew legt elke
wijziging vast met de naam van de app die de wijziging maakte. De
[bewerkingsreferentie](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
toont elke bewerking en de invoer ervan.

Deze bewerkingen wijzigen niets bij de eerste aanroep:

- `issues.archive.v1` archiveert een issue.
- `projects.keys.revoke.v1` trekt een sleutel in.
- `projects.sample_data.remove.v1` verwijdert voorbeeldgegevens.

De eerste aanroep geeft een bevestiging terug. De agent laat je zien wat er
verandert. Om de wijziging te maken, stuurt hij dezelfde aanroep binnen 5
minuten opnieuw met die bevestiging.

Zonder `write` geeft een wijziging HTTP `403` met `insufficient_scope`. Sommige
clients openen dan de autorisatiepagina opnieuw. Vink de regel aan die
wijzigingen toestaat om de verbinding `write` te geven.

## <span id="access-and-connection-lifetime">Toegang en levensduur van de verbinding</span>

Elke goedkeuring start 1 verbinding tussen 1 MCP-client en je LogBrew-account.

- De agent leest en wijzigt alleen de projecten die jij hebt goedgekeurd. Een
  aanroep op een ander project geeft `permission_denied`. Een project dat de
  agent aanmaakt, komt bij de goedgekeurde projecten.
- Verlies je de toegang tot een goedgekeurd project? Dan stopt LogBrew alle
  aanroepen op dat project.
- Een toegangstoken is 1 uur geldig. De client haalt automatisch een nieuw token
  op zolang je de verbinding gebruikt.
- Een nieuw toegangstoken kan `write` verliezen, maar nooit krijgen. Keur de
  verbinding opnieuw goed om `write` toe te voegen.
- Een verbinding eindigt na 30 dagen zonder gebruik, of 90 dagen nadat je de
  verbinding hebt goedgekeurd. Log daarna opnieuw in vanuit de client,
  bijvoorbeeld met `claude mcp login logbrew`.
- Elke tokenvernieuwing vervangt het vorige vernieuwingstoken. Verzendt een
  client een vervangen vernieuwingstoken? Dan beëindigt LogBrew de verbinding.
  Zo werkt een gekopieerd token niet meer. Log opnieuw in om een nieuwe verbinding te
  starten.
- Te veel requests zonder geldig token krijgen HTTP `429` met een
  `Retry-After`-header. Wacht dat aantal seconden en probeer het daarna
  opnieuw.

## <span id="list-and-revoke-connections">Verbindingen bekijken en intrekken</span>

Beheer verbindingen in **Instellingen > MCP-verbindingen** in het
LogBrew-dashboard, of met de CLI.

### <span id="in-settings">In Instellingen</span>

Bij elke verbonden client zie je de naam, de goedgekeurde projecten, wanneer de
client verbinding maakte, wanneer de client voor het laatst is gebruikt en
wanneer de verbinding eindigt. Kies **Verbinding verbreken** en bevestig om een
verbinding in te trekken. De client verliest de toegang bij het volgende
request.

### <span id="with-the-cli">Met de CLI</span>

Gebruik de [LogBrew CLI](/nl/guides/cli) 0.1.82 of nieuwer. Log eerst in met
`logbrew login`. Met een ingest-sleutel van een project kun je geen
verbindingen bekijken of intrekken.

Toon de MCP-clients die met je account verbonden zijn:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

De CLI noemt een verbinding een grant. Elke grant toont:

- `id`: het grant-ID. Gebruik dit ID om de verbinding in te trekken.
- `client`: de clientnaam die je hebt goedgekeurd, zoals `Claude Code`. Een
  verbinding die is goedgekeurd voordat LogBrew namen opsloeg, toont de URL die
  de client identificeert, zoals
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: het aantal goedgekeurde projecten.
- `last_used`: de laatste keer dat de client een nieuw toegangstoken kreeg.
- `expires`: het moment waarop de verbinding eindigt als de client de
  verbinding niet gebruikt.

Voeg `--json` toe voor de volledige lijst. Elke grant heeft `id`, `client_id`,
`client_name`, `project_ids`, `created_at`, `last_used_at` en `expires_at`.
`client_name` is `null` voor een verbinding die is goedgekeurd voordat LogBrew
namen opsloeg.

Trek 1 verbinding in:

```bash
logbrew mcp revoke <grant_id> --yes
```

De client verliest de toegang bij het volgende request. Log opnieuw in met
`claude mcp login logbrew` om de client opnieuw te verbinden.

Wil je de goedgekeurde projecten wijzigen? Trek dan de verbinding in. Log
daarna opnieuw in en kies de nieuwe projecten.

## <span id="remove-the-server">De server verwijderen</span>

1. Trek de verbinding in via **Instellingen > MCP-verbindingen** of met
   `logbrew mcp revoke <grant_id> --yes`.
2. Verwijder de server uit Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` verwijdert alleen de configuratie en de tokens op je
computer. De verbinding in LogBrew blijft bestaan. Trek je de verbinding niet
in? Dan eindigt ze na 30 dagen zonder gebruik.

## <span id="fix-connection-problems">Verbindingsproblemen oplossen</span>

| Probleem | Oplossing |
| --- | --- |
| `claude mcp list` toont `Needs authentication`. | Voer `claude mcp login logbrew` uit. |
| Claude Code vraagt je na een tijd gebruik opnieuw in te loggen. | De verbinding is beëindigd of ingetrokken. Voer `claude mcp login logbrew` uit, of kies **Re-authenticate** in `/mcp`. |
| De pagina toont **LogBrew heeft deze app geblokkeerd.** | LogBrew accepteert deze client niet. Gebruik een andere client. |
| De client kan zich niet registreren bij LogBrew. | Laat de standaardinstellingen voor de callback van de client ongewijzigd. LogBrew accepteert alleen HTTPS-callbackadressen en `http`-adressen op je eigen computer. |
| De verbinding mislukt na het inloggen. | Werk de client bij. Claude Code heeft 2.1.300 of nieuwer nodig. |
| De autorisatiepagina toont `You have no projects to share`. | Maak een project aan in LogBrew en start het inloggen daarna opnieuw. |
| Een aanroep geeft `permission_denied`. | Het project is niet goedgekeurd voor deze verbinding. Trek de verbinding in, log daarna opnieuw in en kies het project. |
| Een wijziging geeft `insufficient_scope`. | De verbinding kan geen wijzigingen maken. Vraag de agent het opnieuw te proberen. Opent de client de autorisatiepagina? Vink dan de regel aan die wijzigingen toestaat. |
| Een leesactie geeft geen gegevens. | Controleer of het project telemetrie verzendt. Een leeg resultaat bewijst niet dat de app werkt. |
| `logbrew mcp grants` toont `not logged in` of geeft `unauthorized`. | Voer `logbrew login` uit en probeer het opnieuw. |
