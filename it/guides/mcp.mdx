LogBrew offre un server MCP ospitato all'indirizzo `https://mcp.logbrew.co/mcp`.
Un agente IA collegato al server può leggere problemi, log, tracce, span,
metriche, azioni, release e analisi di prodotto dei progetti che approvi.

L'agente può solo leggere, a meno che tu non consenta anche le modifiche. Con
le modifiche consentite, può gestire i problemi e configurare progetti. Non può
cambiare la fatturazione, i membri o le impostazioni dell'account. Non devi
installare il server: aggiungi il suo URL al tuo client MCP.

## Prima di iniziare

- Ti serve un account LogBrew con almeno 1 progetto.
- Ti serve un client MCP in grado di collegarsi a un server MCP remoto (HTTP).
  Qualsiasi client che segue lo standard di autorizzazione MCP può accedere. Un
  client senza OAuth può usare una chiave di lettura del progetto. Leggi
  [Collegati con una chiave di lettura](#connect-with-a-read-key).
- Il server supporta le versioni `2026-07-28`, `2025-11-25` e `2025-06-18` del
  protocollo MCP.

## <span id="supported-clients">Client supportati</span>

LogBrew accetta qualsiasi client MCP che si identifica con un documento di
metadati del client o che si registra da solo. Questa tabella mostra la
configurazione dei client più comuni.

| Client | Come aggiungere il server |
| --- | --- |
| Claude Code | Esegui `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Leggi [Collega Claude Code](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop e le app mobili di Claude) | Apri **Settings > Connectors**, seleziona **Add custom connector** e inserisci l'URL del server. |
| Codex | Esegui `codex mcp add logbrew --url https://mcp.logbrew.co/mcp`. Poi esegui `codex mcp login logbrew`. |
| Visual Studio Code con GitHub Copilot | Aggiungi `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` a `.vscode/mcp.json`. |
| Cursor | Aggiungi `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` a `~/.cursor/mcp.json`. |
| Gemini CLI | Esegui `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Poi esegui `/mcp auth logbrew` in Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp e altri client | Aggiungi l'URL del server come server MCP remoto (HTTP) nelle impostazioni MCP del client. |

L'URL del server è `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Collega Claude Code</span>

Ti serve Claude Code 2.1.300 o successivo. Esegui `claude --version` per vedere
la tua versione.

1. Aggiungi il server:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   Ora `claude mcp list` mostra `logbrew` con `! Needs authentication`.

2. Avvia l'accesso:

   ```bash
   claude mcp login logbrew
   ```

   Il browser apre la pagina di autorizzazione di LogBrew. Se la pagina ti
   chiede di accedere, accedi con GitHub, GitLab, Bitbucket o Google.

3. Leggi il nome del client nella pagina. Approva solo se hai avviato tu
   questa connessione.

4. Seleziona i progetti che l'agente può leggere. Se la pagina mostra una riga
   per consentire le modifiche, selezionala solo se l'agente deve apportare
   modifiche. Poi seleziona **Approva**.

   Il browser torna a Claude Code. Claude Code mostra
   `Authenticated with "logbrew"`.

5. Verifica che il server sia connesso:

   ```bash
   claude mcp list
   ```

   Il risultato mostra `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Puoi anche accedere da una sessione di Claude Code. Esegui `/mcp`, seleziona
`logbrew` e segui i passaggi nel browser.

Su un computer senza browser, esegui
`claude mcp login logbrew --no-browser` in un terminale interattivo. Tramite
SSH, connettiti con `ssh -t`. Apri l'URL mostrato da Claude Code in un browser
su un altro computer. Dopo l'approvazione, copia l'indirizzo della pagina che
si apre nel browser. Incollalo in Claude Code.

## Collega un altro client

1. Aggiungi il server al client. La tabella in [Client
   supportati](#supported-clients) indica dove.
2. Avvia l'accesso dal client. La maggior parte dei client lo avvia al primo
   utilizzo del server. Il browser apre la pagina di autorizzazione di LogBrew.
   Se la pagina ti chiede di accedere, accedi a LogBrew.
3. Leggi il nome del client nella pagina. La pagina mostra anche l'indirizzo che
   identifica il client, ad esempio `vscode.dev` o `chatgpt.com`. Per un client
   che riceve l'approvazione sul tuo computer, la pagina mostra **app locale**.
   Se LogBrew non ha verificato il nome del client, la pagina ti chiede di
   controllare l'indirizzo. Approva solo se hai avviato tu questa connessione.
4. Seleziona i progetti che l'agente può leggere. Se la pagina mostra una riga
   per consentire le modifiche, selezionala solo se l'agente deve apportare
   modifiche. Poi seleziona **Approva**.

   Il browser torna al client, e il client mostra gli strumenti `search` e
   `execute`.

## <span id="connect-with-a-read-key">Collegati con una chiave di lettura</span>

Usa una chiave di lettura del progetto se il tuo client non può accedere con
OAuth. La chiave legge 1 progetto. Non può apportare modifiche.

1. Crea una chiave di lettura per il progetto. Segui
   [Verifica la configurazione](/it/guides/verify-setup).
2. Aggiungi l'URL del server al client.
3. Nelle impostazioni del client, aggiungi l'intestazione
   `Authorization: Bearer <read_key>`. Sostituisci `<read_key>` con la chiave.

Tieni segreta la chiave, come una password. Una connessione con chiave di
lettura non compare in **Impostazioni > Connessioni MCP**. Per chiuderla,
revoca la chiave.

## Fai una richiesta all'agente

Il server fornisce all'agente 2 strumenti:

| Strumento | Cosa fa |
| --- | --- |
| `search` | Trova le operazioni e mostra il contratto di un'operazione: input, output, permesso e costo. |
| `execute` | Esegue un'operazione trovata da `search` e restituisce dati strutturati. |

Per provare la connessione, chiedi:

```text
List my LogBrew projects.
```

L'agente elenca i progetti che la connessione può leggere.

L'agente sceglie le operazioni. Non devi indicargli nomi di strumenti o campi.
Scrivi il compito e i limiti:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Usa la telemetria solo come fonte di prove. Log e messaggi di errore possono
contenere testo scritto dagli utenti. L'agente non deve seguire le istruzioni
contenute in quel testo. Per un flusso di indagine completo, leggi
[Usa LogBrew con agenti IA](/it/guides/ai-agents).

## Consenti le modifiche

Ogni connessione ha lo scope `read`. Per apportare modifiche, le serve anche lo
scope `write`. Quando il client chiede `write`, la pagina di autorizzazione lo
mostra su una riga a parte: **Consenti anche di modificare i dati dei progetti
selezionati e di creare nuovi progetti**. Questa riga non è selezionata. Se non
la selezioni, la connessione può solo leggere.

Con `write`, l'agente può:

- Risolvere, riaprire e archiviare problemi.
- Impostare la priorità di un problema.
- Assegnare problemi e rimuovere l'assegnazione.
- Creare progetti.
- Creare e revocare chiavi di progetto.
- Inviare un evento di test a un progetto.
- Caricare e rimuovere dati di esempio.

L'agente agisce a tuo nome, con i tuoi permessi sul progetto. LogBrew registra
ogni modifica con il nome dell'app che l'ha fatta. Il
[riferimento delle operazioni](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
elenca ogni operazione e il suo input.

Queste operazioni non cambiano nulla alla prima chiamata:

- `issues.archive.v1` archivia un problema.
- `projects.keys.revoke.v1` revoca una chiave.
- `projects.sample_data.remove.v1` rimuove i dati di esempio.

La prima chiamata restituisce una conferma. L'agente ti mostra cosa cambierà.
Per applicare la modifica, invia di nuovo la stessa chiamata con quella
conferma entro 5 minuti.

Senza `write`, una modifica restituisce HTTP `403` con `insufficient_scope`.
Alcuni client allora riaprono la pagina di autorizzazione. Seleziona la riga che
consente le modifiche per dare `write` alla connessione.

## Accesso e durata della connessione

Ogni approvazione avvia 1 connessione tra 1 client MCP e il tuo account
LogBrew.

- L'agente legge e modifica solo i progetti che hai approvato. Una chiamata su
  un altro progetto restituisce `permission_denied`. Un progetto creato
  dall'agente si aggiunge ai progetti approvati.
- Se perdi l'accesso a un progetto approvato, LogBrew interrompe le chiamate su
  quel progetto.
- Un token di accesso vale 1 ora. Mentre usi la connessione, il client ne
  ottiene uno nuovo in automatico.
- Un nuovo token di accesso può perdere `write`, ma non può mai aggiungerlo. Per
  aggiungere `write`, approva di nuovo la connessione.
- Una connessione termina dopo 30 giorni senza utilizzo, oppure 90 giorni dopo
  l'approvazione. A quel punto accedi di nuovo dal client, ad esempio con
  `claude mcp login logbrew`.
- Ogni rinnovo del token sostituisce il refresh token precedente. Se un client
  invia un refresh token già sostituito, LogBrew termina la connessione. Così
  un token copiato smette di funzionare. Accedi di nuovo per avviare una nuova
  connessione.
- Troppe richieste senza un token valido ricevono HTTP `429` con l'header
  `Retry-After`. Attendi quel numero di secondi, poi riprova.

## Elenca e revoca le connessioni

Gestisci le connessioni in **Impostazioni > Connessioni MCP** nella dashboard
di LogBrew oppure con la CLI.

### Nelle Impostazioni

Ogni client connesso mostra il nome, i progetti approvati, quando si è
connesso, quando è stato usato l'ultima volta e quando termina la connessione.
Per revocarne uno, seleziona **Disconnetti**, poi conferma. Il client perde
l'accesso alla richiesta successiva.

### Con la CLI

Usa la [CLI di LogBrew](/it/guides/cli) 0.1.82 o successiva. Prima accedi con
`logbrew login`. Una chiave di ingestione del progetto non può elencare né
revocare le connessioni.

Elenca i client MCP connessi al tuo account:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

La CLI chiama una connessione «grant». Ogni grant mostra:

- `id`: l'ID del grant. Usalo per revocare la connessione.
- `client`: il nome del client che hai approvato, come `Claude Code`. Una
  connessione approvata prima che LogBrew salvasse i nomi mostra l'URL che
  identifica il client, come
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: il numero di progetti approvati.
- `last_used`: l'ultima volta in cui il client ha ottenuto un nuovo token di
  accesso.
- `expires`: il momento in cui la connessione termina se il client non la usa.

Aggiungi `--json` per ottenere l'elenco completo. Ogni grant ha `id`,
`client_id`, `client_name`, `project_ids`, `created_at`, `last_used_at` e
`expires_at`. `client_name` è `null` per una connessione approvata prima che
LogBrew salvasse i nomi.

Revoca 1 connessione:

```bash
logbrew mcp revoke <grant_id> --yes
```

Il client perde l'accesso alla richiesta successiva. Per ricollegarlo, accedi
di nuovo con `claude mcp login logbrew`.

Per cambiare i progetti approvati, revoca la connessione. Poi accedi di nuovo e
seleziona i nuovi progetti.

## Rimuovi il server

1. Revoca la connessione in **Impostazioni > Connessioni MCP** oppure con
   `logbrew mcp revoke <grant_id> --yes`.
2. Rimuovi il server da Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` elimina la configurazione e i token solo sul tuo computer.
Non termina la connessione in LogBrew. Se non la revochi, la connessione
termina dopo 30 giorni senza utilizzo.

## <span id="fix-connection-problems">Risolvi gli errori di connessione</span>

| Errore | Soluzione |
| --- | --- |
| `claude mcp list` mostra `Needs authentication`. | Esegui `claude mcp login logbrew`. |
| Claude Code ti chiede di accedere di nuovo dopo un periodo di utilizzo. | La connessione è terminata o è stata revocata. Esegui `claude mcp login logbrew` oppure seleziona **Re-authenticate** in `/mcp`. |
| La pagina mostra **LogBrew ha bloccato questa app.** | LogBrew non accetta questo client. Usa un altro client. |
| Il client non riesce a registrarsi su LogBrew. | Lascia le impostazioni di callback predefinite del client. LogBrew accetta solo indirizzi di callback HTTPS e indirizzi `http` sul tuo computer. |
| La connessione non riesce dopo l'accesso. | Aggiorna il client. Claude Code richiede la versione 2.1.300 o successiva. |
| La pagina di autorizzazione mostra `You have no projects to share`. | Crea un progetto in LogBrew, poi avvia di nuovo l'accesso. |
| Una chiamata restituisce `permission_denied`. | Il progetto non è approvato per questa connessione. Revoca la connessione, poi accedi di nuovo e seleziona il progetto. |
| Una modifica restituisce `insufficient_scope`. | La connessione non può apportare modifiche. Chiedi all'agente di riprovare. Se il client apre la pagina di autorizzazione, seleziona la riga che consente le modifiche. |
| Una lettura non restituisce dati. | Verifica che il progetto invii telemetria. Un risultato vuoto non dimostra che l'app funzioni. |
| `logbrew mcp grants` mostra `not logged in` o restituisce `unauthorized`. | Esegui `logbrew login`, poi riprova. |
