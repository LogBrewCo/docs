LogBrew usa un solo termine per ogni concetto del prodotto. Campi API, flag
della CLI, valori enum, nomi degli eventi e chiavi degli attributi restano
invariati in ogni lingua.

## Osservabilità e monitoraggio

| Termine | Significato |
| --- | --- |
| Osservabilità | Capire il comportamento di un'applicazione a partire dalle prove che produce. |
| Telemetria | I segnali che un'applicazione invia, come log, tracce e metriche. |
| Monitoraggio | Verificare condizioni note, come un valore misurato rispetto a una soglia. |
| `o11y` | Abbreviazione dell'inglese observability (osservabilità). Il numero conta le 11 lettere tra `o` e `y`. |

Per scegliere i segnali e vedere esempi pratici, leggi [Telemetria](/it/concepts/telemetry).

## Agenti IA

| Termine | Significato |
| --- | --- |
| Server MCP | Il server ospitato di LogBrew per il Model Context Protocol. Gli agenti IA lo usano per leggere i progetti approvati e, se lo consenti, per modificarli. |
| Client MCP | Un'applicazione che collega un agente IA a un server MCP, come Claude Code. |
| Progetto approvato | Un progetto che hai selezionato quando hai dato l'accesso a un client MCP. Il client può usare solo i progetti approvati. |
| Connessione | L'accesso che dai a 1 client MCP quando lo approvi. Termina dopo 30 giorni senza utilizzo, dopo 90 giorni o quando la revochi. La CLI la chiama «grant». |
| Scope | Cosa può fare una connessione. `read` legge i progetti approvati. `write` può anche modificarli. Scegli tu `write` quando approvi la connessione. |

Per collegare un client, leggi [Collega un agente IA con MCP](/it/guides/mcp).

## Segnali di osservabilità

<AccordionGroup>
  <Accordion title="Problema">
    Un problema raggruppato che può contenere più occorrenze. Un'occorrenza è
    una singola istanza acquisita di quel problema. `first_seen_at` è l'orario
    della prima occorrenza. `last_seen_at` è l'orario dell'occorrenza più
    recente.
  </Accordion>

  <Accordion title="Log">
    Un singolo record di evento con timestamp. Un log può includere gravità,
    servizio, release, ambiente, contesto di traccia e attributi entro i limiti
    di privacy.
  </Accordion>

  <Accordion title="Traccia e span">
    Una traccia segue il lavoro lungo una richiesta o un'operazione. Uno span è
    una singola operazione cronometrata all'interno di quella traccia. Una
    correlazione con una traccia è una prova di contesto condiviso; non
    dimostra la causa.
  </Accordion>

  <Accordion title="Metrica">
    Una misura di runtime con unità, tipo, aggregazione e intervallo di tempo
    definiti. I punti dati di una metrica non sono intercambiabili con i
    conteggi di log, tracce o problemi.
  </Accordion>

  <Accordion title="Release">
    Una versione di un'applicazione o di un servizio distribuita e indicata
    nella telemetria. Una release non è la stessa cosa di un progetto o di un
    repository.
  </Accordion>

  <Accordion title="Azione">
    Un evento di prodotto classificato, come una registrazione, un checkout,
    un'importazione o un job non riuscito. Analisi classifica un'azione come
    visualizzazione di pagina, visualizzazione di schermata o interazione.
    Un'azione non è un comando automatico eseguito da LogBrew.
  </Accordion>
</AccordionGroup>

## Indagine sui problemi

Non tutte le occorrenze contengono tutti i campi.

| Termine | Significato |
| --- | --- |
| Gravità | L'urgenza di un segnale: `info`, `warning`, `error` o `critical`. È distinta dallo stato del problema. |
| Stato del problema | Lo stato di un problema raggruppato nel flusso di lavoro: `unresolved`, `resolved` o `archived`. Non è l'esito di una singola richiesta. |
| Problema archiviato | Un problema che il team ha tolto dal triage attivo. Le risposte meno recenti chiamano questo stato `ignored`. |
| Priorità del problema | L'ordine di triage di un problema raggruppato: `high`, `medium` o `low`. Segue la gravità finché una persona non la imposta. |
| Origine della priorità | Da dove proviene la priorità. `derived` segue la gravità: `error` e `critical` diventano `high`, `warning` diventa `medium` e `info` diventa `low`. `manual` è una priorità impostata da una persona. |
| Assegnatario | L'unico account o team responsabile del passo successivo su un problema raggruppato. Un account deve poter leggere il progetto. Un team deve appartenere all'organizzazione del progetto. |
| Team | Un gruppo di membri di un'organizzazione, con un nome. Puoi assegnare problemi a un team e le regole dei referenti possono indicarlo. Un team non dà ai suoi membri alcun accesso ai progetti. |
| Regola dei referenti | Una regola del progetto che collega un percorso di frame dello stack, un modulo, una route, un servizio o un tag agli account o ai team referenti dei problemi corrispondenti. |
| Referente suggerito | Un account o un team che LogBrew propone per un problema in base a una regola dei referenti, a una riga di CODEOWNERS o all'attività recente. È un suggerimento, non un'assegnazione. |
| Inbox | L'elenco dei problemi che altre persone hanno assegnato a te o ai tuoi team. LogBrew non invia email per questo elenco. |
| Stack trace | Le prove delle chiamate di funzione acquisite per un errore. È diverso da una traccia distribuita. |
| Frame dello stack | Una voce di uno stack trace. Può identificare una funzione, un modulo, un file, una riga o una colonna. |
| Catena di eccezioni | Eccezioni collegate segnalate insieme, come un errore e la sua causa. Le voci mancanti, oscurate o troncate limitano le prove. |
| Frame dell'applicazione | Un frame dello stack contrassegnato come codice dell'applicazione. Indica il codice da esaminare. Non dimostra dove sia il difetto. |
| Breadcrumb | Un breve evento registrato prima di un'occorrenza del problema. I breadcrumb non sono una registrazione completa di una sessione. |
| Eccezione gestita | Un'eccezione che l'applicazione ha segnalato come gestita. Non dimostra che l'operazione sia riuscita. |
| Source map | Un artefatto di build che associa le posizioni del JavaScript generato alle posizioni nel codice sorgente originale. |
| Frame simbolizzato | Un frame la cui posizione generata è stata ricondotta alle informazioni del codice sorgente originale. |
| Occorrenza di riferimento | L'occorrenza acquisita usata come riferimento per la riproduzione. |
| Provenienza | Da dove proviene una valutazione. `backend_observed` significa che LogBrew l'ha osservata. `application_reported` significa che l'app l'ha segnalata e LogBrew non l'ha verificata. |
| Idoneità alla riproduzione | Indica se l'occorrenza di riferimento ha le prove necessarie per tentare una riproduzione. Non è un test di riproduzione superato. |

Per l'ordine di lettura e i campi della risposta, usa la
[guida all'indagine](/it/guides/investigate-an-issue).

## Identità e correlazione

Un valore mancante non dimostra che l'attività correlata non sia avvenuta.

| Termine | Significato |
| --- | --- |
| Contesto di traccia | Gli identificatori di traccia e di span che collegano il lavoro tra i segnali. |
| Span radice | Lo span che avvia una traccia e non ha uno span padre. Il primo span restituito non è necessariamente quello radice. |
| Span figlio | Uno span con uno span padre nella stessa traccia. |
| Correlazione | Una relazione esatta restituita da LogBrew, come un ID traccia condiviso. Non dimostra la causa. |
| Utente identificato | Un soggetto fornito dall'app con un ID stabile e tipo `user`. |
| Soggetto anonimo | Un soggetto fornito dall'app con tipo `anonymous`. I conteggi lo tengono separato dagli utenti identificati. |
| Tipo di identità sconosciuto | Un soggetto senza un tipo noto. LogBrew non lo conta come utente identificato. |
| Soggetto mancante | Un evento senza soggetto. È diverso da un soggetto con tipo sconosciuto. |

Il tipo di identità mostra come l'app ha classificato il suo soggetto. Non
dimostra che i dati siano anonimi. Un ID stabile può comunque collegare le
attività.

## Ambito e qualità dei dati

| Termine | Significato |
| --- | --- |
| Progetto | Il confine principale del prodotto, con un proprietario definito. Un progetto può contenere più servizi o componenti di repository. |
| Servizio | Un runtime o un componente che invia dati all'interno di un progetto. |
| Ambiente | Un contesto esatto da cui arrivano i dati, come produzione o staging. |
| Chiave di ingestione | Una chiave di progetto che invia telemetria a un solo progetto. Non può leggere la telemetria. |
| Chiave di lettura | Una chiave di progetto che legge la telemetria di un solo progetto. Non può inviare telemetria, modificare dati né accedere. Vedi [Tipi di chiave di progetto](/it/guides/verify-setup#project-key-kinds). |
| Ingerito | Accettato secondo il contratto di ingestione. Non garantisce una conservazione illimitata. |
| Indicizzato | Disponibile per l'indice o la query specificati. Non è un sinonimo di ingerito. |
| Conservato | Presente nell'intervallo di dati valutato e nella conservazione dei dati dell'account. |
| Campionato | Una parte della telemetria è stata selezionata prima o durante la raccolta. |
| Copertura | Una quota misurata con numeratore e denominatore espliciti. |
| Troncato | La risposta ha raggiunto un limite. I dati omessi non sono necessariamente assenti. |
| Approssimativo | Stimato con il metodo documentato invece che contato con esattezza. |
| Intervallo di tempo | Il periodo esatto che una query valuta. |

## Piani e organizzazioni

| Termine | Significato |
| --- | --- |
| Piano | Un insieme fisso di quote mensili con un periodo di conservazione. I piani sono Free, Pro, Business ed Enterprise. |
| Quota | La quantità di un tipo di telemetria che un piano include in 1 mese di fatturazione, per esempio i byte dei log o gli span delle tracce. |
| Conservazione dei dati | Il numero di giorni per cui LogBrew conserva la telemetria di un account. LogBrew elimina la telemetria più vecchia. Non coincide con la fidelizzazione nell'analisi di prodotto. |
| Offerta beta | Le quote di Pro che gli account creati prima del 2026-10-26 ricevono gratis per 6 mesi. Dopo, l'account usa il suo piano. |
| Organizzazione | Uno spazio condiviso per membri, team e progetti. Ogni piano ha organizzazioni senza limiti di membri né di progetti. |

Le quote e la conservazione di ogni piano sono in [API dell'account](/it/reference/account-api).

## Misure e tempo

| Termine | Significato |
| --- | --- |
| Punto dati | Un valore in un momento indicato. Prima di confrontare punti dati, leggi il nome e l'unità della metrica. |
| Serie temporale | Valori della stessa misura ordinati nel tempo. Un vuoto non significa che il valore fosse zero. |
| Durata | Il tempo trascorso durante un'operazione. È diverso dal momento in cui l'operazione è avvenuta. |
| Aggregazione | Un calcolo definito su più misure, come una somma o una media. |
| Fascia temporale | Un intervallo in un grafico o in un risultato raggruppato. Il suo inizio e la sua fine definiscono il periodo coperto. |
| Periodo parziale | Un periodo non ancora concluso. Non è un periodo concluso senza attività. |

Non sommare le durate di span figli sovrapposti per ottenere il tempo totale
della richiesta. Non confrontare un conteggio di eventi con un conteggio di
utenti identificati.

## Stati delle prove

Questi stati non sono intercambiabili:

- **Acquisito:** le prove sono presenti.
- **Mancante:** le prove non sono state acquisite.
- **Oscurato:** le prove sono state nascoste di proposito.
- **Troncato:** le prove hanno superato un limite della risposta o
  dell'acquisizione.
- **Non disponibile:** la lettura non ha potuto fornire le prove.

`Likely cause` (causa probabile) e `likely fix area` (area di correzione
probabile) descrivono prove diagnostiche limitate, non una causa radice
dimostrata. `Reported impact` (impatto segnalato) proviene dall'applicazione
che invia i dati, a meno che un contratto non descriva esplicitamente una
misura di LogBrew.

## Analisi di prodotto

| Termine | Significato |
| --- | --- |
| Evento | Attività di prodotto classificata con un nome esatto e stabile. |
| Proprietà | Una chiave di contesto usata per descrivere o filtrare un evento. |
| Sessione | Una visita o una sessione dell'app, non una persona. |
| Coorte | Un gruppo delimitato definito da criteri esatti. |
| Funnel | Passaggi ordinati usati per misurare l'avanzamento o la conversione. |
| Fidelizzazione | Il comportamento di ritorno misurato con un periodo e un denominatore espliciti. |
| Percorsi | I percorsi delle sessioni prima o dopo un evento selezionato. |
| Ciclo di vita | Raggruppa i soggetti identificati in ogni periodo come nuovi nella cronologia osservata, di ritorno, riattivati o inattivi. |
| Nuovo nella cronologia osservata | Attivo senza un evento selezionato precedente nell'intervallo di cronologia considerato. Non indica un cliente nuovo. |

Periodi parziali, identità mancante, acquisizione incompleta delle proprietà,
campionamento e troncamento limitano la validità del risultato. LogBrew mostra
questi limiti invece di trasformarli in zero o in certezza.

Per le regole di conteggio, leggi [Analisi di prodotto](/it/concepts/product-analytics).
Usa [Acquisizione eventi di prodotto](/it/guides/product-events) per
inviare attività classificate e identità tipizzate.
