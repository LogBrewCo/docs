Usa l'API dell'account per leggere l'utilizzo, lo stato della quota, la
cronologia dell'utilizzo e lo stato dell'abbonamento, e per disconnetterti. Le
letture dell'account usano un token bearer dell'account o la sessione del
browser. Non usare mai una chiave di ingestione del progetto per una richiesta
dell'account. Non usare mai una credenziale dell'account nella configurazione
dell'SDK o dell'ingestione.

| Attività | Endpoint |
| --- | --- |
| Leggi l'utilizzo attuale e lo stato della quota | `GET /api/account/usage` |
| Leggi l'utilizzo nel tempo | `GET /api/account/usage/history` |
| Leggi lo stato dell'abbonamento e dell'organizzazione | `GET /api/account/subscription` |
| Leggi i piani e le loro quote | `GET /api/billing/catalog` |
| Elenca gli inviti a un'organizzazione che ti sono stati inviati | `GET /api/account/invitations` |
| Leggi un invito che ti è stato inviato | `GET /api/organizations/{organization_id}/invitations/{invitation_id}` |
| Disconnetti un accesso dell'app o della CLI | `POST /api/auth/logout` |
| Revoca ogni accesso a LogBrew | `POST /api/auth/logout-all` |
| Cancella la sessione del browser | `POST /api/auth/web/logout` |

Gli errori usano il [formato di errore standard dell'API](/it/reference/api-errors).
Una lettura senza un'autenticazione valida dell'account restituisce `401` con
`code: "unauthorized"`. Non mostrare questo errore come utilizzo zero, grafico
vuoto o piano gratuito. Un metodo non supportato restituisce `405` con
`code: "method_not_allowed"` e `next` indica la richiesta supportata.

L'API dell'account riporta l'utilizzo della telemetria, non importi in denaro.
Non riporta addebiti, fatture o stato dei pagamenti.

## <span id="account-usage">Utilizzo dell'account</span>

`GET /api/account/usage` è l'endpoint di riferimento per utilizzo e quota.
Usalo per i totali di utilizzo, l'orario di azzeramento, lo stato della quota
e le suddivisioni per progetto e per flusso di telemetria. Non calcolare
l'utilizzo da file dell'SDK, file della CLI o contatori del client. Il comando
CLI `logbrew usage` legge questo endpoint. Consulta il
[riferimento della CLI](/it/reference/cli).

```bash
curl "https://api.logbrew.co/api/account/usage" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

Esempio di risposta con valori sintetici. Questo account gratuito ha 1
progetto e nel periodo corrente ha inviato solo log:

```json
{
  "period_start": "2026-06-01T00:00:00Z",
  "period_end": "2026-07-01T00:00:00Z",
  "reset_at": "2026-07-01T00:00:00Z",
  "plan": { "tier": "free", "status": "free" },
  "limits": { "events": null, "bytes": null, "projects": null, "retention_days": 30 },
  "usage": { "events": 27000, "bytes": 10485760, "projects": 1 },
  "state": "ok",
  "warning_threshold": 0.8,
  "percent_used": 0.02,
  "warning": false,
  "blocked": false,
  "limit": null,
  "next": "continue sending telemetry",
  "next_action": {
    "code": "continue_sending_telemetry",
    "target": "telemetry_ingest",
    "state": "ok",
    "limit": null,
    "reset_at": "2026-07-01T00:00:00Z"
  },
  "by_project": [
    { "project_id": "00000000-0000-4000-8000-000000000001", "events": 27000, "bytes": 10485760 }
  ],
  "by_stream": [
    { "kind": "logs", "events": 27000, "bytes": 10485760 }
  ]
}
```

| Campo | Significato |
| --- | --- |
| `period_start`, `period_end` | Il periodo di utilizzo corrente. La fine è esclusa. |
| `reset_at` | Quando la quota di utilizzo si azzera. Coincide con `period_end`. |
| `plan.tier` | Identificatore del piano: `free`, `pro` o `scale`. |
| `plan.status` | `free`, `trial`, `active`, `past_due` o `disabled`. |
| `limits.events`, `limits.bytes`, `limits.projects` | Campi di compatibilità. Valgono `null`. `null` non significa illimitato. Usa `state`, `limit` e `percent_used` per lo stato della quota. |
| `limits.retention_days` | La conservazione dei dati dell'account, in giorni. È la maggiore tra quella del piano e quella di un'offerta attiva per i nuovi account. È `null` per un piano Enterprise, il cui contratto stabilisce la conservazione. Vedi [Conservazione dei dati](#data-retention). |
| `usage.events`, `usage.bytes` | I totali di tutti i flussi di telemetria nel periodo. |
| `usage.projects` | Il numero di progetti di proprietà dell'account. |
| `state` | `ok`, `warning` o `blocked`. |
| `warning_threshold` | La parte di una quota che avvia lo stato `warning`, espressa come frazione. |
| `percent_used` | La parte più alta tra tutte le quote, espressa come percentuale. Per esempio, `80` significa 80%. |
| `warning`, `blocked` | Forme di compatibilità di `state`. |
| `limit` | La quota che ha causato lo stato: `events`, `bytes` o `null`. |
| `next`, `next_action` | Il testo di ripristino e l'azione tipizzata per lo stato corrente. |
| `by_project` | L'utilizzo per progetto. C'è 1 riga per ogni progetto di proprietà, anche quando il suo utilizzo è zero. Abbina le righe per `project_id`, non per posizione nell'array. |
| `by_stream` | L'utilizzo per `kind` di flusso di telemetria, come `logs`, `issues`, `actions` o `traces`. |

### Eventi scartati dagli SDK

Invia `response_version=2` per ricevere anche `sdk_dropped_events`. Senza questo parametro, o con `response_version=1`, la risposta non contiene questo campo.

```bash
curl "https://api.logbrew.co/api/account/usage?response_version=2" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

`sdk_dropped_events` elenca gli eventi che gli SDK hanno segnalato come scartati prima dell'invio nel periodo corrente, per esempio perché la coda del client era piena. C'è 1 riga per ogni progetto e motivo:

```json
{
  "sdk_dropped_events": [
    { "project_id": "00000000-0000-4000-8000-000000000001", "reason": "queue_overflow", "events": 12 }
  ]
}
```

| Campo | Significato |
| --- | --- |
| `project_id` | Il progetto il cui SDK ha scartato gli eventi. |
| `reason` | Il codice del motivo inviato dall'SDK, come `queue_overflow`. |
| `events` | Il numero di eventi scartati. |

Gli eventi scartati non sono mai arrivati a LogBrew. Non vengono fatturati e non contano in `usage`, `by_project` o `by_stream`. L'array è vuoto quando nessun SDK ha segnalato eventi scartati.

L'array conta anche i record OTLP che LogBrew ha rifiutato, con il motivo `otlp_rejected_record`, oppure `usage_limit_exceeded` al limite del piano. Questi record sono arrivati a LogBrew, ma LogBrew non li ha salvati. Non vengono fatturati. Vedi [OpenTelemetry (OTLP)](/it/guides/opentelemetry).

### <span id="new-account-offer">Offerta per i nuovi account</span>

Gli account meno recenti hanno ricevuto gratis le quote di Pro per 6 mesi, contati dalla registrazione o, per gli account che esistevano il 2026-10-22, da quella data. Mantengono l'offerta fino al suo `ends_at`. I nuovi account partono con Free e non ricevono questa offerta. Pro include 1 mese di prova gratuita. Aggiungi una carta per iniziarla; poi si rinnova ogni mese finché non annulli. Invia `response_version=3` per ricevere anche `offer`. Le versioni 1 e 2 non hanno questo campo. La versione 3 ha anche `sdk_dropped_events`.

```bash
curl "https://api.logbrew.co/api/account/usage?response_version=3" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

`offer` è `null` quando nessuna offerta è attiva. Altrimenti ha questi campi:

```json
{
  "offer": {
    "kind": "public_beta",
    "tier": "team",
    "starts_at": "2026-10-22T00:00:00Z",
    "ends_at": "2027-04-22T00:00:00Z"
  }
}
```

| Campo | Significato |
| --- | --- |
| `kind` | Perché le quote si applicano. Il valore è `public_beta`. |
| `tier` | Il piano di cui si applicano le quote. `team` è il piano Pro. |
| `starts_at`, `ends_at` | Il periodo dell'offerta. La fine è esclusa. |

Finché un'offerta è attiva, `limits.retention_days`, `state`, `limit`, `percent_used` e `next_action` usano le quote maggiori tra il piano proprio dell'account e l'offerta. `plan` mostra ancora il piano proprio dell'account. Dopo `ends_at`, l'account usa di nuovo il suo piano. Le versioni 1 e 2 seguono le stesse quote, ma non mostrano l'offerta. Il riepilogo di fatturazione, `GET /api/billing/overview`, ha lo stesso campo `offer`. Ha anche `pro_trial_available`, che è `true` quando un checkout di Pro avvia la prova gratuita.

### Stati della quota

Usa `state` per la scelta principale. `limit` vale `null` solo quando `state`
è `ok`.

| `state` | `warning` | `blocked` | `limit` | `next_action.code` | `next_action.target` |
| --- | --- | --- | --- | --- | --- |
| `ok` | `false` | `false` | `null` | `continue_sending_telemetry` | `telemetry_ingest` |
| `warning` | `true` | `false` | `events` o `bytes` | `reduce_usage_or_upgrade` | `pricing` |
| `blocked` | `false` | `true` | `events` o `bytes` | `wait_until_reset_or_upgrade` | `pricing` |

Questa tabella vale per le versioni 2 e 3. La versione 1, quella predefinita, ha
2 differenze: `warning` è `true` anche nello stato `blocked`, e nello stato
`warning` il valore di `next_action.target` è `account_usage`.

`next_action.state`, `next_action.limit` e `next_action.reset_at` ripetono i
valori di primo livello. I valori di `next_action.code` includono anche
`check_usage_limits` con il target `account_usage`. Se il tuo client riceve
questa coppia, leggi di nuovo l'utilizzo e mostra `next`.

LogBrew misura ogni tipo di telemetria rispetto alla sua quota. `limit` le
raggruppa:

- `events` comprende gli eventi dei problemi e gli span delle tracce.
- `bytes` comprende i byte dei log e i byte delle metriche.

Se una quota è bloccata e un'altra è in avviso, `limit` indica la quota
bloccata. Lo stato `warning` inizia quando l'utilizzo raggiunge
`warning_threshold` di una quota. Lo stato `blocked` inizia quando l'utilizzo
raggiunge la quota.

Il testo di `next` può cambiare, per esempio quando i piani non sono in
vendita. I valori di `next_action` non cambiano. Localizza a partire da
`next_action`. Non analizzare `next`.

Un limite di utilizzo dell'account non è un limite di frequenza dell'API.
Quando l'ingestione supera una quota, la richiesta di ingestione restituisce
`429` con `usage_limit_exceeded` e il corpo aggiunge `limit` e `reset_at`. In
questo errore, `limit` indica la quota esatta: `issue_events`, `log_bytes`,
`metric_bytes` o `trace_spans`. LogBrew rifiuta l'intera richiesta. Non
inviare di nuovo quel tipo di telemetria fino a `reset_at` o finché il piano
non cambia. Quando un client invia troppe richieste, l'API restituisce
`rate_limited`. Consulta [Errori API](/it/reference/api-errors#retry-rules).

La risposta è un'istantanea. Leggila di nuovo dopo una modifica all'account.

<Note>
  `GET /api/logs/usage` è una risposta legacy di compatibilità per mobile, con
  `bytes_used`, `limit_bytes` e `month`. Per le nuove integrazioni usa
  `GET /api/account/usage`.
</Note>

## Cronologia dell'utilizzo

`GET /api/account/usage/history` restituisce un numero limitato di fasce
temporali (bucket) di utilizzo, riempite con zeri, per grafici e report.
Imposta `interval` su un valore supportato. Se ometti `interval`, l'API usa
`monthly`. La route non accetta altre chiavi di query.

```bash
curl --get "https://api.logbrew.co/api/account/usage/history" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER" \
  --data-urlencode "interval=daily"
```

| `interval` | Fasce | Inizio della fascia |
| --- | ---: | --- |
| `daily` | 30 | 00:00 UTC |
| `weekly` | 12 | Lunedì, 00:00 UTC |
| `monthly` | 12 | Primo giorno del mese, 00:00 UTC |
| `yearly` | 5 | 1 gennaio, 00:00 UTC |

| Campo | Significato |
| --- | --- |
| `interval` | La granularità richiesta. |
| `period_start`, `period_end` | L'inizio e la fine esclusa dell'intervallo della cronologia. |
| `current` | La risposta completa di `GET /api/account/usage` per il periodo corrente, nella versione 3. Contiene sempre `sdk_dropped_events` e `offer`. |
| `buckets` | Le fasce in ordine di tempo, dalla più vecchia. Ogni fascia ha `period_start`, `period_end`, `usage`, `by_project` e `by_stream`. |

Questa risposta `yearly` usa dati sintetici per una richiesta di giugno 2026.
Tutto l'utilizzo è avvenuto a giugno:

```json
{
  "interval": "yearly",
  "period_start": "2022-01-01T00:00:00Z",
  "period_end": "2027-01-01T00:00:00Z",
  "current": {
    "period_start": "2026-06-01T00:00:00Z",
    "period_end": "2026-07-01T00:00:00Z",
    "reset_at": "2026-07-01T00:00:00Z",
    "plan": { "tier": "free", "status": "free" },
    "limits": { "events": null, "bytes": null, "projects": null, "retention_days": 30 },
    "usage": { "events": 27000, "bytes": 10485760, "projects": 1 },
    "state": "ok",
    "warning_threshold": 0.8,
    "percent_used": 0.02,
    "warning": false,
    "blocked": false,
    "limit": null,
    "next": "continue sending telemetry",
    "next_action": {
      "code": "continue_sending_telemetry",
      "target": "telemetry_ingest",
      "state": "ok",
      "limit": null,
      "reset_at": "2026-07-01T00:00:00Z"
    },
    "by_project": [
      { "project_id": "00000000-0000-4000-8000-000000000001", "events": 27000, "bytes": 10485760 }
    ],
    "by_stream": [{ "kind": "logs", "events": 27000, "bytes": 10485760 }],
    "sdk_dropped_events": [],
    "offer": null
  },
  "buckets": [
    { "period_start": "2022-01-01T00:00:00Z", "period_end": "2023-01-01T00:00:00Z", "usage": { "events": 0, "bytes": 0, "projects": 0 }, "by_project": [], "by_stream": [] },
    { "period_start": "2023-01-01T00:00:00Z", "period_end": "2024-01-01T00:00:00Z", "usage": { "events": 0, "bytes": 0, "projects": 0 }, "by_project": [], "by_stream": [] },
    { "period_start": "2024-01-01T00:00:00Z", "period_end": "2025-01-01T00:00:00Z", "usage": { "events": 0, "bytes": 0, "projects": 0 }, "by_project": [], "by_stream": [] },
    { "period_start": "2025-01-01T00:00:00Z", "period_end": "2026-01-01T00:00:00Z", "usage": { "events": 0, "bytes": 0, "projects": 0 }, "by_project": [], "by_stream": [] },
    {
      "period_start": "2026-01-01T00:00:00Z",
      "period_end": "2027-01-01T00:00:00Z",
      "usage": { "events": 27000, "bytes": 10485760, "projects": 1 },
      "by_project": [
        { "project_id": "00000000-0000-4000-8000-000000000001", "events": 27000, "bytes": 10485760 }
      ],
      "by_stream": [{ "kind": "logs", "events": 27000, "bytes": 10485760 }]
    }
  ]
}
```

Usa `current.reset_at` per l'azzeramento della quota. Non usare la fine
dell'intervallo della cronologia. `current` non è la somma delle fasce e le
sue date possono essere diverse da quelle dell'intervallo.

L'ultima fascia contiene il periodo di calendario corrente, che non è
completo. Il suo orario di fine futuro non significa che LogBrew abbia
misurato un utilizzo futuro. Una fascia con zeri significa che LogBrew non ha
contato alcun utilizzo in quella fascia.

In una fascia, `usage.projects` conta i progetti che hanno un utilizzo in
quella fascia. Non sommare questi conteggi per ottenere il numero di progetti.
Usa `current.usage.projects` per il numero di progetti di proprietà.

Rappresenta eventi e byte come serie separate, perché usano unità diverse. Le
fasce contengono l'utilizzo, non i costi. Non etichettare il grafico come
spesa, fatture o richieste API.

Un valore di `interval` non supportato restituisce `422`:

```json
{
  "error": "Unsupported usage history interval",
  "code": "validation_failed",
  "next": "use interval=daily, weekly, monthly, or yearly",
  "next_action": {
    "code": "fix_request",
    "target": "request"
  }
}
```

Anche una chiave di query sconosciuta restituisce `422` con
`validation_failed`.

## Piani e quote

`GET /api/billing/catalog` elenca i piani. Non richiede autenticazione. Ogni piano ha tutte le funzioni. Ogni piano ha membri e progetti illimitati. I piani differiscono per volume e conservazione. Le quote si azzerano a ogni mese di fatturazione. 1 GB sono 1.000.000.000 di byte.

Puoi acquistare Pro e Business con il pagamento online, e `checkout_available` è `true`. Per Enterprise, scrivi all'indirizzo `quote_email` del piano per chiedere un preventivo. Un account con un'[offerta per i nuovi account](#new-account-offer) attiva riceve gratis le quote di Pro fino alla fine dell'offerta.

| Piano | `tier` | Prezzo al mese | Log | Metriche delle app | Span delle tracce | Eventi dei problemi | Conservazione |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Free | `developer` | $0 | 50 GB | 50 GB | 50 milioni | 100.000 | 30 giorni |
| Pro | `team` | $25 | 500 GB | 500 GB | 500 milioni | 2 milioni | 90 giorni |
| Business | `business` | $80 | 2.000 GB | 2.000 GB | 2 miliardi | 10 milioni | 365 giorni |
| Enterprise | `enterprise` | Su preventivo | Personalizzato | Personalizzato | Personalizzato | Personalizzato | Personalizzato |

Il catalogo e il riepilogo di fatturazione usano i valori `tier` `developer`, `team`, `business` e `enterprise`. Le risposte di utilizzo e di abbonamento usano `free`, `pro` e `scale`. I piani Business ed Enterprise sono entrambi `scale`.

```bash
curl "https://api.logbrew.co/api/billing/catalog"
```

La risposta elenca i piani in quest'ordine. Questo esempio mostra il piano Pro:

```json
{
  "response_version": 1,
  "currency": "usd",
  "interval": "month",
  "checkout_available": true,
  "plans": [
    {
      "tier": "team",
      "monthly_price_cents": 2500,
      "activation": "checkout",
      "quote_email": null,
      "limits": {
        "issue_events": 2000000,
        "log_bytes": 500000000000,
        "metric_bytes": 500000000000,
        "trace_spans": 500000000,
        "retention_days": 90,
        "unlimited_projects": true
      }
    }
  ]
}
```

| Campo | Significato |
| --- | --- |
| `checkout_available` | `true` quando puoi acquistare un piano a pagamento. È `false` quando il pagamento online non è disponibile. |
| `monthly_price_cents` | Il prezzo in centesimi di dollaro. È `null` per un piano su preventivo. |
| `activation` | `included`, `checkout` o `quote`. |
| `quote_email` | L'indirizzo email a cui scrivi per ottenere un preventivo. È `null` per gli altri piani. |
| `limits` | Le quote di 1 mese di fatturazione. Un valore `null` è stabilito dal contratto. |

### <span id="data-retention">Conservazione dei dati</span>

La conservazione è il numero di giorni per cui LogBrew conserva la telemetria di un account. La conservazione dell'account è la maggiore tra quella del suo piano e quella di un'offerta attiva per i nuovi account. Un contratto Enterprise stabilisce la propria conservazione.

- Le letture restituiscono solo la telemetria compresa nella conservazione.
- Ogni giorno LogBrew elimina la telemetria dell'account più vecchia della
  conservazione più 1 giorno.
- Dopo un downgrade o la fine di un'offerta, la conservazione più breve si
  applica alla successiva eliminazione giornaliera.

## Stato dell'abbonamento

`GET /api/account/subscription` è di sola lettura. Usalo per decidere se attivare i controlli delle organizzazioni. Per lo stato della quota usa l'endpoint dell'utilizzo.

```bash
curl "https://api.logbrew.co/api/account/subscription" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

Un account gratuito restituisce questa risposta. L'`account_id` è sintetico:

```json
{
  "account_id": "00000000-0000-4000-8000-0000000000aa",
  "tier": "free",
  "billing_interval": "none",
  "state": "free",
  "access_state": "active",
  "current_period_start": null,
  "current_period_end": null,
  "renews_at": null,
  "cancels_at": null,
  "organization_creation_allowed": true,
  "organization_creation_blocker": null,
  "limits": {
    "organizations": 1,
    "members_per_organization": 9007199254740991,
    "projects_per_organization": 9007199254740991,
    "invitations_per_day": 20
  },
  "next": "<display text>",
  "next_action": {
    "code": "create_or_manage_organization",
    "target": "organization"
  }
}
```

Il valore `9007199254740991` in `members_per_organization` e `projects_per_organization` significa illimitato. È il numero intero più grande che i client JSON leggono con esattezza. Mostra «Illimitato» per questo valore. Solo il numero di organizzazioni possedute da un account può bloccare la creazione di un'organizzazione.

`next` è testo da mostrare. Mostra il testo restituito, oppure localizza a partire da `next_action`. Non fissare nel codice il nome di un piano ricavato da `next`.

Valori enum:

| Campo | Valori |
| --- | --- |
| `tier` | `free`, `pro`, `scale` |
| `billing_interval` | `none`, `monthly`, `yearly` |
| `state` | `free`, `trialing`, `active`, `past_due`, `paused`, `canceled` |
| `access_state` | `active` per `free`, `trialing` e `active`. `paused` per `past_due`, `paused` e `canceled`. |
| `organization_creation_blocker` | `organization_limit_exceeded` o `null` |

L'API non restituisce i motivi di blocco `subscription_required` e `subscription_inactive`. Ogni motivo di blocco ha una sola coppia `next_action`:

| `organization_creation_blocker` | `next_action.code` | `next_action.target` |
| --- | --- | --- |
| `null` | `create_or_manage_organization` | `organization` |
| `organization_limit_exceeded` | `manage_organization_limit` | `organization` |

I valori del tier sono identificatori, non nomi da mostrare. Mantienili invariati in un client localizzato. Controlla `organization_creation_allowed` prima di attivare la creazione di organizzazioni.

Questo endpoint non crea organizzazioni, non invia inviti, non cambia ruoli e
non modifica la fatturazione.

## Inviti all'organizzazione

Un proprietario o un amministratore dell'organizzazione invita un collega via email. LogBrew invia al collega un'email con un link all'invito. L'invito scade dopo 7 giorni. Questi endpoint mostrano l'invito all'account invitato prima che lo accetti. Un invito è tuo quando è stato inviato all'indirizzo email del tuo account o di un metodo di accesso collegato al tuo account.

Elenca i tuoi inviti in sospeso:

```bash
curl "https://api.logbrew.co/api/account/invitations" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

La risposta elenca gli inviti in sospeso non scaduti, dal più recente, fino a 100. Gli ID sono sintetici:

```json
{
  "invitations": [
    {
      "id": "00000000-0000-4000-8000-0000000000c1",
      "organization_id": "00000000-0000-4000-8000-0000000000b1",
      "organization_name": "Example Org",
      "role": "member",
      "state": "pending",
      "created_at": "2026-10-22T12:00:00Z",
      "expires_at": "2026-10-29T12:00:00Z",
      "inviter_name": "Example Owner",
      "accept_path": "/api/organizations/00000000-0000-4000-8000-0000000000b1/invitations/00000000-0000-4000-8000-0000000000c1/accept"
    }
  ]
}
```

Leggi un invito dal suo link:

```bash
curl "https://api.logbrew.co/api/organizations/$ORGANIZATION_ID/invitations/$INVITATION_ID" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

La risposta è un invito con gli stessi campi.

| Campo | Significato |
| --- | --- |
| `organization_name` | Il nome dell'organizzazione che ti ha invitato. |
| `role` | Il ruolo che ottieni quando accetti: `admin` o `member`. |
| `state` | `pending`, `accepted`, `expired` o `revoked`. Un invito in sospeso dopo `expires_at` è `expired`. |
| `inviter_name` | Il nome visualizzato dell'account che ha inviato l'invito, oppure `null`. |
| `accept_path` | Invia `POST` a questo percorso per accettare l'invito. |

Solo l'account invitato può leggere un invito. Un altro account, un ID invito sconosciuto e un'organizzazione sconosciuta ricevono tutti lo stesso `404` con `code: "not_found"`. Accedi con l'indirizzo email invitato e riprova.

Per accettare, invia `POST` a `accept_path` con l'account invitato. Una seconda accettazione dello stesso account restituisce la stessa appartenenza. Un invito scaduto o revocato restituisce `422` con `code: "invite_invalid"`. Chiedi un nuovo invito a un proprietario o a un amministratore.

Un account può inviare al massimo 20 inviti per giorno UTC, in tutte le sue organizzazioni. L'invito successivo restituisce `429` con `code: "invitation_limit_exceeded"` e `limit: "invitations_per_inviter_per_day"`. Attendi `reset_at`. Vedi [Errori API](/it/reference/api-errors#limit-fields).

## Disconnessione

Scegli l'ambito più piccolo adatto all'attività. Questi endpoint non eliminano
l'account o i suoi progetti, non ruotano le chiavi di ingestione e non
revocano l'autorizzazione concessa a un provider di accesso di terze parti.

| Ambito | Endpoint | Credenziale |
| --- | --- | --- |
| Un accesso dell'app o della CLI | `POST /api/auth/logout` | Il token di aggiornamento di quel client nel corpo JSON. Nessun token bearer. |
| Ogni accesso a LogBrew | `POST /api/auth/logout-all` | Token bearer dell'account o sessione del browser. Nessun corpo. |
| La sessione corrente del browser | `POST /api/auth/web/logout` | Nessuna. La risposta cancella il cookie del browser. |

### Un accesso dell'app o della CLI

Invia la richiesta dal client che possiede il token di aggiornamento. Imposta
`Content-Type: application/json`:

```json
{
  "refresh_token": "<current refresh token>"
}
```

Non chiedere mai a una persona o a un agente di stampare o incollare un token
di aggiornamento. Una risposta riuscita è `200`:

```json
{
  "revoked": true,
  "next_action": {
    "code": "clear_local_session",
    "target": "local_credentials"
  }
}
```

Questa richiesta revoca una famiglia di token di aggiornamento. LogBrew
rifiuta i successivi aggiornamenti per quell'accesso. Gli altri accessi
dell'account non cambiano. Un token di accesso che il client possiede già
resta valido fino alla scadenza. Se le credenziali dell'account potrebbero
essere esposte, usa [Ogni accesso a LogBrew](#every-logbrew-login).

Dopo la risposta, il client rimuove le sue credenziali locali. Se invii di
nuovo lo stesso token di aggiornamento valido, la risposta è lo stesso `200`.
Se il token non è valido, è scaduto o è un token di accesso, la risposta è
`401` con `code: "unauthorized"` e `next_action.code: "authorize_request"`.
Anche in questo caso, rimuovi le credenziali locali. `logbrew logout` usa
questo endpoint.

### <span id="every-logbrew-login">Ogni accesso a LogBrew</span>

<Warning>
  Questa richiesta disconnette ogni client dell'account. Ottieni
  l'approvazione del proprietario dell'account prima che un agente la invii.
</Warning>

Una risposta riuscita è `200`:

```json
{
  "revoked": true,
  "revoked_before": "2026-09-07T12:00:00.123Z",
  "next_action": {
    "code": "clear_local_session",
    "target": "local_credentials"
  }
}
```

`revoked_before` è incluso e ha una precisione al millisecondo. LogBrew
rifiuta token di accesso, sessioni del browser e token di aggiornamento
provenienti da un accesso eseguito in quell'istante o prima. Rifiuta anche un
token aggiornato in seguito a partire da un accesso di questo tipo. Le
sessioni attive del flusso in tempo reale terminano e la risposta cancella il
cookie di sessione del browser. Un accesso eseguito dopo quell'istante resta
valido. Ogni client deve rimuovere le proprie credenziali LogBrew locali ed
eseguire di nuovo l'accesso.

Non eseguire di nuovo l'accesso per poi ripetere questa richiesta in
automatico. Una nuova richiesta revoca anche il nuovo accesso.

Se la risposta va persa, non dichiarare che tutti gli accessi sono stati
revocati. Un successivo `401` da una vecchia credenziale non sostituisce la
risposta di successo. Per altri passaggi di ripristino, leggi
[Proteggi un account compromesso](/it/guides/troubleshooting#secure-a-compromised-account).

### Sessione del browser

`POST /api/auth/web/logout` cancella il cookie `logbrew_session` del browser e
restituisce `204 No Content` senza corpo. Chiamalo dal browser. Non copiare il
cookie di sessione in un comando. Questa richiesta non disconnette gli altri
client e non revoca una copia del valore del cookie. Per revocare ogni
sessione, usa [Ogni accesso a LogBrew](#every-logbrew-login).

### Risolvi un errore di disconnessione

| Risultato | Ripristino |
| --- | --- |
| `401` da `POST /api/auth/logout` | Rimuovi le credenziali locali del client. Non inviare un altro tipo di credenziale. |
| `401` da `POST /api/auth/logout-all` | Se l'utente vuole ancora l'accesso, esegui l'accesso da un client attendibile. Ottieni di nuovo l'approvazione prima di ripetere la richiesta. |
| `405` | Usa il metodo indicato da `next`, e solo per l'ambito che l'utente ha approvato. |
| `invalid_json` da `POST /api/auth/logout` | Invia un oggetto JSON con una stringa `refresh_token` e `Content-Type: application/json`. Non stampare il token. |
| Un timeout o uno stato `5xx` | Non dichiarare il successo. Non avviare un ciclo automatico di accesso e disconnessione. Segui le [regole per i nuovi tentativi di scrittura](/it/reference/api-errors#writes). |

Per le route, i filtri e la paginazione della telemetria, leggi
[API di telemetria](/it/reference/telemetry-api).
