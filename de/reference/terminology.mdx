LogBrew verwendet für jedes Produktkonzept genau einen Begriff. API-Felder,
CLI-Flags, Enum-Werte, Ereignisnamen und Attributschlüssel bleiben in jeder
Sprache unverändert.

## Observability und Monitoring

| Begriff | Bedeutung |
| --- | --- |
| Observability | Beobachtbarkeit: das Verhalten einer Anwendung anhand der Belege verstehen, die sie erzeugt. |
| Telemetrie | Die Signale, die eine Anwendung meldet, zum Beispiel Logs, Traces und Metriken. |
| Monitoring | Bekannte Bedingungen prüfen, zum Beispiel einen Messwert gegen einen Schwellenwert. |
| `o11y` | Eine Kurzform von Observability. Die Zahl zählt die 11 Buchstaben zwischen `o` und `y`. |

Wie Sie Signale auswählen, zeigen Beispiele unter
[Telemetrie](/de/concepts/telemetry).

## KI-Agenten

| Begriff | Bedeutung |
| --- | --- |
| MCP-Server | Der gehostete LogBrew-Server für das Model Context Protocol. KI-Agenten lesen darüber freigegebene Projekte. |
| MCP-Client | Eine Anwendung, die einen KI-Agenten mit einem MCP-Server verbindet, zum Beispiel Claude Code. |
| Freigegebenes Projekt | Ein Projekt, das Sie ausgewählt haben, als Sie einem MCP-Client Zugriff gegeben haben. Der Client kann nur freigegebene Projekte lesen. |
| Verbindung | Der Zugriff, den Sie 1 MCP-Client mit der Freigabe geben. Er endet nach 30 Tagen ohne Nutzung, nach 90 Tagen oder wenn Sie ihn widerrufen. Die CLI nennt ihn „Grant“. |

Wie Sie einen Client verbinden, lesen Sie unter
[KI-Agenten per MCP verbinden](/de/guides/mcp).

## Observability-Signale

<AccordionGroup>
  <Accordion title="Issue">
    Ein gruppiertes Problem, das mehrere Vorkommen enthalten kann. Ein
    Vorkommen ist ein einzelnes erfasstes Auftreten dieses Issues.
    `first_seen_at` ist die Zeit des ersten Vorkommens. `last_seen_at` ist die
    Zeit des neuesten Vorkommens.
  </Accordion>

  <Accordion title="Log">
    Ein einzelner Ereigniseintrag mit Zeitstempel, also ein Protokolleintrag.
    Ein Log kann Schweregrad, Dienst, Release, Umgebung, Trace-Kontext und
    datenschutzbegrenzte Attribute enthalten.
  </Accordion>

  <Accordion title="Trace und Span">
    Ein Trace verfolgt Arbeit über eine Anfrage oder Operation hinweg. Ein Span
    ist eine einzelne, zeitlich gemessene Operation in diesem Trace. Eine
    Korrelation mit einem Trace belegt gemeinsamen Kontext. Sie beweist keine
    Ursache.
  </Accordion>

  <Accordion title="Metrik">
    Ein Laufzeit-Messwert mit festgelegter Einheit, Art, Aggregation und
    festgelegtem Zeitraum. Metrikpunkte lassen sich nicht mit der Anzahl von
    Logs, Traces oder Issues gleichsetzen.
  </Accordion>

  <Accordion title="Release">
    Eine bereitgestellte Version einer Anwendung oder eines Dienstes, die mit
    der Telemetrie gemeldet wird. Ein Release ist nicht dasselbe Objekt wie ein
    Projekt oder ein Repository.
  </Accordion>

  <Accordion title="Aktion">
    Ein klassifiziertes Produktereignis, zum Beispiel eine Registrierung, ein
    Checkout, ein Import oder ein fehlgeschlagener Job. Analysen ordnen eine
    Aktion als Seitenaufruf, Bildschirmaufruf oder Interaktion ein. Eine Aktion
    ist kein automatischer Befehl, den LogBrew ausführt.
  </Accordion>
</AccordionGroup>

## Untersuchung von Issues

Nicht jedes Vorkommen enthält jedes Feld.

| Begriff | Bedeutung |
| --- | --- |
| Schweregrad | Die Dringlichkeit eines Signals: `info`, `warning`, `error` oder `critical`. Er ist unabhängig vom Issue-Status. |
| Issue-Status | Der Workflow-Zustand eines gruppierten Issues: `unresolved`, `resolved` oder `archived`. Er ist nicht das Ergebnis einer einzelnen Anfrage. |
| Archiviertes Issue | Ein Issue, das das Team aus der aktiven Triage genommen hat. Ältere Antworten nennen diesen Status `ignored`. |
| Issue-Priorität | Die Triage-Reihenfolge eines gruppierten Issues: `high`, `medium` oder `low`. Sie folgt dem Schweregrad, bis eine Person sie festlegt. |
| Prioritätsquelle | Woher die Priorität stammt. `derived` folgt dem Schweregrad: `error` und `critical` sind `high`, `warning` ist `medium`, und `info` ist `low`. `manual` ist eine Priorität, die eine Person festgelegt hat. |
| Zuständig | Genau 1 Konto oder 1 Team, das für den nächsten Schritt bei einem gruppierten Issue zuständig ist. Ein Konto muss das Projekt lesen können. Ein Team muss zur Organisation des Projekts gehören. |
| Team | Eine Gruppe von Mitgliedern einer Organisation, die einen Namen hat. Issues lassen sich einem Team zuweisen, und Zuständigkeitsregeln können es nennen. Ein Team gibt seinen Mitgliedern keinen Zugriff auf Projekte. |
| Zuständigkeitsregel | Eine Regel des Projekts, die einen Stackframe-Pfad, ein Modul, eine Route, einen Dienst oder ein Tag den Konten oder Teams zuordnet, die für passende Issues zuständig sind. |
| Zuständigkeitsvorschlag | Ein Konto oder Team, das LogBrew als zuständig für ein Issue vorschlägt. Der Vorschlag stammt aus einer Zuständigkeitsregel, einer Zeile der CODEOWNERS-Datei oder der letzten Aktivität. Es ist ein Vorschlag, keine Zuweisung. |
| Posteingang | Die Liste der Issues, die andere Personen Ihnen oder Ihren Teams zugewiesen haben. LogBrew verschickt dafür keine E-Mails. |
| Stacktrace | Erfasste Belege der Funktionsaufrufe zu einem Fehler. Er ist etwas anderes als ein verteilter Trace. |
| Stackframe | Ein Eintrag in einem Stacktrace. Er kann eine Funktion, ein Modul, eine Datei, eine Zeile oder eine Spalte bezeichnen. |
| Ausnahmekette | Verknüpfte Ausnahmen, die zusammen gemeldet werden, zum Beispiel ein Fehler und seine Ursache. Nicht erfasste, geschwärzte oder gekürzte Einträge begrenzen die Belege. |
| Anwendungsframe | Ein Stackframe, der als Anwendungscode markiert ist. Er zeigt Code, den Sie prüfen sollten. Er beweist nicht den Fehler. |
| Vorheriger Schritt | Ein kurzes Ereignis, das vor einem Vorkommen eines Issues aufgezeichnet wurde (Breadcrumb). Vorherige Schritte sind keine vollständige Aufzeichnung einer Sitzung. |
| Behandelte Ausnahme | Eine Ausnahme, die die Anwendung als behandelt gemeldet hat. Sie beweist nicht, dass die Operation erfolgreich war. |
| Source Map | Ein Build-Artefakt, also eine Quellzuordnung, die Stellen im generierten JavaScript den ursprünglichen Stellen im Quellcode zuordnet. |
| Symbolisierter Frame | Ein Frame, dessen generierte Stelle in ursprüngliche Quellcode-Informationen aufgelöst wurde. |
| Basis-Vorkommen | Das erfasste Vorkommen, das als Bezug für die Reproduktion dient. |
| Herkunft | Woher eine Bewertung stammt. `backend_observed` bedeutet, dass LogBrew sie beobachtet hat. `application_reported` bedeutet, dass die App sie gemeldet hat und LogBrew sie nicht geprüft hat. |
| Bereit zur Reproduktion | Ob das Basis-Vorkommen die Belege hat, die für einen Reproduktionsversuch nötig sind. Es ist kein bestandener Reproduktionstest. |

Die Lesereihenfolge und die Felder der Antwort beschreibt der
[Leitfaden zur Untersuchung](/de/guides/investigate-an-issue).

## Identität und Korrelation

Ein fehlender Wert beweist nicht, dass die zugehörige Aktivität nicht
stattgefunden hat.

| Begriff | Bedeutung |
| --- | --- |
| Trace-Kontext | Die Trace- und Span-Kennungen, die Arbeit über Signale hinweg verbinden. |
| Root-Span | Der Span, der einen Trace beginnt und keinen übergeordneten Span hat. Der früheste gelieferte Span ist nicht unbedingt der Root-Span. |
| Child-Span | Ein Span mit einem übergeordneten Span im selben Trace. |
| Korrelation | Eine exakte Beziehung, die LogBrew liefert, zum Beispiel eine gemeinsame Trace-ID. Sie beweist keine Ursache. |
| Identifizierter Nutzer | Ein von der App geliefertes Subjekt mit stabiler ID und der Art `user`. |
| Anonymes Subjekt | Ein von der App geliefertes Subjekt mit der Art `anonymous`. Zählungen halten es von identifizierten Nutzern getrennt. |
| Unbekannte Identitätsart | Ein Subjekt ohne bekannte Art. Es zählt nicht als identifizierter Nutzer. |
| Fehlendes Subjekt | Ein Ereignis ohne Subjekt. Das ist etwas anderes als ein Subjekt mit unbekannter Art. |

Die Identitätsart zeigt, wie die App ihr Subjekt eingeordnet hat. Sie beweist
nicht, dass die Daten anonym sind. Eine stabile ID kann Aktivitäten trotzdem
verknüpfen.

## Bereich und Datenqualität

| Begriff | Bedeutung |
| --- | --- |
| Projekt | Die wichtigste Produktgrenze mit eigener Zuständigkeit. Ein Projekt kann mehrere Dienste oder Repository-Komponenten enthalten. |
| Dienst | Eine meldende Laufzeit oder Komponente innerhalb eines Projekts. |
| Umgebung | Ein exakter Kontext, aus dem gemeldet wird, zum Beispiel production oder staging. |
| Ingest-Schlüssel | Ein Projektschlüssel, der Telemetrie an genau ein Projekt sendet. Er kann keine Telemetrie lesen. |
| Leseschlüssel | Ein Projektschlüssel, der die Telemetrie genau eines Projekts liest. Er kann keine Telemetrie senden, keine Daten ändern und sich nicht anmelden. Siehe [Arten von Projektschlüsseln](/de/guides/verify-setup#project-key-kinds). |
| Aufgenommen | Gemäß dem Vertrag der Signalaufnahme angenommen. Das verspricht keine unbegrenzte Aufbewahrung. |
| Indiziert | Im angegebenen Index oder für die angegebene Abfrage verfügbar. Es ist kein Synonym für aufgenommen. |
| Gespeichert | Im ausgewerteten Datenzeitraum und innerhalb der Datenaufbewahrung des Kontos vorhanden. |
| Per Sampling ausgewählt | Ein Teil der Telemetrie wurde vor oder während der Erfassung ausgewählt. |
| Abdeckung | Ein gemessener Anteil mit ausdrücklichem Zähler und Nenner. |
| Gekürzt | Die Antwort hat eine Grenze erreicht. Ausgelassene Daten fehlen nicht unbedingt. |
| Ungefähr | Mit der dokumentierten Methode geschätzt, nicht exakt gezählt. |
| Zeitraum | Die genaue Zeitspanne, die eine Abfrage auswertet. |

## Tarife und Organisationen

| Begriff | Bedeutung |
| --- | --- |
| Tarif | Ein fester Satz monatlicher Kontingente mit einer Aufbewahrungsdauer. Die Tarife sind Free, Pro, Business und Enterprise. |
| Kontingent | Die Menge einer Telemetrieart, die ein Tarif in 1 Abrechnungsmonat enthält, zum Beispiel Log-Bytes oder Trace-Spans. |
| Datenaufbewahrung | Die Zahl der Tage, die LogBrew die Telemetrie eines Kontos speichert. LogBrew löscht ältere Telemetrie. Das ist etwas anderes als die Nutzerbindung in der Produktanalyse. |
| Beta-Angebot | Pro-Kontingente, die Konten, die vor dem 2026-10-26 erstellt wurden, 6 Monate lang kostenlos erhalten. Danach gilt der eigene Tarif des Kontos. |
| Organisation | Ein gemeinsamer Bereich für Mitglieder, Teams und Projekte. Jeder Tarif hat Organisationen ohne Limit für Mitglieder und Projekte. |

Die Kontingente und die Aufbewahrungsdauer der einzelnen Tarife finden Sie in der [Konto-API](/de/reference/account-api).

## Messungen und Zeit

| Begriff | Bedeutung |
| --- | --- |
| Datenpunkt | Ein Wert zu einem gemeldeten Zeitpunkt. Lesen Sie Name und Einheit der Metrik, bevor Sie Datenpunkte vergleichen. |
| Zeitreihe | Werte derselben Messung, nach Zeit geordnet. Eine Lücke bedeutet nicht, dass der Wert null war. |
| Dauer | Die verstrichene Zeit einer Operation. Sie ist etwas anderes als der Zeitpunkt, zu dem die Operation stattfand. |
| Aggregation | Eine festgelegte Berechnung über Messungen, zum Beispiel eine Summe oder ein Durchschnitt. |
| Zeitfenster | Ein Intervall in einem Diagramm oder gruppierten Ergebnis. Sein Anfang und sein Ende legen den Bereich fest. |
| Unvollständiger Zeitraum | Ein Zeitraum, der noch nicht abgeschlossen ist. Er ist kein abgeschlossener Zeitraum ohne Aktivität. |

Addieren Sie nicht die Dauern sich überlappender Child-Spans, um die
Gesamtzeit einer Anfrage zu erhalten. Vergleichen Sie keine Anzahl von
Ereignissen mit einer Anzahl identifizierter Nutzer.

## Belegzustände

Diese Zustände sind nicht austauschbar:

- **Erfasst:** Der Beleg ist vorhanden.
- **Nicht erfasst:** Der Beleg wurde nicht erfasst.
- **Geschwärzt:** Der Beleg wurde absichtlich verborgen.
- **Gekürzt:** Der Beleg hat eine Grenze der Antwort oder der Erfassung
  überschritten.
- **Nicht verfügbar:** Die Abfrage konnte den Beleg nicht liefern.

`Likely cause` (wahrscheinliche Ursache) und `likely fix area`
(wahrscheinlicher Korrekturbereich) beschreiben begrenzte diagnostische
Belege, keine bewiesene Grundursache. `Reported impact` (gemeldete Auswirkung)
liefert die meldende Anwendung, außer ein Vertrag beschreibt ausdrücklich eine
Messung durch LogBrew.

## Produktanalysen

| Begriff | Bedeutung |
| --- | --- |
| Ereignis | Klassifizierte Produktaktivität mit einem exakten, stabilen Namen. |
| Eigenschaft | Ein Kontextschlüssel, der ein Ereignis beschreibt oder nach dem Sie filtern. |
| Sitzung | Ein Besuch oder eine App-Sitzung, keine Person. |
| Kohorte | Eine begrenzte Gruppe, die durch exakte Kriterien festgelegt ist. |
| Trichter | Geordnete Schritte, mit denen Sie Fortschritt oder Conversion messen. |
| Nutzerbindung | Rückkehrverhalten, gemessen mit einem ausdrücklichen Zeitraum und Nenner. |
| Pfade | Abläufe innerhalb einer Sitzung vor oder nach einem ausgewählten Ereignis. |
| Lebenszyklus | Ordnet identifizierte Subjekte in jedem Zeitraum als neu im beobachteten Verlauf, wiederkehrend, reaktiviert oder inaktiv ein. |
| Neu im beobachteten Verlauf | Aktiv ohne früheres ausgewähltes Ereignis im begrenzten Verlaufszeitraum. Das bedeutet nicht, dass es sich um einen Erstkunden handelt. |

Unvollständige Zeiträume, fehlende Identität, unvollständig erfasste
Eigenschaften, Sampling und Kürzung schränken das Ergebnis ein. LogBrew zeigt
diese Grenzen an, statt sie in null oder Gewissheit umzuwandeln.

Die Zählregeln beschreibt [Produktanalysen](/de/concepts/product-analytics).
Mit [Produktereignisse erfassen](/de/guides/product-events) senden Sie
klassifizierte Aktivität und typisierte Identität.
