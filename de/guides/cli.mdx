Die LogBrew-Kommandozeile (CLI) liest Logs, Issues, Traces und Aktionen im
Terminal. Sie kann auch den Issue-Status ändern. Mit `--json` erhalten Skripte
und KI-Agenten eine strukturierte Ausgabe.

Ersetzen Sie jeden Platzhalter in spitzen Klammern, bevor Sie einen Befehl
ausführen. Verwenden Sie Projekt-, Issue- und Trace-IDs, die LogBrew
zurückgegeben hat.

## CLI installieren

Wählen Sie eine Installationsmethode.

macOS oder Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
```

Homebrew:

```bash
brew install LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install logbrew-cli
```

Unter Windows können Sie auch das MSI-Paket aus dem
[neuesten Release](https://github.com/LogBrewCo/cli/releases/latest)
installieren.

<Note>
  Cargo braucht Rust 1.87 oder neuer. Die anderen Methoden installieren ein
  natives Binary und brauchen kein Rust.
</Note>

## CLI aktualisieren

Die CLI aktualisiert sich nicht selbst. Verwenden Sie dieselbe Methode, mit
der Sie sie installiert haben.

Homebrew:

```bash
brew update && brew upgrade LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install --locked logbrew-cli
```

Beim Shell- oder PowerShell-Installer führen Sie den Installer erneut aus.

Lesen Sie danach die Version. Vergleichen Sie sie mit dem
[neuesten Release](https://github.com/LogBrewCo/cli/releases/latest):

```bash
logbrew version --json
```

Das JSON enthält `ok`, `name`, `version`, `binary`, `os` und `arch`.

## Anmelden und Sitzung prüfen

Lesen Sie das Konto für das aktuelle Terminal:

```bash
logbrew status --json
logbrew whoami --json
```

Zeigt `whoami` das erwartete Konto, fahren Sie fort. Wenn nicht, melden Sie
sich an. Eine Person schließt die Anmeldung beim Anbieter im Browser ab. Ein
Coding-Agent muss eine Person bitten, diesen Schritt auszuführen.

```bash
logbrew login --provider github
```

Der Anbieter ist `github` (Standard), `gitlab`, `bitbucket` oder `google`. Mit
`--no-open` gibt die CLI die Anmelde-URL aus, ohne einen Browser zu öffnen.
Auch `--json` gibt die Angaben für die Anmeldung aus, ohne einen Browser zu
öffnen.

Führen Sie nach der Anmeldung `status` und `whoami` erneut aus. Schreiben Sie
Konto-Zugangsdaten nie in einen Prompt, einen Bericht oder eine Quelldatei.

## SDK-Einrichtung planen

Wechseln Sie in das Verzeichnis mit dem Paket- oder Build-Manifest der App.
Wählen Sie in einem Monorepo eine App oder einen Dienst. Führen Sie dann
diesen Befehl aus:

```bash
logbrew setup --json
```

Lesen Sie `detected`, `install_ready`, `install_plan` und `next`. Der Plan
nennt Laufzeit, Framework, Paketmanager und Installationsbefehl. Die CLI
installiert keine Pakete und ändert keine Dateien. `logbrew init`, `install`,
`configure` und `sdk` liefern denselben Plan.

<Warning>
  Tragen Sie einen Projekt-Ingest-Schlüssel in die SDK-Konfiguration ein.
  Verwenden Sie nie Konto-Zugangsdaten als SDK-Schlüssel. Halten Sie
  Ingest-Schlüssel aus der Versionsverwaltung heraus.
</Warning>

Die Schritte für jede Laufzeit finden Sie unter
[SDK-Integration](/de/guides/sdk-ingestion). Führen Sie
`logbrew examples` aus, um eine kurze Liste häufiger Befehle zu sehen.

## Projekte lesen, anlegen und konfigurieren

Listen Sie die aktiven Projekte in Ihrem Konto auf:

```bash
logbrew projects --json
```

Wählen Sie eine Projekt-ID aus dem Ergebnis. Verwenden Sie sie für Schlüssel
und Abfragen.

Um einen Ingest-Schlüssel für ein bestehendes Projekt zu erstellen, wählen Sie
eine neue Datei außerhalb der Versionsverwaltung. Die CLI schreibt den
Schlüssel in diese Datei, die nur der Eigentümer lesen kann. Sie gibt weder
den Schlüssel noch den Dateipfad aus.

```bash
logbrew projects keys create "<project_id>" --ingest-key-file "<private_key_file>" --json
```

| Flag | Wert |
| --- | --- |
| `--kind` | `sdk` (Standard), `browser`, `server`, `cli` oder `artifact`. Ein `artifact`-Schlüssel lädt Source Maps und native Debug-Dateien hoch. Er kann keine Telemetrie senden. |
| `--label` | Ein Name für den Schlüssel, bis zu 120 Zeichen. Standard ist `CLI-created SDK key`. |

Das JSON-Ergebnis enthält `status`, `project_id`, `ingest_key`, `checks` und
`next`. `ingest_key` enthält `id`, `label`, `kind`, `created_at` und
`expires_at` des Schlüssels. Wie Sie einen Schlüssel ersetzen, steht unter
[Ingest-Schlüssel rotieren](/de/guides/rotate-ingest-key).

Dieser Befehl erstellt Zugangsdaten. Prüfen Sie vorher, ob das Projekt stimmt.
Ist das Ergebnis unklar, führen Sie genau denselben Befehl erneut aus. Die CLI
verwendet dann den ausstehenden Versuch weiter. Verwenden Sie
`--abandon-retry` nur, um einen neuen Versuch zu starten.

Um ein neues Projekt anzulegen, folgen Sie dem
[Schnellstart](/de/quickstart). Er verwendet
`logbrew projects create "<name>" --ingest-key-file "<private_key_file>"`,
das den ersten Schlüssel auf dieselbe Weise speichert. Führen Sie
`logbrew setup --create-project` aus, um die Hilfe zum Anlegen eines Projekts
zu lesen. Dieser Befehl legt kein Projekt an.

Nach einem Einrichtungsschritt können Sie ihn für das Projekt festhalten. Der
Wert von `--source` ist `api`, `cli` oder `sdk`:

```bash
logbrew projects setup "<project_id>" --source cli --environment production --json
```

Lesen Sie dann die Projektbereitschaft:

```bash
logbrew doctor --project "<project_id>" --json
```

Der Exit-Code `0` bedeutet nicht, dass alle Prüfungen bestanden sind. Lesen
Sie den `status` des Berichts und jede einzelne Prüfung. Siehe die
[Referenz zum Doctor-Bericht](/de/reference/cli#read-a-project-doctor-report).

## Kontonutzung lesen

Lesen Sie Nutzung und Limits. Das ändert weder Konto noch Abrechnung.

```bash
logbrew usage --json
```

`logbrew account usage --json` liefert dasselbe Ergebnis. Die Antwort nennt
den Tarif, den Kontingentstatus, das Rücksetzdatum, die Nutzung pro Projekt
und pro Telemetrieart sowie einen nächsten Schritt. Zu den Feldern gehören
`plan`, `state`, `reset_at`, `by_project`, `by_stream` und `next`.

## Häufige Untersuchungen

Filtern Sie jede Abfrage nach Projekt. Fügen Sie Filter für Release,
Umgebung, Zeit oder Schweregrad hinzu, wenn der Befehl sie unterstützt. Siehe
[Filter](/de/reference/cli#filters).

  <Card title="Issues in einem Release" icon="tag">

    ```
  </Card>

  <Card title="Eine fehlgeschlagene Anfrage" icon="route">

    ```
  </Card>

  <Card title="Logs eines Release" icon="file-text">

## Live-Ereignisse beobachten

Mit watch sehen Sie neue Ereignisse, während Sie eine Änderung testen.
Drücken Sie Strg+C, um zu stoppen.

```bash
logbrew watch --severity error,critical --json
```

Watch gibt nur JSON aus. Ohne `--json` bricht der Befehl mit einem Fehler ab.
Fügen Sie `logs`, `issues` oder `actions` hinzu, um nur einen Typ zu
beobachten, zum Beispiel `logbrew watch logs --json`. Watch unterstützt keine
Traces oder Spans.

Watch hat keinen Filter für Projekt, Release oder Umgebung. Verwenden Sie für
ein einzelnes Projekt die Abfragen oben. Die unterstützten Ressourcen und
Filter stehen unter [Live-Beobachtung](/de/reference/cli#live-watch).

## Erst erklären, dann Code ändern

Lesen Sie den Kontext, bevor Sie eine Korrektur vorschlagen.

<Steps>
  <Step title="Issue lesen">
    ```bash
    logbrew read issue "<issue_id>" --json
    ```
  </Step>

  <Step title="Trace lesen">
    Führen Sie diesen Schritt nur aus, wenn das Issue eine Trace-ID hat. Ein
    Issue ohne Trace ist trotzdem gültig.

    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Step>

  <Step title="Erklärung lesen">
    ```bash
    logbrew explain issue "<issue_id>" --json
    ```

    Für ein Log verwenden Sie `logbrew explain log "<log_id>" --json`. Für
    eine Aktion verwenden Sie `logbrew explain action "<action_id>" --json`.
  </Step>

  <Step title="Issue nach der Prüfung lösen">
    ```bash
    logbrew set issue "<issue_id>" resolved --json
    ```

    Wie Sie Status, Priorität oder Zuweisung für viele Issues ändern,
    steht unter
    [Status und Priorität eines Issues ändern](/de/reference/cli#change-issue-status-and-priority)
    und im [Issue-Workflow](/de/guides/issue-workflow).
  </Step>
</Steps>

## JSON-Ausgabe

- Setzen Sie `--json` vor oder hinter den Befehl, zum Beispiel
  `logbrew --json status` oder `logbrew status --json`.
- Lesen Sie den Exit-Code, bevor Sie die Ausgabe verwenden.
- JSON-Fehler enthalten `ok`, `error`, `message` und `next`. Eine
  Zeitüberschreitung beweist nicht, dass ein Schreibvorgang fehlgeschlagen
  ist. Lesen Sie die Wiederholungsregeln, bevor Sie einen Schreibvorgang
  wiederholen.
- Automatisieren Sie nicht mit Ausgabe ohne `--json`. Sie kann sich ändern.

Exit-Codes und Fehlerbeispiele finden Sie unter
[Ergebnisse und Fehler lesen](/de/reference/cli#read-results-and-errors).
