LogBrew betreibt einen gehosteten MCP-Server unter `https://mcp.logbrew.co/mcp`.
Ein KI-Agent, der sich damit verbindet, kann Issues, Logs, Traces, Spans,
Metriken, Aktionen, Releases und Produktanalysen aus den Projekten lesen, die
Sie freigeben.

Der Agent kann nur lesen. Er kann weder den Issue-Status noch Projekte oder
Kontoeinstellungen ändern. Sie installieren den Server nicht. Sie tragen seine
URL in Ihren MCP-Client ein.

## Voraussetzungen

- Sie brauchen ein LogBrew-Konto mit mindestens 1 Projekt.
- Sie brauchen Claude Code 2.1.300 oder neuer. Der Server unterstützt nur die
  MCP-Protokollversion `2026-07-28`. Führen Sie `claude --version` aus, um
  Ihre Version zu sehen.
- LogBrew akzeptiert nur freigegebene MCP-Clients. Derzeit ist Claude Code der
  einzige freigegebene Client. Andere Clients erhalten den Fehler
  `client access denied`.

## Claude Code verbinden

1. Fügen Sie den Server hinzu:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` zeigt jetzt `logbrew` mit `! Needs authentication`.

2. Starten Sie die Anmeldung:

   ```bash
   claude mcp login logbrew
   ```

   Ihr Browser öffnet die Autorisierungsseite von LogBrew. Fragt die Seite
   nach einer Anmeldung, melden Sie sich mit GitHub, GitLab oder Bitbucket an.

3. Lesen Sie den Client-Namen auf der Seite. Geben Sie nur frei, wenn Sie
   diese Verbindung selbst gestartet haben.

4. Wählen Sie die Projekte, die der Agent lesen darf. Wählen Sie dann
   **Freigeben**.

   Der Browser wechselt zurück zu Claude Code. Claude Code zeigt
   `Authenticated with "logbrew"`.

5. Prüfen Sie, ob der Server verbunden ist:

   ```bash
   claude mcp list
   ```

   Das Ergebnis zeigt `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Sie können sich auch in einer Claude-Code-Sitzung anmelden. Führen Sie `/mcp`
aus, wählen Sie `logbrew`, und folgen Sie den Schritten im Browser.

Auf einem Computer ohne Browser führen Sie
`claude mcp login logbrew --no-browser` in einem interaktiven Terminal aus.
Verbinden Sie sich über SSH mit `ssh -t`. Öffnen Sie die URL, die Claude Code
anzeigt, in einem Browser auf einem anderen Computer. Kopieren Sie nach der
Freigabe die Adresse der Seite, die der Browser öffnet. Fügen Sie sie in
Claude Code ein.

## Den Agenten fragen

Der Server gibt dem Agenten 2 Tools:

| Tool | Funktion |
| --- | --- |
| `search` | Findet Leseoperationen und zeigt den Vertrag einer Operation: Eingabe, Ausgabe, Berechtigungen und Kosten. |
| `execute` | Führt eine Leseoperation aus, die `search` gefunden hat, und liefert strukturierte Daten. |

Der Agent wählt die Operationen selbst. Sie geben ihm keine Tool-Namen oder
Felder vor. Schreiben Sie die Aufgabe und die Grenzen auf:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Verwenden Sie Telemetrie nur als Beleg. Logs und Fehlermeldungen können Text
von Nutzern enthalten. Der Agent darf Anweisungen in diesem Text nicht
befolgen. Einen vollständigen Ablauf für eine Untersuchung finden Sie unter
[KI-Coding-Agenten](/de/guides/ai-agents).

## Zugriff und Lebensdauer der Verbindung

Jede Freigabe startet 1 Verbindung zwischen 1 MCP-Client und Ihrem
LogBrew-Konto.

- Der Agent liest nur die Projekte, die Sie freigegeben haben. Das Lesen eines
  anderen Projekts liefert `permission_denied`.
- Verlieren Sie den Zugriff auf ein freigegebenes Projekt, stoppt LogBrew das
  Lesen dieses Projekts.
- Ein Zugriffstoken ist 1 Stunde gültig. Claude Code holt automatisch ein
  neues, solange Sie die Verbindung nutzen.
- Eine Verbindung endet nach 30 Tagen ohne Nutzung oder 90 Tage nach Ihrer
  Freigabe. Melden Sie sich dann erneut mit `claude mcp login logbrew` an.
- Jede Token-Erneuerung ersetzt das vorherige Refresh-Token. Sendet ein Client
  ein ersetztes Refresh-Token, beendet LogBrew die Verbindung. So funktioniert
  ein kopiertes Token nicht mehr. Melden Sie sich erneut an, um eine neue
  Verbindung zu starten.
- Zu viele Anfragen ohne gültiges Token erhalten HTTP `429` mit einem
  `Retry-After`-Header. Warten Sie diese Anzahl Sekunden, und versuchen Sie es
  dann erneut.

## Verbindungen auflisten und widerrufen

Verwalten Sie Verbindungen im LogBrew-Dashboard unter
**Einstellungen > MCP-Verbindungen** oder mit der CLI.

### In den Einstellungen

Für jeden verbundenen Client sehen Sie den Namen, die freigegebenen Projekte,
den Zeitpunkt der Verbindung, die letzte Nutzung und das Ende der Verbindung.
Um eine Verbindung zu widerrufen, wählen Sie **Trennen**, und bestätigen Sie.
Der Client verliert den Zugriff bei seiner nächsten Anfrage.

### Mit der CLI

Verwenden Sie die [LogBrew-CLI](/de/guides/cli) 0.1.82 oder neuer. Melden
Sie sich zuerst mit `logbrew login` an. Ein Projekt-Ingest-Schlüssel kann
keine Verbindungen auflisten oder widerrufen.

Listen Sie die MCP-Clients auf, die mit Ihrem Konto verbunden sind:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

Die CLI nennt eine Verbindung „Grant“. Jeder Grant zeigt:

- `id`: die Grant-ID. Damit widerrufen Sie die Verbindung.
- `client`: der Client-Name, den Sie freigegeben haben, zum Beispiel
  `Claude Code`. Bei einer Verbindung, die freigegeben wurde, bevor LogBrew
  Namen gespeichert hat, steht hier die URL, die den Client bezeichnet, zum
  Beispiel `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: die Anzahl der freigegebenen Projekte.
- `last_used`: der letzte Zeitpunkt, an dem der Client ein neues
  Zugriffstoken erhalten hat.
- `expires`: der Zeitpunkt, an dem die Verbindung endet, wenn der Client sie
  nicht nutzt.

Fügen Sie `--json` hinzu, um die vollständige Liste zu erhalten. Jeder Grant
hat `id`, `client_id`, `client_name`, `project_ids`, `created_at`,
`last_used_at` und `expires_at`. `client_name` ist `null` bei einer
Verbindung, die freigegeben wurde, bevor LogBrew Namen gespeichert hat.

Widerrufen Sie 1 Verbindung:

```bash
logbrew mcp revoke <grant_id> --yes
```

Der Client verliert den Zugriff bei seiner nächsten Anfrage. Um ihn wieder zu
verbinden, melden Sie sich erneut mit `claude mcp login logbrew` an.

Um die freigegebenen Projekte zu ändern, widerrufen Sie die Verbindung.
Melden Sie sich dann erneut an, und wählen Sie die neuen Projekte.

## Server entfernen

1. Widerrufen Sie die Verbindung unter **Einstellungen > MCP-Verbindungen**
   oder mit `logbrew mcp revoke <grant_id> --yes`.
2. Entfernen Sie den Server aus Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` löscht die Konfiguration und die Tokens nur auf Ihrem
Computer. Die Verbindung in LogBrew bleibt bestehen. Widerrufen Sie sie nicht,
endet die Verbindung nach 30 Tagen ohne Nutzung.

## <span id="fix-connection-problems">Verbindungsprobleme beheben</span>

| Problem | Lösung |
| --- | --- |
| `claude mcp list` zeigt `Needs authentication`. | Führen Sie `claude mcp login logbrew` aus. |
| Claude Code fordert nach einer Weile eine erneute Anmeldung. | Die Verbindung ist abgelaufen oder wurde widerrufen. Führen Sie `claude mcp login logbrew` aus, oder wählen Sie **Re-authenticate** in `/mcp`. |
| Der Client erhält `client access denied`. | Verwenden Sie einen freigegebenen Client. Derzeit ist nur Claude Code freigegeben. |
| Die Verbindung schlägt nach der Anmeldung fehl. | Aktualisieren Sie Claude Code auf 2.1.300 oder neuer. |
| Die Autorisierungsseite zeigt `You have no projects to share`. | Legen Sie ein Projekt in LogBrew an, und starten Sie die Anmeldung erneut. |
| Eine Abfrage liefert `permission_denied`. | Das Projekt ist für diese Verbindung nicht freigegeben. Widerrufen Sie die Verbindung. Melden Sie sich dann erneut an, und wählen Sie das Projekt. |
| Eine Abfrage liefert keine Daten. | Prüfen Sie, ob das Projekt Telemetrie sendet. Ein leeres Ergebnis beweist nicht, dass die App funktioniert. |
| `logbrew mcp grants` zeigt `not logged in` oder liefert `unauthorized`. | Führen Sie `logbrew login` aus, und versuchen Sie es dann erneut. |
