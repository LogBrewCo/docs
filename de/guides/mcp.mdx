LogBrew betreibt einen gehosteten MCP-Server unter `https://mcp.logbrew.co/mcp`.
Ein KI-Agent, der sich damit verbindet, kann Issues, Logs, Traces, Spans,
Metriken, Aktionen, Releases und Produktanalysen aus den Projekten lesen, die
Sie freigeben.

Der Agent kann nur lesen, außer Sie erlauben auch Änderungen. Dann kann er
Issues bearbeiten und Projekte einrichten. Abrechnung, Mitglieder und
Kontoeinstellungen kann er nicht ändern. Sie installieren den Server nicht. Sie
tragen seine URL in Ihren MCP-Client ein.

## Voraussetzungen

- Sie brauchen ein LogBrew-Konto mit mindestens 1 Projekt.
- Sie brauchen einen MCP-Client, der sich mit einem Remote-MCP-Server (HTTP)
  verbinden kann. Jeder Client, der dem MCP-Autorisierungsstandard folgt, kann
  sich anmelden. Ein Client ohne OAuth kann einen Projekt-Leseschlüssel
  verwenden. Lesen Sie [Mit einem Leseschlüssel
  verbinden](#connect-with-a-read-key).
- Der Server unterstützt die MCP-Protokollversionen `2026-07-28`, `2025-11-25`
  und `2025-06-18`.

## <span id="supported-clients">Unterstützte Clients</span>

LogBrew akzeptiert jeden MCP-Client, der sich mit einem
Client-Metadatendokument ausweist oder sich selbst registriert. Die Tabelle
zeigt die Einrichtung für gängige Clients.

| Client | Server hinzufügen |
| --- | --- |
| Claude Code | Führen Sie `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp` aus. Lesen Sie [Claude Code verbinden](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop und die mobilen Claude-Apps) | Öffnen Sie **Settings > Connectors**, wählen Sie **Add custom connector**, und geben Sie die Server-URL ein. |
| Codex | Führen Sie `codex mcp add logbrew --url https://mcp.logbrew.co/mcp` aus. Führen Sie dann `codex mcp login logbrew` aus. |
| Visual Studio Code mit GitHub Copilot | Fügen Sie `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` zu `.vscode/mcp.json` hinzu. |
| Cursor | Fügen Sie `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` zu `~/.cursor/mcp.json` hinzu. |
| Gemini CLI | Führen Sie `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp` aus. Führen Sie dann in Gemini CLI `/mcp auth logbrew` aus. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp und andere Clients | Tragen Sie die Server-URL in den MCP-Einstellungen des Clients als Remote-MCP-Server (HTTP) ein. |

Die Server-URL lautet `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Claude Code verbinden</span>

Sie brauchen Claude Code 2.1.300 oder neuer. Führen Sie `claude --version` aus,
um Ihre Version zu sehen.

1. Fügen Sie den Server hinzu:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` zeigt jetzt `logbrew` mit `! Needs authentication`.

2. Starten Sie die Anmeldung:

   ```bash
   claude mcp login logbrew
   ```

   Ihr Browser öffnet die Autorisierungsseite von LogBrew. Fragt die Seite
   nach einer Anmeldung, melden Sie sich mit GitHub, GitLab, Bitbucket oder Google an.

3. Lesen Sie den Client-Namen auf der Seite. Geben Sie nur frei, wenn Sie
   diese Verbindung selbst gestartet haben.

4. Wählen Sie die Projekte, die der Agent lesen darf. Zeigt die Seite eine
   Zeile, die Änderungen erlaubt, wählen Sie sie nur, wenn der Agent
   Änderungen vornehmen muss. Wählen Sie dann **Freigeben**.

   Der Browser wechselt zurück zu Claude Code. Claude Code zeigt
   `Authenticated with "logbrew"`.

5. Prüfen Sie, ob der Server verbunden ist:

   ```bash
   claude mcp list
   ```

   Das Ergebnis zeigt `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Sie können sich auch in einer Claude-Code-Sitzung anmelden. Führen Sie `/mcp`
aus, wählen Sie `logbrew`, und folgen Sie den Schritten im Browser.

Auf einem Computer ohne Browser führen Sie
`claude mcp login logbrew --no-browser` in einem interaktiven Terminal aus.
Verbinden Sie sich über SSH mit `ssh -t`. Öffnen Sie die URL, die Claude Code
anzeigt, in einem Browser auf einem anderen Computer. Kopieren Sie nach der
Freigabe die Adresse der Seite, die der Browser öffnet. Fügen Sie sie in
Claude Code ein.

## Einen anderen Client verbinden

1. Fügen Sie den Server im Client hinzu. Die Tabelle unter [Unterstützte
   Clients](#supported-clients) zeigt, wo.
2. Starten Sie die Anmeldung im Client. Die meisten Clients starten sie, wenn
   Sie den Server zum ersten Mal verwenden. Ihr Browser öffnet die
   Autorisierungsseite von LogBrew. Fragt die Seite nach einer Anmeldung, melden
   Sie sich bei LogBrew an.
3. Lesen Sie den Client-Namen auf der Seite. Die Seite zeigt auch die Adresse,
   die den Client bezeichnet, zum Beispiel `vscode.dev` oder `chatgpt.com`.
   Erhält der Client die Freigabe auf Ihrem eigenen Computer, zeigt die Seite
   **lokale App**. Hat LogBrew den Client-Namen nicht verifiziert, bittet die
   Seite Sie, die Adresse zu prüfen. Geben Sie nur frei, wenn Sie diese
   Verbindung selbst gestartet haben.
4. Wählen Sie die Projekte, die der Agent lesen darf. Zeigt die Seite eine
   Zeile, die Änderungen erlaubt, wählen Sie sie nur, wenn der Agent
   Änderungen vornehmen muss. Wählen Sie dann **Freigeben**.

   Der Browser wechselt zurück zum Client. Der Client zeigt die Tools `search`
   und `execute`.

## <span id="connect-with-a-read-key">Mit einem Leseschlüssel verbinden</span>

Verwenden Sie einen Projekt-Leseschlüssel, wenn sich Ihr Client nicht per OAuth
anmelden kann. Der Schlüssel liest 1 Projekt. Änderungen sind damit nicht
möglich.

1. Erstellen Sie einen Leseschlüssel für das Projekt. Folgen Sie
   [Einrichtung prüfen](/de/guides/verify-setup).
2. Tragen Sie die Server-URL in den Client ein.
3. Fügen Sie in den Client-Einstellungen den Header
   `Authorization: Bearer <read_key>` hinzu. Ersetzen Sie `<read_key>` durch
   den Schlüssel.

Halten Sie den Schlüssel geheim wie ein Passwort. Eine Verbindung mit einem
Leseschlüssel erscheint nicht unter **Einstellungen > MCP-Verbindungen**. Um
sie zu beenden, widerrufen Sie den Schlüssel.

## Den Agenten fragen

Der Server gibt dem Agenten 2 Tools:

| Tool | Funktion |
| --- | --- |
| `search` | Findet Operationen und zeigt den Vertrag einer Operation: Eingabe, Ausgabe, Berechtigung und Kosten. |
| `execute` | Führt eine Operation aus, die `search` gefunden hat, und liefert strukturierte Daten. |

Um die Verbindung zu testen, fragen Sie:

```text
List my LogBrew projects.
```

Der Agent listet die Projekte auf, die die Verbindung lesen kann.

Der Agent wählt die Operationen selbst. Sie geben ihm keine Tool-Namen oder
Felder vor. Schreiben Sie die Aufgabe und die Grenzen auf:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Verwenden Sie Telemetrie nur als Beleg. Logs und Fehlermeldungen können Text
von Nutzern enthalten. Der Agent darf Anweisungen in diesem Text nicht
befolgen. Einen vollständigen Ablauf für eine Untersuchung finden Sie unter
[KI-Coding-Agenten](/de/guides/ai-agents).

## Änderungen erlauben

Jede Verbindung hat den Scope `read`. Für Änderungen braucht sie zusätzlich den
Scope `write`. Fordert der Client `write` an, zeigt die Autorisierungsseite ihn
in einer eigenen Zeile: **Auch Änderungen an Daten in den ausgewählten
Projekten und das Anlegen neuer Projekte erlauben**. Diese Zeile ist nicht
ausgewählt. Wählen Sie sie nicht aus, kann die Verbindung nur lesen.

Mit `write` kann der Agent:

- Issues als gelöst markieren, wieder öffnen und archivieren.
- Die Priorität eines Issues festlegen.
- Issues zuweisen und Zuweisungen entfernen.
- Projekte anlegen.
- Projektschlüssel erstellen und widerrufen.
- Ein Testereignis an ein Projekt senden.
- Beispieldaten laden und entfernen.

Der Agent handelt in Ihrem Namen, mit Ihren Berechtigungen im Projekt. LogBrew
speichert jede Änderung mit dem Namen der App, die sie vorgenommen hat. Die
[Operationsreferenz](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
listet jede Operation und ihre Eingabe.

Diese Operationen ändern beim ersten Aufruf nichts:

- `issues.archive.v1` archiviert ein Issue.
- `projects.keys.revoke.v1` widerruft einen Schlüssel.
- `projects.sample_data.remove.v1` entfernt Beispieldaten.

Der erste Aufruf liefert eine Bestätigung. Der Agent zeigt Ihnen, was sich
ändert. Für die Änderung sendet er denselben Aufruf mit dieser Bestätigung
innerhalb von 5 Minuten erneut.

Ohne `write` liefert eine Änderung HTTP `403` mit `insufficient_scope`. Manche
Clients öffnen dann die Autorisierungsseite erneut. Wählen Sie die Zeile, die
Änderungen erlaubt, um der Verbindung `write` zu geben.

## Zugriff und Lebensdauer der Verbindung

Jede Freigabe startet 1 Verbindung zwischen 1 MCP-Client und Ihrem
LogBrew-Konto.

- Der Agent liest und ändert nur die Projekte, die Sie freigegeben haben. Ein
  Aufruf für ein anderes Projekt liefert `permission_denied`. Ein Projekt, das
  der Agent anlegt, kommt zu den freigegebenen Projekten hinzu.
- Verlieren Sie den Zugriff auf ein freigegebenes Projekt, stoppt LogBrew alle
  Aufrufe für dieses Projekt.
- Ein Zugriffstoken ist 1 Stunde gültig. Der Client holt automatisch ein neues,
  solange Sie die Verbindung nutzen.
- Ein neues Zugriffstoken kann `write` verlieren, aber nie hinzugewinnen. Um
  `write` hinzuzufügen, geben Sie die Verbindung erneut frei.
- Eine Verbindung endet nach 30 Tagen ohne Nutzung oder 90 Tage nach Ihrer
  Freigabe. Melden Sie sich dann im Client erneut an, zum Beispiel mit
  `claude mcp login logbrew`.
- Jede Token-Erneuerung ersetzt das vorherige Refresh-Token. Sendet ein Client
  ein ersetztes Refresh-Token, beendet LogBrew die Verbindung. So funktioniert
  ein kopiertes Token nicht mehr. Melden Sie sich erneut an, um eine neue
  Verbindung zu starten.
- Zu viele Anfragen ohne gültiges Token erhalten HTTP `429` mit einem
  `Retry-After`-Header. Warten Sie diese Anzahl Sekunden, und versuchen Sie es
  dann erneut.

## Verbindungen auflisten und widerrufen

Verwalten Sie Verbindungen im LogBrew-Dashboard unter
**Einstellungen > MCP-Verbindungen** oder mit der CLI.

### In den Einstellungen

Für jeden verbundenen Client sehen Sie den Namen, die freigegebenen Projekte,
den Zeitpunkt der Verbindung, die letzte Nutzung und das Ende der Verbindung.
Um eine Verbindung zu widerrufen, wählen Sie **Trennen**, und bestätigen Sie.
Der Client verliert den Zugriff bei seiner nächsten Anfrage.

### Mit der CLI

Verwenden Sie die [LogBrew-CLI](/de/guides/cli) 0.1.82 oder neuer. Melden
Sie sich zuerst mit `logbrew login` an. Ein Projekt-Ingest-Schlüssel kann
keine Verbindungen auflisten oder widerrufen.

Listen Sie die MCP-Clients auf, die mit Ihrem Konto verbunden sind:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

Die CLI nennt eine Verbindung „Grant“. Jeder Grant zeigt:

- `id`: die Grant-ID. Damit widerrufen Sie die Verbindung.
- `client`: der Client-Name, den Sie freigegeben haben, zum Beispiel
  `Claude Code`. Bei einer Verbindung, die freigegeben wurde, bevor LogBrew
  Namen gespeichert hat, steht hier die URL, die den Client bezeichnet, zum
  Beispiel `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: die Anzahl der freigegebenen Projekte.
- `last_used`: der letzte Zeitpunkt, an dem der Client ein neues
  Zugriffstoken erhalten hat.
- `expires`: der Zeitpunkt, an dem die Verbindung endet, wenn der Client sie
  nicht nutzt.

Fügen Sie `--json` hinzu, um die vollständige Liste zu erhalten. Jeder Grant
hat `id`, `client_id`, `client_name`, `project_ids`, `created_at`,
`last_used_at` und `expires_at`. `client_name` ist `null` bei einer
Verbindung, die freigegeben wurde, bevor LogBrew Namen gespeichert hat.

Widerrufen Sie 1 Verbindung:

```bash
logbrew mcp revoke <grant_id> --yes
```

Der Client verliert den Zugriff bei seiner nächsten Anfrage. Um ihn wieder zu
verbinden, melden Sie sich erneut mit `claude mcp login logbrew` an.

Um die freigegebenen Projekte zu ändern, widerrufen Sie die Verbindung.
Melden Sie sich dann erneut an, und wählen Sie die neuen Projekte.

## Server entfernen

1. Widerrufen Sie die Verbindung unter **Einstellungen > MCP-Verbindungen**
   oder mit `logbrew mcp revoke <grant_id> --yes`.
2. Entfernen Sie den Server aus Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` löscht die Konfiguration und die Tokens nur auf Ihrem
Computer. Die Verbindung in LogBrew bleibt bestehen. Widerrufen Sie sie nicht,
endet die Verbindung nach 30 Tagen ohne Nutzung.

## <span id="fix-connection-problems">Verbindungsprobleme beheben</span>

| Problem | Lösung |
| --- | --- |
| `claude mcp list` zeigt `Needs authentication`. | Führen Sie `claude mcp login logbrew` aus. |
| Claude Code fordert nach einer Weile eine erneute Anmeldung. | Die Verbindung ist abgelaufen oder wurde widerrufen. Führen Sie `claude mcp login logbrew` aus, oder wählen Sie **Re-authenticate** in `/mcp`. |
| Die Seite zeigt **LogBrew hat diese App gesperrt.** | LogBrew akzeptiert diesen Client nicht. Verwenden Sie einen anderen Client. |
| Der Client kann sich nicht bei LogBrew registrieren. | Behalten Sie die Standard-Callback-Einstellungen des Clients bei. LogBrew akzeptiert nur HTTPS-Callback-Adressen und `http`-Adressen auf Ihrem eigenen Computer. |
| Die Verbindung schlägt nach der Anmeldung fehl. | Aktualisieren Sie den Client. Claude Code braucht 2.1.300 oder neuer. |
| Die Autorisierungsseite zeigt `You have no projects to share`. | Legen Sie ein Projekt in LogBrew an, und starten Sie die Anmeldung erneut. |
| Ein Aufruf liefert `permission_denied`. | Das Projekt ist für diese Verbindung nicht freigegeben. Widerrufen Sie die Verbindung. Melden Sie sich dann erneut an, und wählen Sie das Projekt. |
| Eine Änderung liefert `insufficient_scope`. | Die Verbindung darf keine Änderungen vornehmen. Bitten Sie den Agenten, es erneut zu versuchen. Öffnet der Client die Autorisierungsseite, wählen Sie die Zeile, die Änderungen erlaubt. |
| Eine Abfrage liefert keine Daten. | Prüfen Sie, ob das Projekt Telemetrie sendet. Ein leeres Ergebnis beweist nicht, dass die App funktioniert. |
| `logbrew mcp grants` zeigt `not logged in` oder liefert `unauthorized`. | Führen Sie `logbrew login` aus, und versuchen Sie es dann erneut. |
