LogBrew komut satırı arayüzü (CLI), logları, sorunları, izleri ve aksiyonları
terminalden okur. Sorun durumunu da güncelleyebilir. Betiklere ve AI
agentlara yapılandırılmış çıktı vermek için `--json` kullanın.

Bir komutu çalıştırmadan önce açılı ayraç içindeki her yer tutucuyu
değiştirin. LogBrew'ün döndürdüğü proje, sorun ve iz kimliklerini kullanın.

## CLI'ı kurun

Bir kurulum yöntemi seçin.

macOS veya Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
```

Homebrew:

```bash
brew install LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install logbrew-cli
```

Windows'ta MSI dosyasını
[en son sürümden](https://github.com/LogBrewCo/cli/releases/latest) de
kurabilirsiniz.

<Note>
  Cargo için Rust 1.87 veya üstü gerekir. Diğer yöntemler yerel bir ikili
  dosya kurar ve Rust gerektirmez.
</Note>

## CLI'ı güncelleyin

CLI kendini güncellemez. Kurarken kullandığınız yöntemi kullanın.

Homebrew:

```bash
brew update && brew upgrade LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install --locked logbrew-cli
```

Shell veya PowerShell kurulum betiğiyle kurduysanız betiği yeniden
çalıştırın.

Ardından sürümü okuyun. Sürümü
[en son sürümle](https://github.com/LogBrewCo/cli/releases/latest)
karşılaştırın:

```bash
logbrew version --json
```

JSON çıktısı `ok`, `name`, `version`, `binary`, `os` ve `arch` alanlarını
verir.

## Giriş yapın ve oturumu doğrulayın

Geçerli terminalin hesabını okuyun:

```bash
logbrew status --json
logbrew whoami --json
```

`whoami` beklediğiniz hesabı gösteriyorsa devam edin. Göstermiyorsa giriş
yapın. Sağlayıcı girişini bir kişi tarayıcıda tamamlar. Bir kodlama asistanı bu
adımı bir kişiden istemelidir.

```bash
logbrew login --provider github
```

Sağlayıcı `github` (varsayılan), `gitlab`, `bitbucket` veya `google` olabilir. Giriş
adresini tarayıcı açmadan yazdırmak için `--no-open` kullanın. `--json` de giriş
yönlendirmesini tarayıcı açmadan yazdırır.

Girişten sonra `status` ve `whoami` komutlarını yeniden çalıştırın. Hesap
kimlik bilgilerini bir prompta, rapora veya kaynak dosyaya yazmayın.

## SDK kurulumunu planlayın

Uygulamanın paket veya derleme manifestini içeren dizine gidin. Monorepo'da
tek bir uygulama veya hizmet seçin. Ardından şunu çalıştırın:

```bash
logbrew setup --json
```

`detected`, `install_ready`, `install_plan` ve `next` alanlarını okuyun. Plan;
çalışma zamanını, framework'ü, paket yöneticisini ve kurulum komutunu verir.
CLI paket kurmaz ve dosya değiştirmez. `logbrew init`, `install`, `configure`
ve `sdk` aynı planı verir.

<Warning>
  SDK yapılandırmasına bir projenin alım anahtarını (ingest key) yazın. Hesap
  kimlik bilgisini asla SDK anahtarı olarak kullanmayın. Alım anahtarlarını
  kaynak kontrolünün dışında tutun.
</Warning>

Çalışma zamanına özel adımlar için [SDK entegrasyonu](/tr/guides/sdk-ingestion)
sayfasına bakın. Sık kullanılan komutların kısa listesi için
`logbrew examples` komutunu çalıştırın.

## Projeleri okuyun, oluşturun ve yapılandırın

Hesabınızdaki etkin projeleri listeleyin:

```bash
logbrew projects --json
```

Sonuçtan bir proje kimliği seçin. Anahtarlar ve okumalar için bu kimliği
kullanın.

Mevcut bir proje için alım anahtarı oluşturmak üzere kaynak kontrolünün
dışında yeni bir dosya seçin. CLI anahtarı yalnızca sahibinin okuyabildiği bu
dosyaya yazar. Anahtarı ve dosya yolunu ekrana yazdırmaz.

```bash
logbrew projects keys create "<project_id>" --ingest-key-file "<private_key_file>" --json
```

| Seçenek | Değer |
| --- | --- |
| `--kind` | `sdk` (varsayılan), `browser`, `server`, `cli` veya `artifact`. `artifact` anahtarı source map'leri ve yerel hata ayıklama dosyalarını yükler. Telemetri gönderemez. |
| `--label` | Anahtar için en fazla 120 karakterlik bir ad. Varsayılan değer `CLI-created SDK key` olur. |

JSON sonucu `status`, `project_id`, `ingest_key`, `checks` ve `next`
alanlarını içerir. `ingest_key`; anahtarın `id`, `label`, `kind`, `created_at`
ve `expires_at` alanlarını içerir. Bir anahtarı değiştirmek için
[Alım anahtarını yenileyin](/tr/guides/rotate-ingest-key) sayfasına bakın.

Bu komut bir kimlik bilgisi oluşturur. Çalıştırmadan önce projenin doğru
olduğundan emin olun. Sonuç belirsizse aynı komutu yeniden çalıştırın. CLI
bekleyen denemeyi yeniden kullanır. `--abandon-retry` seçeneğini yalnızca yeni
bir deneme başlatmak için kullanın.

Yeni bir proje oluşturmak için [hızlı başlangıç](/tr/quickstart) adımlarını
izleyin. Bu adımlar
`logbrew projects create "<name>" --ingest-key-file "<private_key_file>"`
komutunu kullanır. Komut ilk anahtarı aynı şekilde saklar. Proje oluşturma
yardımını okumak için `logbrew setup --create-project` komutunu çalıştırın. Bu
komut proje oluşturmaz.

Bir kurulum adımından sonra bu adımı proje için kaydedebilirsiniz. `--source`
değeri `api`, `cli` veya `sdk` olur:

```bash
logbrew projects setup "<project_id>" --source cli --environment production --json
```

Ardından projenin hazır olup olmadığını okuyun:

```bash
logbrew doctor --project "<project_id>" --json
```

`0` çıkış kodu tüm kontrollerin geçtiği anlamına gelmez. Raporun `status`
alanını ve her kontrolü okuyun. [Doctor raporu
referansına](/tr/reference/cli#read-a-project-doctor-report) bakın.

## Hesap kullanımını okuyun

Kullanımı ve sınırları okuyun. Bu komut hesabı veya faturalandırma durumunu
değiştirmez.

```bash
logbrew usage --json
```

`logbrew account usage --json` aynı sonucu verir. Yanıt; planı, kota
durumunu, sıfırlanma tarihini, proje ve telemetri türüne göre kullanım
toplamlarını ve bir sonraki adımı verir. Alanlar arasında `plan`, `state`,
`reset_at`, `by_project`, `by_stream` ve `next` bulunur.

## Sık yapılan incelemeler

Her okumayı projeye göre filtreleyin. Komut destekliyorsa sürüm, ortam, zaman
veya önem düzeyi filtreleri ekleyin. Bkz. [Filtreler](/tr/reference/cli#filters).

## Canlı olayları izleyin

Bir değişikliği test ederken yeni olayları görmek için watch komutunu
kullanın. Durdurmak için Ctrl+C tuşlarına basın.

```bash
logbrew watch --severity error,critical --json
```

Watch yalnızca JSON akışı verir. `--json` olmadan komut bir hatayla durur.
Tek bir türü izlemek için `logs`, `issues` veya `actions` ekleyin, örneğin
`logbrew watch logs --json`. Watch izleri ve span'leri desteklemez.

Watch komutunda proje, sürüm veya ortam filtresi yoktur. Tek bir proje için
yukarıdaki okumaları kullanın. Desteklenen kaynaklar ve filtreler için
[Canlı izleme](/tr/reference/cli#live-watch) bölümüne bakın.

## Kodu değiştirmeden önce açıklamayı okuyun

Bir düzeltme önermeden önce bağlamı okuyun.

<Steps>
  <Step title="Sorunu okuyun">
    ```bash
    logbrew read issue "<issue_id>" --json
    ```
  </Step>

  <Step title="İzi okuyun">
    Bu adımı yalnızca sorunun bir iz kimliği varsa yapın. İzi olmayan bir sorun
    da geçerlidir.

    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Step>

  <Step title="Açıklamayı okuyun">
    ```bash
    logbrew explain issue "<issue_id>" --json
    ```

    Bir log için `logbrew explain log "<log_id>" --json` kullanın. Bir aksiyon
    için `logbrew explain action "<action_id>" --json` kullanın.
  </Step>

  <Step title="Doğruladıktan sonra çözün">
    ```bash
    logbrew set issue "<issue_id>" resolved --json
    ```

    Birçok sorunun durumunu, önceliğini veya sorumlusunu değiştirmek için
    [Sorun durumunu ve önceliğini değiştirin](/tr/reference/cli#change-issue-status-and-priority)
    bölümüne ve [Sorunları yönetin](/tr/guides/issue-workflow) sayfasına bakın.
  </Step>
</Steps>

## JSON çıktısı

- `--json` seçeneğini komuttan önce veya sonra yazın, örneğin
  `logbrew --json status` veya `logbrew status --json`.
- Çıktıyı kullanmadan önce çıkış kodunu okuyun.
- JSON hataları `ok`, `error`, `message` ve `next` alanlarını içerir. Zaman
  aşımı, bir yazma işleminin başarısız olduğunu kanıtlamaz. Bir yazma işlemini
  tekrarlamadan önce yeniden deneme kurallarını okuyun.
- `--json` olmayan çıktıyla otomasyon yapmayın. Bu çıktı değişebilir.

Çıkış kodları ve hata örnekleri için
[Sonuçları ve hataları okuyun](/tr/reference/cli#read-results-and-errors)
bölümüne bakın.
