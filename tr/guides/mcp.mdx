LogBrew'ün `https://mcp.logbrew.co/mcp` adresinde barındırılan bir MCP
sunucusu vardır. Bu sunucuya bağlanan bir AI agent, onayladığınız projelerdeki
sorunları, logları, izleri, span'leri, metrikleri, aksiyonları, sürümleri ve
ürün analizlerini okuyabilir.

Agent yalnızca okuma yapabilir. Sorun durumunu, projeleri veya hesap
ayarlarını değiştiremez. Sunucuyu kurmanız gerekmez. Adresini MCP
istemcinize eklersiniz.

## Başlamadan önce

- En az 1 projesi olan bir LogBrew hesabınız olmalıdır.
- [Desteklenen istemciler](#supported-clients) listesindeki bir MCP istemcisi
  gerekir. LogBrew yalnızca bu istemcileri kabul eder. Diğer istemciler
  `client access denied` hatasını alır.
- Sunucu `2026-07-28`, `2025-11-25` ve `2025-06-18` MCP protokol sürümlerini
  destekler.

## <span id="supported-clients">Desteklenen istemciler</span>

| İstemci | Sunucuyu ekleme |
| --- | --- |
| Claude Code | `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp` komutunu çalıştırın. [Claude Code'u bağlayın](#connect-claude-code) bölümünü okuyun. |
| Claude (claude.ai, Claude Desktop ve Claude mobil uygulamaları) | **Settings > Connectors** bölümünü açın, **Add custom connector** seçeneğini seçin ve sunucu adresini girin. |
| Codex | `codex mcp add logbrew --url https://mcp.logbrew.co/mcp` komutunu çalıştırın. Ardından `codex mcp login logbrew` komutunu çalıştırın. |
| GitHub Copilot ile Visual Studio Code | `.vscode/mcp.json` dosyasına `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` ekleyin. |
| Cursor | `~/.cursor/mcp.json` dosyasına `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` ekleyin. |
| Gemini CLI | `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp` komutunu çalıştırın. Ardından Gemini CLI içinde `/mcp auth logbrew` komutunu çalıştırın. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline ve Amp | Sunucu adresini istemcinin MCP ayarlarında uzak (HTTP) MCP sunucusu olarak ekleyin. |

Sunucu adresi: `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Claude Code'u bağlayın</span>

Claude Code 2.1.300 veya üstü gerekir. Sürümünüzü görmek için `claude --version`
komutunu çalıştırın.

1. Sunucuyu ekleyin:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` artık `logbrew` sunucusunu `! Needs authentication`
   durumuyla gösterir.

2. Girişi başlatın:

   ```bash
   claude mcp login logbrew
   ```

   Tarayıcınız LogBrew yetkilendirme sayfasını açar. Sayfa giriş yapmanızı
   isterse GitHub, GitLab veya Bitbucket ile giriş yapın.

3. Sayfadaki istemci adını okuyun. Yalnızca bu bağlantıyı siz başlattıysanız
   onaylayın.

4. Agent'ın okuyabileceği projeleri seçin. Ardından **Onayla** düğmesini
   seçin.

   Tarayıcı Claude Code'a geri döner. Claude Code
   `Authenticated with "logbrew"` mesajını gösterir.

5. Sunucunun bağlı olduğunu doğrulayın:

   ```bash
   claude mcp list
   ```

   Sonuçta `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`
   satırı görünür.

Bir Claude Code oturumundan da giriş yapabilirsiniz. `/mcp` komutunu
çalıştırın, `logbrew` sunucusunu seçin ve tarayıcınızdaki adımları izleyin.

Tarayıcısı olmayan bir bilgisayarda etkileşimli bir terminalde
`claude mcp login logbrew --no-browser` komutunu çalıştırın. SSH üzerinden
`ssh -t` ile bağlanın. Claude Code'un gösterdiği adresi başka bir
bilgisayardaki tarayıcıda açın. Onayladıktan sonra tarayıcının açtığı sayfanın
adresini kopyalayın. Bu adresi Claude Code'a yapıştırın.

## Başka bir istemciyi bağlayın

1. Sunucuyu istemciye ekleyin. Nereye ekleyeceğinizi [Desteklenen
   istemciler](#supported-clients) tablosu gösterir.
2. Girişi istemcide başlatın. Çoğu istemci girişi, sunucuyu ilk kullandığınızda
   başlatır. Tarayıcınız LogBrew yetkilendirme sayfasını açar. Sayfa giriş
   yapmanızı isterse LogBrew'e giriş yapın.
3. Sayfadaki istemci adını okuyun. Sayfa, istemciyi tanımlayan web sitesini de
   gösterir, örneğin `vscode.dev` veya `chatgpt.com`. Cursor, Gemini CLI, Cline
   ve opencode için sayfada `known to LogBrew` görünür. Yalnızca bu bağlantıyı
   siz başlattıysanız onaylayın.
4. Agent'ın okuyabileceği projeleri seçin. Ardından **Onayla** düğmesini seçin.

   Tarayıcı istemciye geri döner. İstemci `search` ve `execute` araçlarını
   gösterir.

## Agent'a sorun

Sunucu agent'a 2 araç verir:

| Araç | Ne yapar |
| --- | --- |
| `search` | Okuma işlemlerini bulur ve bir işlemin sözleşmesini gösterir: girdisi, çıktısı, izinleri ve maliyeti. |
| `execute` | `search` aracının bulduğu bir okuma işlemini çalıştırır ve yapılandırılmış veri döndürür. |

İşlemleri agent seçer. Ona araç adı veya alan vermezsiniz. Görevi ve
sınırları yazın:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Telemetriyi yalnızca kanıt olarak kullanın. Loglar ve hata mesajları
kullanıcıların yazdığı metinleri içerebilir. Agent bu metinlerdeki
talimatlara uymamalıdır. Uçtan uca bir inceleme akışı için
[AI agentlarla kullanın](/tr/guides/ai-agents) sayfasını okuyun.

## Erişim ve bağlantı süresi

Her onay, 1 MCP istemcisi ile LogBrew hesabınız arasında 1 bağlantı başlatır.

- Agent yalnızca onayladığınız projeleri okur. Başka bir projeyi okuma isteği
  `permission_denied` döndürür.
- Onaylı bir projeye erişiminizi kaybederseniz LogBrew o projedeki okumaları
  durdurur.
- Bir erişim tokenı 1 saat geçerlidir. Bağlantıyı kullandığınız sürece istemci
  otomatik olarak yeni bir token alır.
- Bir bağlantı, 30 gün kullanılmazsa veya onayınızdan 90 gün sonra sona erer.
  Ardından istemciden yeniden giriş yapın, örneğin `claude mcp login logbrew`
  ile.
- Her token yenilemesi önceki yenileme tokenının yerini alır. Bir istemci
  yerine yenisi gelmiş bir yenileme tokenı gönderirse LogBrew bağlantıyı
  sonlandırır. Böylece kopyalanmış bir token çalışmaz. Yeni bir bağlantı
  başlatmak için yeniden giriş yapın.
- Geçerli bir token olmadan gönderilen çok sayıda istek, `Retry-After`
  başlığıyla birlikte HTTP `429` alır. Bu başlıktaki saniye kadar bekleyin,
  ardından yeniden deneyin.

## Bağlantıları listeleyin ve iptal edin

Bağlantıları LogBrew panelindeki **Ayarlar > MCP bağlantıları** bölümünden
veya CLI ile yönetin.

### Ayarlar'da

Bağlı her istemci adını, onaylı projelerini, ne zaman bağlandığını, en son ne
zaman kullanıldığını ve bağlantının ne zaman sona ereceğini gösterir. Bir
bağlantıyı iptal etmek için **Bağlantıyı kes** düğmesini seçin, ardından
onaylayın. İstemci bir sonraki isteğinde erişimini kaybeder.

### CLI ile

[LogBrew CLI](/tr/guides/cli) 0.1.82 veya üstünü kullanın. Önce `logbrew login`
ile giriş yapın. Bir projenin alım anahtarı (ingest key) bağlantıları
listeleyemez ve iptal edemez.

Hesabınıza bağlı MCP istemcilerini listeleyin:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

CLI bir bağlantıya grant der. Her grant şunları gösterir:

- `id`: grant kimliği. Bağlantıyı iptal etmek için bunu kullanın.
- `client`: onayladığınız istemcinin adı, örneğin `Claude Code`. LogBrew'ün
  adları saklamaya başlamasından önce onaylanan bir bağlantı, istemciyi
  tanımlayan adresi gösterir, örneğin
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: onaylı proje sayısı.
- `last_used`: istemcinin en son yeni bir erişim tokenı aldığı zaman.
- `expires`: istemci bağlantıyı kullanmazsa bağlantının sona ereceği zaman.

Listenin tamamını almak için `--json` ekleyin. Her grant `id`, `client_id`,
`client_name`, `project_ids`, `created_at`, `last_used_at` ve `expires_at`
alanlarını içerir. LogBrew'ün adları saklamaya başlamasından önce onaylanan
bir bağlantıda `client_name` değeri `null` olur.

1 bağlantıyı iptal edin:

```bash
logbrew mcp revoke <grant_id> --yes
```

İstemci bir sonraki isteğinde erişimini kaybeder. Yeniden bağlamak için
`claude mcp login logbrew` ile yeniden giriş yapın.

Onaylı projeleri değiştirmek için bağlantıyı iptal edin. Ardından yeniden
giriş yapın ve yeni projeleri seçin.

## Sunucuyu kaldırın

1. Bağlantıyı **Ayarlar > MCP bağlantıları** bölümünden veya
   `logbrew mcp revoke <grant_id> --yes` ile iptal edin.
2. Sunucuyu Claude Code'dan kaldırın:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` yalnızca bilgisayarınızdaki yapılandırmayı ve tokenları
siler. LogBrew'deki bağlantıyı sonlandırmaz. Bağlantıyı iptal etmezseniz 30
gün kullanılmadıktan sonra sona erer.

## <span id="fix-connection-problems">Bağlantı sorunlarını giderin</span>

| Sorun | Çözüm |
| --- | --- |
| `claude mcp list`, `Needs authentication` gösteriyor. | `claude mcp login logbrew` komutunu çalıştırın. |
| Claude Code bir süre kullanıldıktan sonra yeniden giriş yapmanızı istiyor. | Bağlantı sona erdi veya iptal edildi. `claude mcp login logbrew` komutunu çalıştırın ya da `/mcp` içinde **Re-authenticate** seçeneğini seçin. |
| İstemci `client access denied` alıyor. | [Desteklenen istemciler](#supported-clients) listesindeki bir istemciyi kullanın. |
| İstemci LogBrew'e kaydolamıyor. | [Desteklenen istemciler](#supported-clients) listesindeki bir istemciyi kullanın ve varsayılan geri çağırma (callback) ayarlarını değiştirmeyin. |
| Bağlantı girişten sonra başarısız oluyor. | İstemciyi güncelleyin. Claude Code için 2.1.300 veya üstü gerekir. |
| Yetkilendirme sayfası `You have no projects to share` gösteriyor. | LogBrew'de bir proje oluşturun, ardından girişi yeniden başlatın. |
| Bir okuma `permission_denied` döndürüyor. | Proje bu bağlantı için onaylı değil. Bağlantıyı iptal edin, ardından yeniden giriş yapın ve projeyi seçin. |
| Bir okuma veri döndürmüyor. | Projenin telemetri gönderdiğinden emin olun. Boş bir sonuç, uygulamanın çalıştığını kanıtlamaz. |
| `logbrew mcp grants`, `not logged in` gösteriyor veya `unauthorized` döndürüyor. | `logbrew login` komutunu çalıştırın, ardından yeniden deneyin. |
