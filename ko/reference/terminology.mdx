LogBrew는 제품 개념마다 용어를 하나만 씁니다. API 필드, CLI 플래그, enum 값, 이벤트 이름, 속성 키는 모든 언어에서 그대로 유지됩니다.

## 옵저버빌리티와 모니터링

| 용어 | 의미 |
| --- | --- |
| 옵저버빌리티 | 애플리케이션이 만드는 근거로 애플리케이션의 동작을 이해하는 것입니다. |
| 텔레메트리 | 애플리케이션이 보고하는 시그널입니다. 로그, 트레이스, 메트릭이 그 예입니다. |
| 모니터링 | 측정값을 임곗값과 비교하는 것처럼, 이미 알고 있는 조건을 확인하는 것입니다. |
| `o11y` | observability의 줄임말입니다. 숫자는 `o`와 `y` 사이에 있는 글자 11개를 뜻합니다. |

시그널 선택과 실제 예시는 [텔레메트리](/ko/concepts/telemetry)를 읽으세요.

## AI 에이전트

| 용어 | 의미 |
| --- | --- |
| MCP 서버 | Model Context Protocol을 위한 LogBrew 호스팅 서버입니다. AI 에이전트는 이 서버로 승인된 프로젝트를 읽습니다. |
| MCP 클라이언트 | AI 에이전트를 MCP 서버에 연결하는 애플리케이션입니다. Claude Code가 그 예입니다. |
| 승인된 프로젝트 | MCP 클라이언트에 접근 권한을 줄 때 선택한 프로젝트입니다. 클라이언트는 승인된 프로젝트만 읽을 수 있습니다. |
| 연결 | MCP 클라이언트 1개를 승인할 때 그 클라이언트에 주는 접근 권한입니다. 30일 동안 사용하지 않거나, 90일이 지나거나, 해지하면 끝납니다. CLI에서는 grant라고 부릅니다. |

클라이언트를 연결하려면 [MCP로 AI 에이전트 연결하기](/ko/guides/mcp)를 읽으세요.

## 옵저버빌리티 시그널

<AccordionGroup>
  <Accordion title="이슈">
    여러 발생 건을 포함할 수 있는, 그룹으로 묶인 문제입니다. 발생 건은 그 이슈가 수집된 사례 1개입니다. `first_seen_at`은 첫 발생 건의 시각입니다. `last_seen_at`은 가장 최근 발생 건의 시각입니다.
  </Accordion>

  <Accordion title="로그">
    타임스탬프가 있는 이벤트 기록 1개입니다. 로그에는 심각도, 서비스, 릴리스, 환경, 트레이스 컨텍스트, 개인정보 보호 범위 안의 속성이 담길 수 있습니다.
  </Accordion>

  <Accordion title="트레이스와 스팬">
    트레이스는 요청이나 작업 전체에 걸친 처리 과정을 따라갑니다. 스팬은 그 트레이스 안에서 시간을 잰 작업 1개입니다. 트레이스와의 연관 관계는 컨텍스트를 공유한다는 근거일 뿐, 원인의 증명은 아닙니다.
  </Accordion>

  <Accordion title="메트릭">
    단위, 유형, 집계, 기간이 정해진 런타임 측정값입니다. 메트릭 포인트는 로그, 트레이스, 이슈 개수와 서로 바꿔 쓸 수 없습니다.
  </Accordion>

  <Accordion title="릴리스">
    텔레메트리와 함께 보고된, 배포된 애플리케이션 또는 서비스 버전입니다. 릴리스는 프로젝트나 저장소와 같은 대상이 아닙니다.
  </Accordion>

  <Accordion title="액션">
    가입, 결제, 가져오기, 실패한 작업처럼 분류된 제품 이벤트입니다. 분석에서는 액션을 페이지 조회, 화면 조회, 상호작용 중 하나로 분류합니다. 액션은 LogBrew가 실행하는 자동 명령이 아닙니다.
  </Accordion>
</AccordionGroup>

## 이슈 조사

모든 발생 건에 모든 필드가 들어 있지는 않습니다.

| 용어 | 의미 |
| --- | --- |
| 심각도 | 시그널의 긴급도입니다. `info`, `warning`, `error`, `critical` 중 하나입니다. 이슈 상태와는 별개입니다. |
| 이슈 상태 | 그룹으로 묶인 이슈의 워크플로 상태입니다. `unresolved`, `resolved`, `archived` 중 하나입니다. 요청 1건의 결과가 아닙니다. |
| 보관된 이슈 | 팀이 활성 트리아지에서 뺀 이슈입니다. 이전 응답에서는 이 상태를 `ignored`라고 부릅니다. |
| 이슈 우선순위 | 그룹으로 묶인 이슈의 트리아지 순서입니다. `high`, `medium`, `low` 중 하나입니다. 사람이 설정하기 전까지는 심각도를 따릅니다. |
| 우선순위 출처 | 우선순위가 어디에서 왔는지 나타냅니다. `derived`는 심각도를 따릅니다. `error`와 `critical`은 `high`, `warning`은 `medium`, `info`는 `low`입니다. `manual`은 사람이 설정한 우선순위입니다. |
| 이슈 담당자 | 그룹으로 묶인 이슈의 다음 단계를 맡은 계정 1개 또는 팀 1개입니다. 계정은 프로젝트를 읽을 수 있어야 하고, 팀은 프로젝트가 속한 조직의 팀이어야 합니다. |
| 팀 | 조직 안에서 이름을 붙인 멤버 그룹입니다. 이슈를 팀에 할당할 수 있고, 소유권 규칙에서 팀을 지정할 수 있습니다. 팀에 속한다고 프로젝트 접근 권한이 생기지는 않습니다. |
| 소유권 규칙 | 스택 프레임 경로, 모듈, 라우트, 서비스, 태그를 기준으로 일치하는 이슈의 소유자인 계정이나 팀을 정하는 프로젝트 규칙입니다. |
| 추천 소유자 | LogBrew가 이슈에 추천하는 계정이나 팀입니다. 소유권 규칙, CODEOWNERS의 줄, 최근 활동을 근거로 합니다. 추천일 뿐 할당은 아닙니다. |
| 수신함 | 다른 사람이 나나 내 팀에 할당한 이슈 목록입니다. LogBrew는 이 목록에 대해 이메일을 보내지 않습니다. |
| 스택 트레이스 | 오류가 났을 때 수집된 함수 호출 근거입니다. 분산 트레이스와는 다릅니다. |
| 스택 프레임 | 스택 트레이스의 항목 1개입니다. 함수, 모듈, 파일, 줄, 열을 가리킬 수 있습니다. |
| 예외 체인 | 오류와 그 원인처럼 함께 보고된, 서로 연결된 예외입니다. 항목이 누락되거나 가려지거나 잘리면 근거가 제한됩니다. |
| 애플리케이션 프레임 | 애플리케이션 코드로 표시된 스택 프레임입니다. 살펴볼 코드를 보여 줍니다. 결함을 증명하지는 않습니다. |
| 브레드크럼 | 이슈가 발생하기 전에 기록된 짧은 이벤트입니다. 브레드크럼은 세션을 빠짐없이 기록한 것이 아닙니다. |
| 처리된 예외 | 애플리케이션이 처리했다고 보고한 예외입니다. 작업이 성공했다는 증명은 아닙니다. |
| 소스맵 | 생성된 JavaScript 위치를 원본 소스 위치에 연결하는 빌드 아티팩트입니다. |
| 심볼리케이션된 프레임 | 생성된 위치를 원본 소스 정보로 되돌린 프레임입니다. |
| 기준 발생 건 | 재현의 기준으로 쓰는, 수집된 발생 건입니다. |
| 출처 | 평가가 어디에서 왔는지 나타냅니다. `backend_observed`는 LogBrew가 관측했다는 뜻입니다. `application_reported`는 앱이 보고했고 LogBrew가 검증하지 않았다는 뜻입니다. |
| 재현 준비 상태 | 기준 발생 건에 재현을 시도할 근거가 있는지 나타냅니다. 재현 테스트를 통과했다는 뜻은 아닙니다. |

읽는 순서와 응답 필드는 [이슈 조사하기](/ko/guides/investigate-an-issue)를 참고하세요.

## 식별 정보와 연관 관계

값이 없다고 해서 관련 활동이 일어나지 않았다는 증명은 아닙니다.

| 용어 | 의미 |
| --- | --- |
| 트레이스 컨텍스트 | 여러 시그널에 걸친 처리를 연결하는 트레이스 ID와 스팬 ID입니다. |
| 루트 스팬 | 트레이스를 시작하며 부모 스팬이 없는 스팬입니다. 반환된 스팬 중 가장 이른 스팬이 꼭 루트인 것은 아닙니다. |
| 자식 스팬 | 같은 트레이스 안에 부모 스팬이 있는 스팬입니다. |
| 연관 관계 | 공유 트레이스 ID처럼 LogBrew가 반환하는 정확한 관계입니다. 원인을 증명하지 않습니다. |
| 식별된 사용자 | 앱이 제공한 주체 중 고정 ID가 있고 종류가 `user`인 주체입니다. |
| 익명 주체 | 앱이 제공한 주체 중 종류가 `anonymous`인 주체입니다. 개수를 셀 때 식별된 사용자와 따로 셉니다. |
| 알 수 없는 식별 종류 | 종류를 알 수 없는 주체입니다. 식별된 사용자로 세지 않습니다. |
| 주체 없음 | 주체가 없는 이벤트입니다. 종류를 알 수 없는 주체와는 다릅니다. |

식별 종류는 앱이 주체를 어떻게 분류했는지 보여 줍니다. 데이터가 익명이라는 증명은 아닙니다. 고정 ID로도 활동이 연결될 수 있습니다.

## 범위와 데이터 품질

| 용어 | 의미 |
| --- | --- |
| 프로젝트 | 소유한 제품의 기본 경계입니다. 프로젝트 1개에 여러 서비스나 저장소 구성 요소가 들어갈 수 있습니다. |
| 서비스 | 프로젝트 안에서 데이터를 보고하는 런타임이나 구성 요소입니다. |
| 환경 | 프로덕션이나 스테이징처럼 데이터를 보고하는 정확한 컨텍스트입니다. |
| 수집 접수됨 | 수집 계약에 따라 접수되었습니다. 무기한 보존을 약속하지 않습니다. |
| 인덱싱됨 | 지정된 인덱스나 쿼리에서 사용할 수 있습니다. 수집 접수됨과 같은 뜻이 아닙니다. |
| 보존됨 | 평가한 데이터 기간 안에 있습니다. |
| 샘플링됨 | 수집 전이나 수집 중에 일부 텔레메트리가 선택되었습니다. |
| 커버리지 | 분자와 분모를 명시해 측정한 비율입니다. |
| 잘림 | 응답이 한도에 도달했습니다. 빠진 데이터가 꼭 없는 데이터는 아닙니다. |
| 근사치 | 정확히 센 값이 아니라, 문서에 나온 방법으로 추정한 값입니다. |
| 기간 | 쿼리가 평가하는 정확한 시간 범위입니다. |

## 요금제와 조직

| 용어 | 의미 |
| --- | --- |
| 요금제 | 월별 허용치와 보존 기간이 정해진 묶음입니다. 요금제는 Free, Pro, Business, Enterprise입니다. |
| 허용치 | 요금제가 청구 월 1개월에 포함하는 텔레메트리 한 종류의 양입니다. 예를 들면 로그 바이트나 트레이스 스팬입니다. |
| 베타 혜택 | 공개 베타 기간에 계정이 6개월 동안 무료로 받는 Pro 허용치입니다. 이후에는 계정 자체 요금제를 사용합니다. |
| 조직 | 멤버, 팀, 프로젝트가 함께 쓰는 공간입니다. 모든 요금제에 조직이 있고 멤버 수와 프로젝트 수에는 제한이 없습니다. |

요금제별 허용치는 [계정 API](/ko/reference/account-api) 문서에서 확인하세요.

## 측정값과 시간

| 용어 | 의미 |
| --- | --- |
| 데이터 포인트 | 보고된 시각의 값 1개입니다. 데이터 포인트를 비교하기 전에 메트릭 이름과 단위를 확인하세요. |
| 시계열 | 같은 측정값을 시간순으로 정렬한 값입니다. 값이 비어 있다고 해서 0이었다는 뜻은 아닙니다. |
| 소요 시간 | 작업에 걸린 시간입니다. 작업이 일어난 시각과는 다릅니다. |
| 집계 | 합계나 평균처럼 여러 측정값에 대해 정해진 계산입니다. |
| 시간 구간 | 차트나 그룹으로 묶인 결과의 구간 1개입니다. 시작과 끝이 범위를 정합니다. |
| 미완료 기간 | 아직 끝나지 않은 기간입니다. 활동이 0인, 끝난 기간이 아닙니다. |

전체 요청 시간을 구하려고 겹치는 자식 스팬의 소요 시간을 더하지 마세요. 이벤트 수를 식별된 사용자 수와 비교하지 마세요.

## 근거 상태

다음 상태는 서로 바꿔 쓸 수 없습니다.

- **수집됨:** 근거가 있습니다.
- **수집 안 됨:** 근거가 수집되지 않았습니다.
- **가려짐:** 근거를 의도적으로 가렸습니다.
- **잘림:** 근거가 응답 또는 수집 한도를 넘었습니다.
- **사용할 수 없음:** 조회에서 근거를 가져올 수 없었습니다.

`Likely cause`(추정 원인)와 `likely fix area`(추정 수정 위치)는 범위가 제한된 진단 근거를 설명합니다. 증명된 근본 원인이 아닙니다. 계약에 LogBrew 측정값이라고 명시되어 있지 않으면 `Reported impact`(보고된 영향)는 보고하는 애플리케이션이 제공한 값입니다.

## 제품 분석

| 용어 | 의미 |
| --- | --- |
| 이벤트 | 정확하고 고정된 이름이 있는, 분류된 제품 활동입니다. |
| 속성 | 이벤트를 설명하거나 필터링할 때 쓰는 컨텍스트 키입니다. |
| 세션 | 방문 또는 앱 세션입니다. 사람이 아닙니다. |
| 코호트 | 정확한 기준으로 정한, 범위가 있는 그룹입니다. |
| 퍼널 | 진행이나 전환을 측정할 때 쓰는 순서가 있는 단계입니다. |
| 재방문 | 명시한 기간과 분모로 측정한 재방문 행동입니다. |
| 경로 | 선택한 이벤트 전이나 후의 세션 이동 경로입니다. |
| 라이프사이클 | 기간마다 식별된 주체를 관측 기록 내 신규, 계속 활동, 복귀, 휴면으로 나눕니다. |
| 관측 기록 내 신규 | 범위가 정해진 이력 기간 안에 선택한 이벤트가 이전에 없었고 지금 활동 중인 상태입니다. 처음 온 고객이라는 뜻은 아닙니다. |

미완료 기간, 누락된 식별 정보, 불완전한 속성 수집, 샘플링, 잘림은 결과에 단서를 붙입니다. LogBrew는 이런 한계를 0이나 확실한 값으로 바꾸지 않고 그대로 보여 줍니다.

개수를 세는 규칙은 [제품 분석](/ko/concepts/product-analytics)을 읽으세요. 분류된 활동과 타입이 있는 식별 정보를 보내려면 [제품 이벤트 수집](/ko/guides/product-events)을 사용하세요.
