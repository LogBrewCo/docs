LogBrew vận hành một máy chủ MCP tại `https://mcp.logbrew.co/mcp`. Agent AI
kết nối với máy chủ này có thể đọc vấn đề, log, trace, span, chỉ số, hành động,
bản phát hành và dữ liệu phân tích sản phẩm từ các dự án bạn đã duyệt.

Agent chỉ có quyền đọc, trừ khi bạn cho phép cả thay đổi. Khi được phép thay
đổi, agent có thể xử lý vấn đề và thiết lập dự án. Agent không thể thay đổi
thanh toán, thành viên hay cài đặt tài khoản. Bạn không cần cài đặt máy chủ. Thêm URL của máy chủ vào MCP
client (ứng dụng kết nối agent AI với máy chủ MCP) của bạn.

## Trước khi bắt đầu

- Bạn cần một tài khoản LogBrew có ít nhất 1 dự án.
- Bạn cần một MCP client có thể kết nối với máy chủ MCP từ xa (HTTP). Mọi
  client tuân theo chuẩn cấp quyền của MCP đều đăng nhập được. Client không hỗ
  trợ OAuth có thể dùng khóa đọc dữ liệu của dự án. Đọc
  [Kết nối bằng khóa đọc dữ liệu](#connect-with-a-read-key).
- Máy chủ hỗ trợ các phiên bản giao thức MCP `2026-07-28`, `2025-11-25` và
  `2025-06-18`.

## <span id="supported-clients">Client được hỗ trợ</span>

LogBrew chấp nhận mọi MCP client tự nhận diện bằng tài liệu metadata của client
hoặc tự đăng ký. Bảng này hướng dẫn thiết lập cho các client phổ biến.

| Client | Cách thêm máy chủ |
| --- | --- |
| Claude Code | Chạy `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Xem [Kết nối Claude Code](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop và ứng dụng Claude trên di động) | Mở **Settings > Connectors**, chọn **Add custom connector** rồi nhập URL của máy chủ. |
| Codex | Chạy `codex mcp add logbrew --url https://mcp.logbrew.co/mcp`. Sau đó chạy `codex mcp login logbrew`. |
| Visual Studio Code với GitHub Copilot | Thêm `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` vào `.vscode/mcp.json`. |
| Cursor | Thêm `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` vào `~/.cursor/mcp.json`. |
| Gemini CLI | Chạy `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Sau đó chạy `/mcp auth logbrew` trong Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp và các client khác | Thêm URL của máy chủ dưới dạng máy chủ MCP từ xa (HTTP) trong phần cài đặt MCP của client. |

URL của máy chủ là `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Kết nối Claude Code</span>

Bạn cần Claude Code 2.1.300 trở lên. Chạy `claude --version` để xem phiên bản
của bạn.

1. Thêm máy chủ:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   Lúc này `claude mcp list` hiển thị `logbrew` với `! Needs authentication`.

2. Bắt đầu đăng nhập:

   ```bash
   claude mcp login logbrew
   ```

   Trình duyệt mở trang cấp quyền của LogBrew. Nếu trang yêu cầu đăng nhập,
   đăng nhập bằng GitHub, GitLab, Bitbucket hoặc Google.

3. Đọc tên client trên trang. Chỉ duyệt nếu chính bạn đã bắt đầu kết nối này.

4. Chọn các dự án mà agent được đọc. Nếu trang hiển thị một dòng cho phép thay
   đổi, chỉ chọn dòng đó khi agent cần thay đổi dữ liệu. Sau đó chọn **Duyệt**.

   Trình duyệt quay lại Claude Code. Claude Code hiển thị
   `Authenticated with "logbrew"`.

5. Kiểm tra rằng máy chủ đã kết nối:

   ```bash
   claude mcp list
   ```

   Kết quả hiển thị `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Bạn cũng có thể đăng nhập từ một phiên Claude Code. Chạy `/mcp`, chọn
`logbrew` và làm theo các bước trong trình duyệt.

Trên máy tính không có trình duyệt, chạy
`claude mcp login logbrew --no-browser` trong một terminal tương tác. Qua SSH,
kết nối bằng `ssh -t`. Mở URL mà Claude Code hiển thị bằng trình duyệt trên một
máy tính khác. Sau khi duyệt, sao chép địa chỉ của trang mà trình duyệt mở ra.
Dán địa chỉ đó vào Claude Code.

## Kết nối client khác

1. Thêm máy chủ vào client. Bảng trong [Client được hỗ trợ](#supported-clients)
   cho biết cần thêm ở đâu.
2. Bắt đầu đăng nhập trong client. Hầu hết client tự bắt đầu khi bạn dùng máy
   chủ lần đầu. Trình duyệt mở trang cấp quyền của LogBrew. Nếu trang yêu cầu
   đăng nhập, đăng nhập vào LogBrew.
3. Đọc tên client trên trang. Trang cũng hiển thị địa chỉ dùng để nhận diện
   client, ví dụ `vscode.dev` hoặc `chatgpt.com`. Với client nhận kết quả duyệt
   ngay trên máy tính của bạn, trang hiển thị **ứng dụng cục bộ**. Nếu LogBrew
   chưa xác minh tên client, trang sẽ yêu cầu bạn kiểm tra địa chỉ. Chỉ duyệt
   nếu chính bạn đã bắt đầu kết nối này.
4. Chọn các dự án mà agent được đọc. Nếu trang hiển thị một dòng cho phép thay
   đổi, chỉ chọn dòng đó khi agent cần thay đổi dữ liệu. Sau đó chọn **Duyệt**.

   Trình duyệt quay lại client, và client hiển thị các công cụ `search` và
   `execute`.

## <span id="connect-with-a-read-key">Kết nối bằng khóa đọc dữ liệu</span>

Dùng khóa đọc dữ liệu của dự án khi client không đăng nhập được bằng OAuth.
Khóa này đọc 1 dự án. Khóa không thể thay đổi dữ liệu.

1. Tạo một khóa đọc dữ liệu cho dự án. Làm theo
   [Kiểm tra thiết lập](/vi/guides/verify-setup).
2. Thêm URL của máy chủ vào client.
3. Trong cài đặt của client, thêm header `Authorization: Bearer <read_key>`.
   Thay `<read_key>` bằng khóa của bạn.

Giữ bí mật khóa như một mật khẩu. Kết nối dùng khóa đọc dữ liệu không hiển thị
trong **Cài đặt > Kết nối MCP**. Để kết thúc kết nối, hãy thu hồi khóa.

## Giao việc cho agent

Máy chủ cung cấp cho agent 2 công cụ:

| Công cụ | Chức năng |
| --- | --- |
| `search` | Tìm các thao tác và hiển thị đặc tả của một thao tác: đầu vào, đầu ra, quyền và chi phí. |
| `execute` | Chạy một thao tác mà `search` đã tìm thấy và trả về dữ liệu có cấu trúc. |

Để thử kết nối, hãy hỏi:

```text
List my LogBrew projects.
```

Agent liệt kê các dự án mà kết nối được đọc.

Agent tự chọn thao tác. Bạn không cần đưa cho agent tên công cụ hay tên trường.
Viết nhiệm vụ và các giới hạn:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Chỉ dùng telemetry làm bằng chứng. Log và thông điệp lỗi có thể chứa văn bản từ
người dùng. Agent không được làm theo chỉ dẫn trong văn bản đó. Đọc
[Agent lập trình AI](/vi/guides/ai-agents) để xem quy trình điều tra đầy đủ.

## Cho phép thay đổi

Mọi kết nối đều có scope `read`. Để thay đổi dữ liệu, kết nối cần thêm scope
`write`. Khi client yêu cầu `write`, trang cấp quyền hiển thị scope này trên một
dòng riêng: **Cho phép ứng dụng thay đổi cả dữ liệu trong các dự án đã chọn và
tạo dự án mới**. Dòng này không được chọn sẵn. Nếu bạn không chọn, kết nối chỉ
đọc được.

Với `write`, agent có thể:

- Đánh dấu đã giải quyết, mở lại và lưu trữ vấn đề.
- Đặt mức ưu tiên của một vấn đề.
- Giao vấn đề cho người xử lý và bỏ giao.
- Tạo dự án.
- Tạo và thu hồi khóa dự án.
- Gửi một sự kiện thử đến dự án.
- Tải và xóa dữ liệu mẫu.

Agent hành động thay bạn, với quyền của bạn trên dự án. LogBrew ghi lại mỗi
thay đổi cùng tên của ứng dụng đã thực hiện thay đổi đó.
[Tài liệu tham chiếu thao tác](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
liệt kê từng thao tác và đầu vào của nó.

Các thao tác sau không thay đổi gì ở lần gọi đầu tiên:

- `issues.archive.v1` lưu trữ một vấn đề.
- `projects.keys.revoke.v1` thu hồi một khóa.
- `projects.sample_data.remove.v1` xóa dữ liệu mẫu.

Lần gọi đầu tiên trả về một mã xác nhận. Agent cho bạn thấy những gì sẽ thay
đổi. Để thực hiện thay đổi, agent gửi lại đúng lần gọi đó kèm mã xác nhận trong
vòng 5 phút.

Nếu không có `write`, một thay đổi sẽ trả về HTTP `403` kèm `insufficient_scope`.
Khi đó, một số client mở lại trang cấp quyền. Chọn dòng cho phép thay đổi để cấp
`write` cho kết nối.

## Quyền truy cập và thời hạn kết nối

Mỗi lần duyệt tạo 1 kết nối giữa 1 MCP client và tài khoản LogBrew của bạn.

- Agent chỉ đọc và thay đổi các dự án bạn đã duyệt. Một lần gọi vào dự án khác
  sẽ trả về `permission_denied`. Dự án do agent tạo sẽ được thêm vào các dự án
  đã duyệt.
- Nếu bạn mất quyền truy cập một dự án đã duyệt, LogBrew dừng các lần gọi vào
  dự án đó.
- Token truy cập có hiệu lực trong 1 giờ. Client tự động lấy token mới khi bạn
  dùng kết nối.
- Token truy cập mới có thể mất `write`, nhưng không bao giờ có thêm `write`.
  Để thêm `write`, hãy duyệt lại kết nối.
- Kết nối kết thúc sau 30 ngày không dùng, hoặc 90 ngày sau khi bạn duyệt. Khi
  đó, đăng nhập lại từ client, ví dụ bằng `claude mcp login logbrew`.
- Mỗi lần làm mới token sẽ thay thế refresh token trước đó. Nếu client gửi một
  refresh token đã bị thay thế, LogBrew kết thúc kết nối. Cơ chế này ngăn token
  bị sao chép tiếp tục hoạt động. Đăng nhập lại để bắt đầu kết nối mới.
- Quá nhiều yêu cầu không có token hợp lệ sẽ nhận HTTP `429` kèm header
  `Retry-After`. Chờ đúng số giây đó rồi thử lại.

## Liệt kê và thu hồi kết nối

Quản lý kết nối trong **Cài đặt > Kết nối MCP** trên bảng điều khiển LogBrew,
hoặc bằng CLI.

### Trong Cài đặt

Mỗi client đã kết nối hiển thị tên, các dự án đã duyệt, thời điểm kết nối, lần
dùng gần nhất và thời điểm kết nối kết thúc. Để thu hồi một kết nối, chọn
**Ngắt kết nối**, rồi xác nhận. Client mất quyền truy cập ở yêu cầu tiếp theo.

### Bằng CLI

Dùng [LogBrew CLI](/vi/guides/cli) 0.1.82 trở lên. Trước tiên, đăng nhập bằng
`logbrew login`. Khóa gửi dữ liệu của dự án không thể liệt kê hay thu hồi kết
nối.

Liệt kê các MCP client đang kết nối với tài khoản của bạn:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

CLI gọi kết nối là grant. Mỗi grant hiển thị:

- `id`: ID của grant. Dùng ID này để thu hồi kết nối.
- `client`: tên client bạn đã duyệt, chẳng hạn `Claude Code`. Kết nối được
  duyệt trước khi LogBrew lưu tên sẽ hiển thị URL định danh client, chẳng hạn
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: số dự án đã duyệt.
- `last_used`: lần gần nhất client lấy token truy cập mới.
- `expires`: thời điểm kết nối kết thúc nếu client không dùng nó.

Thêm `--json` để lấy danh sách đầy đủ. Mỗi grant có `id`, `client_id`,
`client_name`, `project_ids`, `created_at`, `last_used_at` và `expires_at`.
`client_name` là `null` với kết nối được duyệt trước khi LogBrew lưu tên.

Thu hồi 1 kết nối:

```bash
logbrew mcp revoke <grant_id> --yes
```

Client mất quyền truy cập ở yêu cầu tiếp theo. Để kết nối lại, đăng nhập lại
bằng `claude mcp login logbrew`.

Để thay đổi các dự án đã duyệt, thu hồi kết nối. Sau đó đăng nhập lại và chọn
các dự án mới.

## Gỡ máy chủ

1. Thu hồi kết nối trong **Cài đặt > Kết nối MCP**, hoặc bằng
   `logbrew mcp revoke <grant_id> --yes`.
2. Gỡ máy chủ khỏi Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` chỉ xóa cấu hình và token trên máy tính của bạn. Lệnh này
không kết thúc kết nối trong LogBrew. Nếu bạn không thu hồi, kết nối sẽ kết
thúc sau 30 ngày không dùng.

## <span id="fix-connection-problems">Khắc phục sự cố kết nối</span>

| Sự cố | Cách khắc phục |
| --- | --- |
| `claude mcp list` hiển thị `Needs authentication`. | Chạy `claude mcp login logbrew`. |
| Claude Code yêu cầu đăng nhập lại sau một thời gian sử dụng. | Kết nối đã kết thúc hoặc đã bị thu hồi. Chạy `claude mcp login logbrew`, hoặc chọn **Re-authenticate** trong `/mcp`. |
| Trang hiển thị **LogBrew đã chặn ứng dụng này.** | LogBrew không chấp nhận client này. Dùng một client khác. |
| Client không đăng ký được với LogBrew. | Giữ nguyên cài đặt callback mặc định của client. LogBrew chỉ chấp nhận địa chỉ callback HTTPS và địa chỉ `http` trên chính máy tính của bạn. |
| Kết nối thất bại sau khi đăng nhập. | Cập nhật client. Claude Code cần phiên bản 2.1.300 trở lên. |
| Trang cấp quyền hiển thị `You have no projects to share`. | Tạo một dự án trong LogBrew, rồi bắt đầu đăng nhập lại. |
| Một lần gọi trả về `permission_denied`. | Dự án chưa được duyệt cho kết nối này. Thu hồi kết nối, rồi đăng nhập lại và chọn dự án đó. |
| Một thay đổi trả về `insufficient_scope`. | Kết nối không được phép thay đổi dữ liệu. Yêu cầu agent thử lại. Nếu client mở trang cấp quyền, chọn dòng cho phép thay đổi. |
| Một thao tác đọc không trả về dữ liệu. | Kiểm tra rằng dự án có gửi telemetry. Kết quả trống không chứng minh ứng dụng hoạt động bình thường. |
| `logbrew mcp grants` hiển thị `not logged in` hoặc trả về `unauthorized`. | Chạy `logbrew login`, rồi thử lại. |
