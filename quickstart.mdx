---
title: "Quickstart"
description: "Log in with the LogBrew CLI, set up SDK ingestion, and read logs, issues, actions, traces, and releases as JSON."
---

This quickstart gives you the shortest useful path: log in, prepare SDK setup,
send telemetry with a release, and read it back from the CLI.

Telemetry is the structured data your app sends to LogBrew, such as logs, trace
spans, issues, actions, releases, and environments.

<Note>
  Use `--json` whenever an AI coding agent needs stable output. Human-readable
  output is for terminal browsing.
</Note>

<Steps>
  <Step title="Install the CLI">
    Install the native `logbrew` CLI for your platform.

    ```bash
    curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
    ```

    ```powershell
    powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
    ```

    Windows users can also install the MSI from the latest GitHub Release
    assets. Package managers are available when you prefer them.

    ```bash
    brew install LogBrewCo/tap/logbrew
    npm install -g logbrew-cli
    cargo install logbrew-cli
    ```

    Then verify that the `logbrew` binary is on your path and can print stable
    JSON for agents.

    ```bash
    logbrew version --json
    logbrew --help
    ```

    The JSON output should include `binary`, `os`, and `arch`. The help output
    should list the main read targets: `logs`, `issues`, `actions`, `releases`,
    `trace`, and `issue`.

    <Note>
      Cargo and source builds require Rust 1.87 or newer. Native installers,
      npm, Homebrew, and the Windows MSI use release artifacts and do not need a
      local Rust toolchain.
    </Note>
  </Step>

  <Step title="Log in once">
    Start browser-based login from the terminal.

    ```bash
    logbrew login
    ```

    After this step, humans and coding agents can use the CLI without opening a
    dashboard for every investigation.
  </Step>

  <Step title="Open first-run examples">
    Ask the CLI for compact examples before you guess command syntax.

    ```bash
    logbrew examples
    logbrew help examples
    ```

    The examples guide covers first-run checks, troubleshooting, live watch, and
    agent JSON workflows.
  </Step>

  <Step title="Set up telemetry for your project">
    Ask LogBrew to plan SDK setup for the current project.

    ```bash
    logbrew setup --auto --yes --json
    ```

    If you already have a project ID, mark setup as observed from the CLI. This
    records shared LogBrew setup state for the project; it does not infer setup
    from local files.

    ```bash
    logbrew projects setup <project_id> --source cli --environment production --json
    ```

    Use discovery commands when an agent needs to inspect intended project
    creation or usage flows without changing state.

    ```bash
    logbrew projects --json
    logbrew setup --create-project --json
    logbrew usage --json
    ```

    In CLI v0.1.17, project creation and account usage commands are help-only.
    They do not create projects, calculate usage locally, create local-only
    setup state, or print SDK or ingest configuration.

    <Warning>
      Do not use an account bearer token as SDK or ingest configuration. Use
      only project-scoped SDK or ingest configuration returned by LogBrew.
    </Warning>

    Keep the release name stable and explicit, such as `api@1.2.3` or a git SHA.
    LogBrew rejects telemetry without a release and environment because
    release-level debugging depends on both fields.
  </Step>

  <Step title="Send a native telemetry envelope">
    First-party SDKs send one envelope that can contain logs, issues, trace
    spans, and actions. Every envelope belongs to one project, service, release,
    and environment.

    ```json telemetry-envelope.json
    {
      "project_id": "00000000-0000-0000-0000-000000000000",
      "environment": "production",
      "release": "api@1.2.3",
      "service_name": "checkout-api",
      "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
      "sdk_name": "logbrew-rust",
      "sdk_version": "0.1.0",
      "items": [
        {
          "type": "log",
          "data": {
            "severity": "error",
            "message": "payment provider timeout",
            "source": "runtime",
            "attributes": { "route": "/checkout" },
            "occurred_at": "2026-06-01T12:00:00Z"
          }
        }
      ]
    }
    ```
  </Step>

  <Step title="Read telemetry back">
    Start broad, then filter.

    ```bash
    logbrew status
    logbrew read releases --environment production --json
    logbrew read logs --release api@1.2.3 --environment production --json
    logbrew read issues --status unresolved --json
    logbrew read actions --name checkout_failed --since 24h --json
    logbrew read trace 4bf92f3577b34da6a3ce929d0e0e4736 --json
    logbrew watch --severity error,critical --json
    ```
  </Step>
</Steps>
