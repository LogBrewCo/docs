O LogBrew usa um termo para cada conceito do produto. Campos da API, flags da
CLI, valores de enum, nomes de eventos e chaves de atributos ficam iguais em
todos os idiomas.

## Observabilidade e monitoramento

| Termo | Significado |
| --- | --- |
| Observabilidade | Entender o comportamento de uma aplicação a partir das evidências que ela produz. |
| Telemetria | Os sinais que uma aplicação informa, como logs, traces e métricas. |
| Monitoramento | Conferir condições conhecidas, como um valor medido em relação a um limite. |
| `o11y` | Abreviação da palavra inglesa observability. O número conta as 11 letras entre o `o` e o `y`. |

Para escolher sinais e ver exemplos práticos, leia [Telemetria](/pt-BR/concepts/telemetry).

## Agentes de IA

| Termo | Significado |
| --- | --- |
| Servidor MCP | O servidor hospedado do LogBrew para o Model Context Protocol. Agentes de IA usam esse servidor para ler projetos aprovados. |
| Cliente MCP | Uma aplicação que conecta um agente de IA a um servidor MCP, como o Claude Code. |
| Projeto aprovado | Um projeto que você selecionou ao dar acesso a um cliente MCP. O cliente só pode ler projetos aprovados. |
| Conexão | O acesso que você dá a 1 cliente MCP ao aprová-lo. Ele termina após 30 dias sem uso, após 90 dias ou quando você o revoga. A CLI chama esse acesso de grant. |

Para conectar um cliente, leia [Conecte um agente de IA com MCP](/pt-BR/guides/mcp).

## Sinais de observabilidade

<AccordionGroup>
  <Accordion title="Problema">
    Uma falha agrupada que pode conter várias ocorrências. Uma ocorrência é uma
    instância capturada desse problema. `first_seen_at` é o horário da
    primeira ocorrência. `last_seen_at` é o horário da ocorrência mais recente.
  </Accordion>

  <Accordion title="Log">
    Um evento registrado com data e hora. Um log pode trazer gravidade,
    serviço, versão, ambiente, contexto de trace e atributos limitados por
    regras de privacidade.
  </Accordion>

  <Accordion title="Trace e span">
    Um trace acompanha o trabalho ao longo de uma requisição ou operação. Um
    span é uma operação cronometrada dentro desse trace. Uma correlação com um
    trace é evidência de contexto compartilhado; não é prova de causa.
  </Accordion>

  <Accordion title="Métrica">
    Uma medição feita em tempo de execução, com unidade, tipo, agregação e
    período definidos. Pontos de métrica não podem ser trocados por contagens
    de logs, traces ou problemas.
  </Accordion>

  <Accordion title="Versão">
    Uma versão implantada de uma aplicação ou de um serviço, informada junto
    com a telemetria. Uma versão não é o mesmo objeto que um projeto ou um
    repositório.
  </Accordion>

  <Accordion title="Ação">
    Um evento de produto classificado, como um cadastro, uma finalização de
    compra, uma importação ou um job com falha. As Análises classificam uma
    ação como visualização de página, visualização de tela ou interação. Uma
    ação não é um comando automático que o LogBrew executa.
  </Accordion>
</AccordionGroup>

## Investigação de problemas

Nem toda ocorrência tem todos os campos.

| Termo | Significado |
| --- | --- |
| Gravidade | A urgência de um sinal: `info`, `warning`, `error` ou `critical`. É diferente do status do problema. |
| Status do problema | O estado de um problema agrupado no fluxo de trabalho: `unresolved`, `resolved` ou `archived`. Não é o resultado de uma requisição. |
| Problema arquivado | Um problema que a equipe tirou da triagem ativa. Respostas mais antigas chamam esse status de `ignored`. |
| Prioridade do problema | A ordem de triagem de um problema agrupado: `high`, `medium` ou `low`. Ela segue a gravidade até que uma pessoa a defina. |
| Origem da prioridade | De onde vem a prioridade. `derived` segue a gravidade: `error` e `critical` são `high`, `warning` é `medium` e `info` é `low`. `manual` é uma prioridade que uma pessoa definiu. |
| Responsável pelo problema | A única conta ou equipe responsável pelo próximo passo de um problema agrupado. Uma conta precisa ter acesso de leitura ao projeto. Uma equipe precisa ser da organização do projeto. |
| Equipe | Um grupo de membros de uma organização, com um nome. Você pode atribuir problemas a uma equipe, e as regras de dono podem citá-la. Fazer parte de uma equipe não dá acesso a nenhum projeto. |
| Regra de dono | Uma regra do projeto que liga um caminho de frame da pilha, um módulo, uma rota, um serviço ou uma tag às contas ou equipes donas dos problemas que correspondem a ela. |
| Dono sugerido | Uma conta ou equipe que o LogBrew propõe para um problema, com base em uma regra de dono, uma linha do CODEOWNERS ou atividade recente. É uma sugestão, não uma atribuição. |
| Caixa de entrada | A lista de problemas que outras pessoas atribuíram a você ou às suas equipes. O LogBrew não envia e-mail sobre ela. |
| Rastreamento de pilha (stack trace) | Evidência capturada das chamadas de função de um erro. É diferente de um trace distribuído. |
| Frame da pilha | Uma entrada em um rastreamento de pilha. Pode identificar uma função, um módulo, um arquivo, uma linha ou uma coluna. |
| Cadeia de exceções | Exceções vinculadas, informadas juntas, como um erro e a causa dele. Entradas não capturadas, ocultadas ou truncadas limitam as evidências. |
| Frame da aplicação | Um frame da pilha marcado como código da aplicação. Mostra o código a examinar. Não prova onde está a falha. |
| Breadcrumb | Um evento curto registrado antes de uma ocorrência de problema. Os breadcrumbs não são uma gravação completa de uma sessão. |
| Exceção tratada | Uma exceção que a aplicação informou como tratada. Não prova que a operação deu certo. |
| Source map | Um artefato de build que mapeia locais do JavaScript gerado para os locais no código-fonte original. |
| Frame simbolizado | Um frame cujo local gerado foi convertido nas informações do código-fonte original. |
| Ocorrência de referência | A ocorrência capturada usada como referência para a reprodução. |
| Procedência | De onde vem uma avaliação. `backend_observed` significa que o LogBrew observou. `application_reported` significa que a aplicação informou e o LogBrew não verificou. |
| Prontidão para reprodução | Se a ocorrência de referência tem as evidências necessárias para tentar uma reprodução. Não é um teste de reprodução aprovado. |

Use o [guia de investigação](/pt-BR/guides/investigate-an-issue) para ver a ordem de
leitura e os campos da resposta.

## Identidade e correlação

Um valor ausente não prova que a atividade relacionada não aconteceu.

| Termo | Significado |
| --- | --- |
| Contexto de trace | Os identificadores de trace e de span que ligam o trabalho entre sinais. |
| Span raiz | O span que inicia um trace e não tem span pai. O span retornado mais antigo não é necessariamente a raiz. |
| Span filho | Um span com um span pai no mesmo trace. |
| Correlação | Uma relação exata que o LogBrew retorna, como um ID de trace compartilhado. Não prova causa. |
| Usuário identificado | Uma identidade fornecida pela aplicação, com ID estável e tipo `user`. |
| Identidade anônima | Uma identidade fornecida pela aplicação, com tipo `anonymous`. As contagens a mantêm separada dos usuários identificados. |
| Tipo de identidade desconhecido | Uma identidade sem tipo conhecido. Ela não conta como usuário identificado. |
| Identidade ausente | Um evento sem identidade. É diferente de uma identidade com tipo desconhecido. |

O tipo de identidade mostra como a aplicação classificou a identidade. Ele não
prova que os dados são anônimos. Um ID estável ainda pode ligar atividades.

## Escopo e qualidade dos dados

| Termo | Significado |
| --- | --- |
| Projeto | O principal limite de produto, com dono definido. Um projeto pode conter vários serviços ou componentes de repositório. |
| Serviço | Um runtime ou componente que envia dados dentro de um projeto. |
| Ambiente | Um contexto exato de origem dos dados, como produção ou staging. |
| Ingerido | Aceito pelo contrato de ingestão. Não garante retenção por tempo indeterminado. |
| Indexado | Disponível para o índice ou a consulta especificados. Não é sinônimo de ingerido. |
| Retido | Presente no período de dados avaliado e dentro da retenção de dados da conta. |
| Amostrado | Parte da telemetria foi selecionada antes ou durante a coleta. |
| Cobertura | Uma proporção medida, com numerador e denominador explícitos. |
| Truncado | A resposta atingiu um limite. Dados omitidos não estão necessariamente ausentes. |
| Aproximado | Estimado pelo método documentado, em vez de contado com exatidão. |
| Período | O trecho de tempo exato que uma consulta avalia. |

## Planos e organizações

| Termo | Significado |
| --- | --- |
| Plano | Um conjunto fixo de franquias mensais com um período de retenção. Os planos são Free, Pro, Business e Enterprise. |
| Franquia | A quantidade de um tipo de telemetria que um plano inclui em 1 mês de cobrança, como bytes de logs ou spans de trace. |
| Retenção de dados | O número de dias que o LogBrew guarda a telemetria de uma conta. O LogBrew exclui a telemetria mais antiga. É diferente da retenção da análise de produto. |
| Oferta beta | As franquias do Pro que uma conta recebe grátis por 6 meses durante o beta público. Depois, a conta usa o plano próprio. |
| Organização | Um espaço compartilhado para membros, equipes e projetos. Todo plano tem organizações sem limite de membros nem de projetos. |

Veja as franquias e a retenção de cada plano em [API de conta](/pt-BR/reference/account-api).

## Medições e tempo

| Termo | Significado |
| --- | --- |
| Ponto de dados | Um valor em um horário informado. Leia o nome e a unidade da métrica antes de comparar pontos de dados. |
| Série temporal | Valores da mesma medição ordenados por tempo. Uma lacuna não significa que o valor foi zero. |
| Duração | O tempo decorrido de uma operação. É diferente do horário em que a operação ocorreu. |
| Agregação | Um cálculo definido sobre medições, como uma soma ou uma média. |
| Intervalo | Uma faixa de tempo em um gráfico ou em um resultado agrupado. O início e o fim dela definem o alcance. |
| Período parcial | Um período que ainda não terminou. Não é um período completo sem atividade. |

Não some as durações de spans filhos sobrepostos para obter o tempo total da
requisição. Não compare uma contagem de eventos com uma contagem de usuários
identificados.

## Estados das evidências

Estes estados não são equivalentes:

- **Capturado:** a evidência está presente.
- **Não capturado:** a evidência não foi capturada.
- **Ocultado:** a evidência foi escondida de propósito.
- **Truncado:** a evidência passou de um limite da resposta ou da captura.
- **Indisponível:** a leitura não conseguiu fornecer a evidência.

`Likely cause` (causa provável) e `likely fix area` (área provável de
correção) descrevem evidências de diagnóstico limitadas, não uma causa raiz
comprovada. `Reported impact` (impacto informado) vem da aplicação que envia os
dados, a menos que um contrato descreva explicitamente uma medição do LogBrew.

## Análise de produto

| Termo | Significado |
| --- | --- |
| Evento | Atividade de produto classificada, com um nome exato e estável. |
| Propriedade | Uma chave de contexto usada para descrever ou filtrar um evento. |
| Sessão | Uma visita ou uma sessão de aplicativo, não uma pessoa. |
| Coorte | Um grupo delimitado, definido por critérios exatos. |
| Funil | Etapas ordenadas usadas para medir progressão ou conversão. |
| Retenção | Comportamento de retorno medido com período e denominador explícitos. |
| Caminhos | Jornadas da sessão antes ou depois de um evento selecionado. |
| Ciclo de vida | Classifica as identidades reconhecidas de cada período em: Novo no histórico observado, Recorrente, Reativado ou Inativo. |
| Novo no histórico observado | Ativo sem um evento selecionado anterior no período delimitado do histórico. Não significa um cliente que chegou pela primeira vez. |

Períodos parciais, identidade ausente, captura incompleta de propriedades,
amostragem e truncamento afetam a leitura do resultado. O LogBrew mostra esses
limites em vez de transformá-los em zero ou em certeza.

Leia [Análise de produto](/pt-BR/concepts/product-analytics) para ver as regras de
contagem. Use [Captura de eventos de produto](/pt-BR/guides/product-events) para
enviar atividade classificada e identidade tipada.
