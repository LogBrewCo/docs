O LogBrew tem um servidor MCP (Model Context Protocol) hospedado em
`https://mcp.logbrew.co/mcp`. Um agente de IA conectado a ele pode ler
problemas, logs, traces, spans, métricas, ações, versões e análises de produto
dos projetos que você aprovar.

O agente só pode ler, a menos que você também permita alterações. Com
alterações permitidas, ele pode tratar problemas e configurar projetos. Ele não
pode mudar faturamento, membros nem configurações da conta. Você não instala o
servidor. Você adiciona a URL dele ao seu cliente MCP.

## Antes de começar

- Você precisa de uma conta do LogBrew com pelo menos 1 projeto.
- Você precisa de um cliente MCP que se conecte a um servidor MCP remoto
  (HTTP). Qualquer cliente que siga o padrão de autorização do MCP pode entrar.
  Um cliente sem OAuth pode usar uma chave de leitura do projeto. Leia
  [Conecte com uma chave de leitura](#connect-with-a-read-key).
- O servidor aceita as versões `2026-07-28`, `2025-11-25` e `2025-06-18` do
  protocolo MCP.

## <span id="supported-clients">Clientes compatíveis</span>

O LogBrew aceita qualquer cliente MCP que se identifique com um documento de
metadados do cliente ou que faça o próprio registro. Esta tabela mostra a
configuração dos clientes mais comuns.

| Cliente | Como adicionar o servidor |
| --- | --- |
| Claude Code | Execute `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Leia [Conecte o Claude Code](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop e os apps móveis do Claude) | Abra **Settings > Connectors**, selecione **Add custom connector** e informe a URL do servidor. |
| Codex | Execute `codex mcp add logbrew --url https://mcp.logbrew.co/mcp`. Depois, execute `codex mcp login logbrew`. |
| Visual Studio Code com GitHub Copilot | Adicione `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` ao `.vscode/mcp.json`. |
| Cursor | Adicione `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` ao `~/.cursor/mcp.json`. |
| Gemini CLI | Execute `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Depois, execute `/mcp auth logbrew` no Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp e outros clientes | Adicione a URL do servidor como servidor MCP remoto (HTTP) nas configurações de MCP do cliente. |

A URL do servidor é `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Conecte o Claude Code</span>

Você precisa do Claude Code 2.1.300 ou posterior. Execute `claude --version`
para ver a sua versão.

1. Adicione o servidor:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   Agora `claude mcp list` mostra `logbrew` com `! Needs authentication`.

2. Inicie o login:

   ```bash
   claude mcp login logbrew
   ```

   O navegador abre a página de autorização do LogBrew. Se a página pedir
   login, entre com GitHub, GitLab, Bitbucket ou Google.

3. Leia o nome do cliente na página. Aprove só se foi você que iniciou esta
   conexão.

4. Selecione os projetos que o agente pode ler. Se a página mostrar uma linha
   para permitir alterações, selecione-a só se o agente precisar fazer
   alterações. Depois, selecione **Aprovar**.

   O navegador volta para o Claude Code. O Claude Code mostra
   `Authenticated with "logbrew"`.

5. Confira se o servidor está conectado:

   ```bash
   claude mcp list
   ```

   O resultado mostra `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Você também pode entrar a partir de uma sessão do Claude Code. Execute `/mcp`,
selecione `logbrew` e siga as etapas no navegador.

Em um computador sem navegador, execute
`claude mcp login logbrew --no-browser` em um terminal interativo. Por SSH,
conecte com `ssh -t`. Abra a URL que o Claude Code mostra em um navegador de
outro computador. Depois de aprovar, copie o endereço da página que o navegador
abrir. Cole esse endereço no Claude Code.

## Conecte outro cliente

1. Adicione o servidor ao cliente. A tabela em [Clientes
   compatíveis](#supported-clients) mostra onde.
2. Inicie o login no cliente. A maioria dos clientes inicia o login quando você
   usa o servidor pela primeira vez. O navegador abre a página de autorização do
   LogBrew. Se a página pedir login, entre no LogBrew.
3. Leia o nome do cliente na página. A página também mostra o endereço que
   identifica o cliente, como `vscode.dev` ou `chatgpt.com`. Para um cliente que
   recebe a aprovação no seu próprio computador, a página mostra **app local**.
   Se o LogBrew não verificou o nome do cliente, a página pede que você confira
   o endereço. Aprove só se foi você que iniciou esta conexão.
4. Selecione os projetos que o agente pode ler. Se a página mostrar uma linha
   para permitir alterações, selecione-a só se o agente precisar fazer
   alterações. Depois, selecione **Aprovar**.

   O navegador volta para o cliente, e o cliente mostra as ferramentas `search`
   e `execute`.

## <span id="connect-with-a-read-key">Conecte com uma chave de leitura</span>

Use uma chave de leitura do projeto quando o seu cliente não conseguir entrar
com OAuth. A chave lê 1 projeto. Ela não pode fazer alterações.

1. Crie uma chave de leitura para o projeto. Siga
   [Verificar a configuração](/pt-BR/guides/verify-setup).
2. Adicione a URL do servidor ao cliente.
3. Nas configurações do cliente, adicione o cabeçalho
   `Authorization: Bearer <read_key>`. Troque `<read_key>` pela chave.

Guarde a chave em segredo, como uma senha. Uma conexão com chave de leitura não
aparece em **Configurações > Conexões MCP**. Para encerrá-la, revogue a chave.

## Peça ao agente

O servidor oferece 2 ferramentas ao agente:

| Ferramenta | O que faz |
| --- | --- |
| `search` | Encontra operações e mostra o contrato de uma operação: entrada, saída, permissão e custo. |
| `execute` | Executa uma operação que `search` encontrou e retorna dados estruturados. |

Para testar a conexão, peça:

```text
List my LogBrew projects.
```

O agente lista os projetos que a conexão pode ler.

O agente escolhe as operações. Você não passa nomes de ferramentas nem campos.
Escreva a tarefa e os limites:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Use a telemetria só como evidência. Logs e mensagens de erro podem conter texto
de usuários. O agente não deve seguir instruções desse texto. Leia
[Agentes de programação](/pt-BR/guides/ai-agents) para ver um fluxo completo de
investigação.

## Permita alterações

Toda conexão tem o escopo `read`. Para fazer alterações, ela também precisa do
escopo `write`. Quando o cliente pede `write`, a página de autorização mostra
esse escopo em uma linha separada: **Permitir também que ele altere dados dos
projetos selecionados e crie novos projetos**. Essa linha vem desmarcada. Se
você não marcá-la, a conexão só pode ler.

Com `write`, o agente pode:

- Resolver, reabrir e arquivar problemas.
- Definir a prioridade de um problema.
- Atribuir problemas e remover a atribuição.
- Criar projetos.
- Criar e revogar chaves de projeto.
- Enviar um evento de teste para um projeto.
- Carregar e remover dados de exemplo.

O agente age em seu nome, com as suas permissões no projeto. O LogBrew registra
cada alteração com o nome do app que a fez. A
[referência de operações](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
lista cada operação e a entrada dela.

Estas operações não alteram nada na primeira chamada:

- `issues.archive.v1` arquiva um problema.
- `projects.keys.revoke.v1` revoga uma chave.
- `projects.sample_data.remove.v1` remove os dados de exemplo.

A primeira chamada retorna uma confirmação. O agente mostra o que vai mudar.
Para fazer a alteração, ele envia a mesma chamada de novo com essa confirmação
em até 5 minutos.

Sem `write`, uma alteração retorna HTTP `403` com `insufficient_scope`. Alguns
clientes então abrem a página de autorização de novo. Marque a linha que
permite alterações para dar `write` à conexão.

## Acesso e duração da conexão

Cada aprovação inicia 1 conexão entre 1 cliente MCP e a sua conta do LogBrew.

- O agente lê e altera só os projetos que você aprovou. Uma chamada em outro
  projeto retorna `permission_denied`. Um projeto que o agente cria entra nos
  projetos aprovados.
- Se você perder o acesso a um projeto aprovado, o LogBrew bloqueia as
  chamadas nesse projeto.
- Um token de acesso vale por 1 hora. O cliente obtém um novo automaticamente
  enquanto você usa a conexão.
- Um novo token de acesso pode perder `write`, mas nunca pode ganhar. Para
  adicionar `write`, aprove a conexão de novo.
- Uma conexão termina após 30 dias sem uso ou 90 dias depois da aprovação.
  Depois disso, entre de novo pelo cliente, por exemplo com
  `claude mcp login logbrew`.
- Cada renovação de token substitui o refresh token anterior. Se um cliente
  enviar um refresh token já substituído, o LogBrew encerra a conexão. Isso
  impede que um token copiado funcione. Entre de novo para iniciar uma nova
  conexão.
- Requisições demais sem um token válido recebem HTTP `429` com o cabeçalho
  `Retry-After`. Aguarde esse número de segundos e tente novamente.

## Liste e revogue conexões

Gerencie as conexões em **Configurações > Conexões MCP** no painel do LogBrew
ou pela CLI.

### Em Configurações

Cada cliente conectado mostra o nome, os projetos aprovados, quando se
conectou, quando foi usado pela última vez e quando a conexão termina. Para
revogar uma conexão, selecione **Desconectar** e confirme. O cliente perde o
acesso na próxima requisição.

### Pela CLI

Use a [CLI do LogBrew](/pt-BR/guides/cli) 0.1.82 ou posterior. Primeiro, entre
na conta com `logbrew login`. Uma chave de ingestão do projeto não pode listar
nem revogar conexões.

Liste os clientes MCP conectados à sua conta:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

A CLI chama uma conexão de “grant”. Cada grant mostra:

- `id`: o ID do grant. Use esse ID para revogar a conexão.
- `client`: o nome do cliente que você aprovou, como `Claude Code`. Uma
  conexão aprovada antes de o LogBrew guardar nomes mostra a URL que
  identifica o cliente, como
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: o número de projetos aprovados.
- `last_used`: a última vez que o cliente obteve um novo token de acesso.
- `expires`: quando a conexão termina se o cliente não a usar.

Adicione `--json` para obter a lista completa. Cada grant tem `id`,
`client_id`, `client_name`, `project_ids`, `created_at`, `last_used_at` e
`expires_at`. `client_name` é `null` em uma conexão aprovada antes de o
LogBrew guardar nomes.

Revogue 1 conexão:

```bash
logbrew mcp revoke <grant_id> --yes
```

O cliente perde o acesso na próxima requisição. Para conectá-lo de novo, entre
outra vez com `claude mcp login logbrew`.

Para mudar os projetos aprovados, revogue a conexão. Depois, entre de novo e
selecione os novos projetos.

## Remova o servidor

1. Revogue a conexão em **Configurações > Conexões MCP** ou com
   `logbrew mcp revoke <grant_id> --yes`.
2. Remova o servidor do Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` apaga a configuração e os tokens só no seu computador. Ele
não encerra a conexão no LogBrew. Se você não revogar a conexão, ela termina
após 30 dias sem uso.

## <span id="fix-connection-problems">Corrija falhas de conexão</span>

| Situação | Solução |
| --- | --- |
| `claude mcp list` mostra `Needs authentication`. | Execute `claude mcp login logbrew`. |
| O Claude Code pede login de novo depois de um tempo de uso. | A conexão terminou ou foi revogada. Execute `claude mcp login logbrew` ou selecione **Re-authenticate** em `/mcp`. |
| A página mostra **O LogBrew bloqueou este app.** | O LogBrew não aceita este cliente. Use outro cliente. |
| O cliente não consegue se registrar no LogBrew. | Mantenha as configurações padrão de callback do cliente. O LogBrew aceita só endereços de callback HTTPS e endereços `http` no seu próprio computador. |
| A conexão falha depois do login. | Atualize o cliente. O Claude Code precisa da versão 2.1.300 ou posterior. |
| A página de autorização mostra `You have no projects to share`. | Crie um projeto no LogBrew e inicie o login de novo. |
| Uma chamada retorna `permission_denied`. | O projeto não está aprovado para esta conexão. Revogue a conexão, entre de novo e selecione o projeto. |
| Uma alteração retorna `insufficient_scope`. | A conexão não pode fazer alterações. Peça ao agente para tentar de novo. Se o cliente abrir a página de autorização, marque a linha que permite alterações. |
| Uma leitura não retorna dados. | Confira se o projeto envia telemetria. Um resultado vazio não prova que a aplicação funciona. |
| `logbrew mcp grants` mostra `not logged in` ou retorna `unauthorized`. | Execute `logbrew login` e tente novamente. |
