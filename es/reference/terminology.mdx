LogBrew usa un término para cada concepto del producto. Los campos de la API,
las opciones de la CLI, los valores de enumeración, los nombres de eventos y
las claves de atributos no cambian en ningún idioma.

## Observabilidad y monitoreo

| Término | Significado |
| --- | --- |
| Observabilidad | Entender el comportamiento de una aplicación a partir de la evidencia que produce. |
| Telemetría | Las señales que informa una aplicación, como logs, trazas y métricas. |
| Monitoreo | Comprobar condiciones conocidas, como un valor medido frente a un umbral. |
| `o11y` | Forma abreviada de «observability». El número cuenta las 11 letras entre `o` e `y`. |

Para elegir señales y ver ejemplos prácticos, lee
[Telemetría](/es/concepts/telemetry).

## Agentes de IA

| Término | Significado |
| --- | --- |
| Servidor MCP | El servidor alojado de LogBrew para el Model Context Protocol. Los agentes de IA lo usan para leer los proyectos aprobados. |
| Cliente MCP | Una aplicación que conecta un agente de IA con un servidor MCP, como Claude Code. |
| Proyecto aprobado | Un proyecto que seleccionaste al dar acceso a un cliente MCP. El cliente solo puede leer los proyectos aprobados. |
| Conexión | El acceso que das a 1 cliente MCP al aprobarlo. Termina tras 30 días sin uso, a los 90 días o cuando la revocas. La CLI la llama «grant». |

Para conectar un cliente, lee [Conecta un agente de IA con MCP](/es/guides/mcp).

## Señales de observabilidad

<AccordionGroup>
  <Accordion title="Incidencia">
    Un problema agrupado que puede contener varias ocurrencias. Una ocurrencia
    es una instancia capturada de esa incidencia. `first_seen_at` es la hora de
    la primera ocurrencia. `last_seen_at` es la hora de la ocurrencia más
    reciente.
  </Accordion>

  <Accordion title="Log">
    Un registro de evento con marca de tiempo. Un log puede llevar severidad,
    servicio, release, entorno, contexto de la traza y atributos limitados por
    las reglas de privacidad.
  </Accordion>

  <Accordion title="Traza y span">
    Una traza sigue el trabajo a lo largo de una solicitud u operación. Un
    span es una operación medida en el tiempo dentro de esa traza. Una
    correlación con una traza es evidencia de un contexto compartido; no
    demuestra la causa.
  </Accordion>

  <Accordion title="Métrica">
    Una medida en tiempo de ejecución con unidad, tipo, agregación e intervalo
    de tiempo definidos. Los puntos de métricas no se pueden intercambiar con
    los recuentos de logs, trazas o incidencias.
  </Accordion>

  <Accordion title="Release">
    Una versión desplegada de una aplicación o un servicio, informada junto con
    la telemetría. Un release no es lo mismo que un proyecto o un repositorio.
  </Accordion>

  <Accordion title="Acción">
    Un evento de producto clasificado, como un registro de usuario, un pago,
    una importación o un trabajo fallido. Analíticas clasifica una acción como
    vista de página, vista de pantalla o interacción. Una acción no es un
    comando automático que ejecute LogBrew.
  </Accordion>
</AccordionGroup>

## Investigación de incidencias

No todas las ocurrencias contienen todos los campos.

| Término | Significado |
| --- | --- |
| Severidad | La urgencia de una señal: `info`, `warning`, `error` o `critical`. Es distinta del estado de la incidencia. |
| Estado de la incidencia | El estado de flujo de trabajo de una incidencia agrupada: `unresolved`, `resolved` o `archived`. No es el resultado de una solicitud. |
| Incidencia archivada | Una incidencia que el equipo sacó del triaje activo. Las respuestas antiguas llaman a este estado `ignored`. |
| Prioridad de la incidencia | El orden de triaje de una incidencia agrupada: `high`, `medium` o `low`. Sigue a la severidad hasta que una persona la define. |
| Origen de la prioridad | De dónde viene la prioridad. `derived` sigue a la severidad: `error` y `critical` son `high`, `warning` es `medium` e `info` es `low`. `manual` es una prioridad que definió una persona. |
| Responsable de la incidencia | La única cuenta o el único equipo responsable del siguiente paso de una incidencia agrupada. Una cuenta debe poder leer el proyecto. Un equipo debe pertenecer a la organización del proyecto. |
| Equipo | Un grupo de miembros de una organización que tiene un nombre. Puedes asignar incidencias a un equipo, y las reglas de propiedad pueden nombrarlo. Pertenecer a un equipo no da acceso a ningún proyecto. |
| Regla de propiedad | Una regla del proyecto que relaciona la ruta de un marco de pila, un módulo, una ruta web, un servicio o una etiqueta con las cuentas o los equipos propietarios de las incidencias que coinciden. |
| Propietario sugerido | Una cuenta o un equipo que LogBrew propone para una incidencia a partir de una regla de propiedad, una línea de CODEOWNERS o la actividad reciente. Es una sugerencia, no una asignación. |
| Bandeja de entrada | La lista de incidencias que otras personas te asignaron a ti o a tus equipos. LogBrew no envía correos por ella. |
| Traza de pila | Evidencia capturada de las llamadas a funciones de un error. Es distinta de una traza distribuida. |
| Marco de pila | Una entrada de una traza de pila. Puede identificar una función, un módulo, un archivo, una línea o una columna. |
| Cadena de excepciones | Excepciones vinculadas que se informan juntas, como un error y su causa. Las entradas ausentes, ocultas o truncadas limitan la evidencia. |
| Marco de la aplicación | Un marco de pila marcado como código de la aplicación. Muestra código que hay que revisar. No demuestra dónde está el fallo. |
| Paso anterior (breadcrumb) | Un evento breve registrado antes de una ocurrencia de una incidencia. Los pasos anteriores no son una grabación completa de una sesión. |
| Excepción gestionada | Una excepción que la aplicación informó como gestionada. No demuestra que la operación terminara bien. |
| Mapa de origen | Un artefacto de compilación que relaciona las ubicaciones del JavaScript generado con las ubicaciones del código fuente original. |
| Marco simbolizado | Un marco cuya ubicación generada se resolvió con la información del código fuente original. |
| Ocurrencia base | La ocurrencia capturada que se usa como referencia para la reproducción. |
| Procedencia | De dónde viene una evaluación. `backend_observed` significa que LogBrew la observó. `application_reported` significa que la app la informó y LogBrew no la verificó. |
| Preparación para reproducir | Si la ocurrencia base tiene la evidencia necesaria para intentar una reproducción. No es una prueba de reproducción superada. |

Usa [Investigar una incidencia](/es/guides/investigate-an-issue) para ver el
orden de lectura y los campos de la respuesta.

## Identidad y correlación

Un valor ausente no demuestra que la actividad relacionada no ocurriera.

| Término | Significado |
| --- | --- |
| Contexto de la traza | Los identificadores de traza y de span que conectan el trabajo entre señales. |
| Span raíz | El span que inicia una traza y no tiene span padre. El primer span devuelto no es necesariamente la raíz. |
| Span hijo | Un span con un span padre en la misma traza. |
| Correlación | Una relación exacta que devuelve LogBrew, como un ID de traza compartido. No demuestra la causa. |
| Usuario identificado | Un sujeto que proporciona la app, con un ID estable y el tipo `user`. |
| Sujeto anónimo | Un sujeto que proporciona la app, con el tipo `anonymous`. Los recuentos lo separan de los usuarios identificados. |
| Tipo de identidad desconocido | Un sujeto sin un tipo conocido. No se cuenta como usuario identificado. |
| Sujeto ausente | Un evento sin sujeto. Es distinto de un sujeto con un tipo desconocido. |

El tipo de identidad muestra cómo clasificó la app a su sujeto. No demuestra
que los datos sean anónimos. Un ID estable puede seguir vinculando actividad.

## Alcance y calidad de los datos

| Término | Significado |
| --- | --- |
| Proyecto | El límite principal de un producto propio. Un proyecto puede contener varios servicios o componentes de repositorio. |
| Servicio | Un runtime o componente que informa datos dentro de un proyecto. |
| Entorno | Un contexto exacto desde el que se informan datos, como producción o staging. |
| Clave de ingesta | Una clave de proyecto que envía telemetría a un solo proyecto. No puede leer telemetría. |
| Clave de lectura | Una clave de proyecto que lee la telemetría de un solo proyecto. No puede enviar telemetría, cambiar datos ni iniciar sesión. Consulta [Tipos de clave de proyecto](/es/guides/verify-setup#project-key-kinds). |
| Ingerido | Aceptado por el contrato de ingesta. No promete una conservación indefinida. |
| Indexado | Disponible para el índice o la consulta indicados. No es sinónimo de ingerido. |
| Conservado | Presente en el intervalo de tiempo evaluado y dentro de la retención de datos de la cuenta. |
| Muestreado | Parte de la telemetría se seleccionó antes o durante la recopilación. |
| Cobertura | Una proporción medida con un numerador y un denominador explícitos. |
| Truncado | La respuesta alcanzó un límite. Los datos omitidos no son necesariamente ausentes. |
| Aproximado | Estimado con el método documentado en lugar de contado con exactitud. |
| Intervalo de tiempo | El periodo exacto que evalúa una consulta. |

## Planes y organizaciones

| Término | Significado |
| --- | --- |
| Plan | Un conjunto fijo de cuotas mensuales con un periodo de retención. Los planes son Free, Pro, Business y Enterprise. |
| Cuota | La cantidad de un tipo de telemetría que incluye un plan en 1 mes de facturación, como bytes de logs o spans de trazas. |
| Retención de datos | El número de días que LogBrew conserva la telemetría de una cuenta. LogBrew elimina la telemetría más antigua. No es lo mismo que la retención en la analítica de producto. |
| Oferta beta | Las cuotas de Pro que una cuenta recibe gratis durante 6 meses en la beta pública. Después, la cuenta usa su plan propio. |
| Organización | Un espacio compartido para miembros, equipos y proyectos. Todos los planes tienen organizaciones sin límite de miembros ni de proyectos. |

Consulta las cuotas y la retención de cada plan en [API de cuenta](/es/reference/account-api).

## Medidas y tiempo

| Término | Significado |
| --- | --- |
| Punto de datos | Un valor en un momento informado. Lee el nombre y la unidad de la métrica antes de comparar puntos de datos. |
| Serie temporal | Valores de una misma medida ordenados por tiempo. Un hueco no significa que el valor fuera cero. |
| Duración | El tiempo transcurrido de una operación. Es distinto del momento en que ocurrió la operación. |
| Agregación | Un cálculo definido sobre varias medidas, como una suma o una media. |
| Intervalo | Un tramo de un gráfico o de un resultado agrupado. Su inicio y su fin definen el rango. |
| Periodo parcial | Un periodo que todavía no ha terminado. No es un periodo terminado sin actividad. |

No sumes las duraciones de spans hijos que se solapan para obtener el tiempo
total de la solicitud. No compares un recuento de eventos con un recuento de
usuarios identificados.

## Estados de la evidencia

Estos estados no son intercambiables:

- **Capturado:** la evidencia está presente.
- **Ausente:** la evidencia no se capturó.
- **Oculto:** la evidencia se ocultó deliberadamente.
- **Truncado:** la evidencia superó un límite de la respuesta o de la captura.
- **No disponible:** la lectura no pudo proporcionar la evidencia.

`Likely cause` (causa probable) y `likely fix area` (área de corrección
probable) describen evidencia de diagnóstico limitada, no una causa raíz
demostrada. `Reported impact` (impacto informado) lo proporciona la
aplicación que informa, salvo que un contrato describa de forma explícita una
medida de LogBrew.

## Analíticas de producto

| Término | Significado |
| --- | --- |
| Evento | Actividad de producto clasificada con un nombre estable exacto. |
| Propiedad | Una clave de contexto que se usa para describir o filtrar un evento. |
| Sesión | Una visita o una sesión de la app, no una persona. |
| Cohorte | Un grupo limitado, definido por criterios exactos. |
| Embudo | Pasos ordenados que se usan para medir el avance o la conversión. |
| Retención | El comportamiento de regreso, medido con un periodo y un denominador explícitos. |
| Rutas | Recorridos de una sesión antes o después de un evento seleccionado. |
| Ciclo de vida | Agrupa a los sujetos identificados de cada periodo como nuevos en el historial observado, recurrentes, reactivados o inactivos. |
| Nuevo en el historial observado | Activo sin un evento seleccionado anterior dentro de la ventana del historial limitada. No significa un cliente nuevo. |

Los periodos parciales, la identidad ausente, la captura incompleta de
propiedades, el muestreo y el truncamiento matizan el resultado. LogBrew
muestra esos límites en lugar de convertirlos en cero o en certeza.

Lee [Analíticas de producto](/es/concepts/product-analytics) para ver las
reglas de recuento. Usa [Captura de eventos de producto](/es/guides/product-events)
para enviar actividad clasificada e identidad tipada.
