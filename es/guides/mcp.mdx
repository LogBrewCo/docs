description: "Conecta Claude Code, Claude, VS Code, Cursor, Codex, ChatGPT o cualquier otro cliente MCP al servidor MCP alojado de LogBrew. Aprueba los proyectos que puede leer, decide si puede hacer cambios y gestiona su conexión en Ajustes o con la CLI."

LogBrew tiene un servidor MCP alojado en `https://mcp.logbrew.co/mcp`. Un
agente de IA conectado a él puede leer incidencias, logs, trazas, spans,
métricas, acciones, releases y analíticas de producto de los proyectos que
apruebes.

El agente solo puede leer, salvo que también permitas cambios. Con cambios
permitidos, puede gestionar incidencias y configurar proyectos. No puede cambiar
la facturación, los miembros ni los ajustes de la cuenta. No tienes que instalar
el servidor. Añades su URL a tu cliente MCP.

## Antes de empezar

- Necesitas una cuenta de LogBrew con al menos 1 proyecto.
- Necesitas un cliente MCP que pueda conectarse a un servidor MCP remoto
  (HTTP). Cualquier cliente que siga el estándar de autorización de MCP puede
  iniciar sesión. Un cliente sin OAuth puede usar una clave de lectura del
  proyecto. Lee [Conecta con una clave de lectura](#connect-with-a-read-key).
- El servidor admite las versiones `2026-07-28`, `2025-11-25` y `2025-06-18` del
  protocolo MCP.

## <span id="supported-clients">Clientes compatibles</span>

LogBrew acepta cualquier cliente MCP que se identifique con un documento de
metadatos de cliente o que se registre por su cuenta. Esta tabla muestra la
configuración de los clientes más comunes.

| Cliente | Cómo añadir el servidor |
| --- | --- |
| Claude Code | Ejecuta `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Lee [Conecta Claude Code](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop y las apps móviles de Claude) | Abre **Settings > Connectors**, selecciona **Add custom connector** e introduce la URL del servidor. |
| Codex | Ejecuta `codex mcp add logbrew --url https://mcp.logbrew.co/mcp`. Después, ejecuta `codex mcp login logbrew`. |
| Visual Studio Code con GitHub Copilot | Añade `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` a `.vscode/mcp.json`. |
| Cursor | Añade `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` a `~/.cursor/mcp.json`. |
| Gemini CLI | Ejecuta `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Después, ejecuta `/mcp auth logbrew` en Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline, Amp y otros clientes | Añade la URL del servidor como servidor MCP remoto (HTTP) en los ajustes de MCP del cliente. |

La URL del servidor es `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Conecta Claude Code</span>

Necesitas Claude Code 2.1.300 o posterior. Ejecuta `claude --version` para ver
tu versión.

1. Añade el servidor:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` muestra ahora `logbrew` con `! Needs authentication`.

2. Inicia sesión:

   ```bash
   claude mcp login logbrew
   ```

   Tu navegador abre la página de autorización de LogBrew. Si la página te
   pide iniciar sesión, inicia sesión con GitHub, GitLab, Bitbucket o Google.

3. Lee el nombre del cliente en la página. Apruébalo solo si tú iniciaste esta
   conexión.

4. Selecciona los proyectos que el agente puede leer. Si la página muestra una
   línea para permitir cambios, selecciónala solo si el agente debe hacer
   cambios. Después, selecciona **Approve**.

   El navegador vuelve a Claude Code. Claude Code muestra
   `Authenticated with "logbrew"`.

5. Comprueba que el servidor está conectado:

   ```bash
   claude mcp list
   ```

   El resultado muestra `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

También puedes iniciar sesión desde una sesión de Claude Code. Ejecuta `/mcp`,
selecciona `logbrew` y sigue los pasos en tu navegador.

En un equipo sin navegador, ejecuta `claude mcp login logbrew --no-browser` en
una terminal interactiva. Por SSH, conéctate con `ssh -t`. Abre la URL que
muestra Claude Code en un navegador de otro equipo. Después de aprobar, copia
la dirección de la página que abre el navegador. Pégala en Claude Code.

## Conecta otro cliente

1. Añade el servidor al cliente. La tabla de [Clientes
   compatibles](#supported-clients) indica dónde.
2. Inicia sesión desde el cliente. La mayoría de los clientes abre el inicio de
   sesión la primera vez que usas el servidor. Tu navegador abre la página de
   autorización de LogBrew. Si la página te pide iniciar sesión, inicia sesión
   en LogBrew.
3. Lee el nombre del cliente en la página. La página también muestra la
   dirección que identifica al cliente, como `vscode.dev` o `chatgpt.com`. Si el
   cliente recibe la aprobación en tu propio ordenador, la página muestra
   **app local**. Si LogBrew no verificó el nombre del cliente, la página te
   pide que revises la dirección. Apruébalo solo si tú iniciaste esta conexión.
4. Selecciona los proyectos que el agente puede leer. Si la página muestra una
   línea para permitir cambios, selecciónala solo si el agente debe hacer
   cambios. Después, selecciona **Approve**.

   El navegador vuelve al cliente, y el cliente muestra las herramientas
   `search` y `execute`.

## <span id="connect-with-a-read-key">Conecta con una clave de lectura</span>

Usa una clave de lectura del proyecto si tu cliente no puede iniciar sesión con
OAuth. La clave lee 1 proyecto. No puede hacer cambios.

1. Crea una clave de lectura para el proyecto. Sigue
   [Verifica tu configuración](/es/guides/verify-setup).
2. Añade la URL del servidor al cliente.
3. En los ajustes del cliente, añade la cabecera
   `Authorization: Bearer <read_key>`. Sustituye `<read_key>` por la clave.

Guarda la clave en secreto, como una contraseña. Una conexión con clave de
lectura no aparece en **Ajustes > Conexiones MCP**. Para terminarla, revoca la
clave.

## Pídele tareas al agente

El servidor le da al agente 2 herramientas:

| Herramienta | Qué hace |
| --- | --- |
| `search` | Busca operaciones y muestra el contrato de una operación: su entrada, su salida, su permiso y su coste. |
| `execute` | Ejecuta una operación que encontró `search` y devuelve datos estructurados. |

Para probar la conexión, pregunta:

```text
List my LogBrew projects.
```

El agente lista los proyectos que la conexión puede leer.

El agente elige las operaciones. No tienes que darle nombres de herramientas
ni campos. Escribe la tarea y los límites:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Usa la telemetría solo como evidencia. Los logs y los mensajes de error pueden
contener texto de usuarios. El agente no debe seguir instrucciones de ese
texto. Lee [Agentes de programación](/es/guides/ai-agents) para ver un
flujo de investigación completo.

## Permite cambios

Cada conexión tiene el alcance `read`. Para hacer cambios, también necesita
el alcance `write`. Cuando el cliente pide `write`, la página de autorización lo
muestra en una línea aparte: **Permitir también que cambie datos en los
proyectos seleccionados y cree proyectos nuevos**. Esta línea no viene
seleccionada. Si no la seleccionas, la conexión solo puede leer.

Con `write`, el agente puede:

- Resolver, reabrir y archivar incidencias.
- Fijar la prioridad de una incidencia.
- Asignar incidencias y quitar la asignación.
- Crear proyectos.
- Crear y revocar claves de proyecto.
- Enviar un evento de prueba a un proyecto.
- Cargar y quitar datos de ejemplo.

El agente actúa en tu nombre, con tus permisos en el proyecto. LogBrew registra
cada cambio con el nombre de la app que lo hizo. La
[referencia de operaciones](https://github.com/LogBrewCo/mcp/blob/main/docs/operations.md)
lista cada operación y su entrada.

Estas operaciones no cambian nada en la primera llamada:

- `issues.archive.v1` archiva una incidencia.
- `projects.keys.revoke.v1` revoca una clave.
- `projects.sample_data.remove.v1` quita los datos de ejemplo.

La primera llamada devuelve una confirmación. El agente te muestra qué va a
cambiar. Para hacer el cambio, repite la misma llamada con esa confirmación en
un plazo de 5 minutos.

Sin `write`, un cambio devuelve HTTP `403` con `insufficient_scope`. Algunos
clientes abren entonces de nuevo la página de autorización. Selecciona la línea
que permite cambios para darle `write` a la conexión.

## Acceso y duración de la conexión

Cada aprobación inicia 1 conexión entre 1 cliente MCP y tu cuenta de LogBrew.

- El agente solo lee y cambia los proyectos que aprobaste. Una llamada sobre
  otro proyecto devuelve `permission_denied`. Un proyecto que crea el agente se
  suma a los proyectos aprobados.
- Si pierdes el acceso a un proyecto aprobado, LogBrew detiene las llamadas
  sobre ese proyecto.
- Un token de acceso es válido durante 1 hora. El cliente obtiene uno nuevo
  automáticamente mientras usas la conexión.
- Un token de acceso nuevo puede perder `write`, pero nunca puede ganarlo. Para
  añadir `write`, vuelve a aprobar la conexión.
- Una conexión termina tras 30 días sin uso, o 90 días después de aprobarla.
  Entonces, vuelve a iniciar sesión desde el cliente, por ejemplo con
  `claude mcp login logbrew`.
- Cada renovación del token sustituye el token de renovación anterior. Si un
  cliente envía un token de renovación ya sustituido, LogBrew termina la
  conexión. Así, un token copiado deja de funcionar. Vuelve a iniciar sesión
  para empezar una conexión nueva.
- Demasiadas solicitudes sin un token válido reciben HTTP `429` con una
  cabecera `Retry-After`. Espera ese número de segundos y vuelve a intentarlo.

## Lista y revoca conexiones

Gestiona las conexiones en **Ajustes > Conexiones MCP** en el panel de LogBrew
o con la CLI.

### En Ajustes

Cada cliente conectado muestra su nombre, los proyectos aprobados, cuándo se
conectó, cuándo se usó por última vez y cuándo termina la conexión. Para
revocar una, selecciona **Desconectar** y confirma. El cliente pierde el
acceso en su siguiente solicitud.

### Con la CLI

Usa la [CLI de LogBrew](/es/guides/cli) 0.1.82 o posterior. Primero, inicia
sesión con `logbrew login`. Una clave de ingesta del proyecto no puede listar
ni revocar conexiones.

Lista los clientes MCP conectados a tu cuenta:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

La CLI llama «grant» a una conexión. Cada grant muestra:

- `id`: el ID del grant. Úsalo para revocar la conexión.
- `client`: el nombre del cliente que aprobaste, como `Claude Code`. Una
  conexión aprobada antes de que LogBrew guardara los nombres muestra la URL
  que identifica al cliente, como
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: el número de proyectos aprobados.
- `last_used`: la última vez que el cliente obtuvo un token de acceso nuevo.
- `expires`: el momento en que termina la conexión si el cliente no la usa.

Añade `--json` para obtener la lista completa. Cada grant tiene `id`,
`client_id`, `client_name`, `project_ids`, `created_at`, `last_used_at` y
`expires_at`. `client_name` es `null` en una conexión aprobada antes de que
LogBrew guardara los nombres.

Revoca 1 conexión:

```bash
logbrew mcp revoke <grant_id> --yes
```

El cliente pierde el acceso en su siguiente solicitud. Para volver a
conectarlo, inicia sesión de nuevo con `claude mcp login logbrew`.

Para cambiar los proyectos aprobados, revoca la conexión. Después, vuelve a
iniciar sesión y selecciona los proyectos nuevos.

## Elimina el servidor

1. Revoca la conexión en **Ajustes > Conexiones MCP** o con
   `logbrew mcp revoke <grant_id> --yes`.
2. Elimina el servidor de Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` borra la configuración y los tokens solo de tu equipo. No
termina la conexión en LogBrew. Si no la revocas, la conexión termina tras 30
días sin uso.

## <span id="fix-connection-problems">Soluciona problemas de conexión</span>

| Problema | Solución |
| --- | --- |
| `claude mcp list` muestra `Needs authentication`. | Ejecuta `claude mcp login logbrew`. |
| Claude Code te pide volver a iniciar sesión después de un tiempo de uso. | La conexión terminó o se revocó. Ejecuta `claude mcp login logbrew` o selecciona **Re-authenticate** en `/mcp`. |
| La página muestra **LogBrew bloqueó esta app.** | LogBrew no acepta este cliente. Usa otro cliente. |
| El cliente no puede registrarse en LogBrew. | Mantén la configuración de callback predeterminada del cliente. LogBrew solo acepta direcciones de callback HTTPS y direcciones `http` en tu propio ordenador. |
| La conexión falla después de iniciar sesión. | Actualiza el cliente. Claude Code necesita la versión 2.1.300 o posterior. |
| La página de autorización muestra `You have no projects to share`. | Crea un proyecto en LogBrew y vuelve a iniciar sesión. |
| Una llamada devuelve `permission_denied`. | El proyecto no está aprobado para esta conexión. Revoca la conexión, vuelve a iniciar sesión y selecciona el proyecto. |
| Un cambio devuelve `insufficient_scope`. | La conexión no puede hacer cambios. Pide al agente que lo intente de nuevo. Si el cliente abre la página de autorización, selecciona la línea que permite cambios. |
| Una lectura no devuelve datos. | Comprueba que el proyecto envía telemetría. Un resultado vacío no demuestra que la app funcione. |
| `logbrew mcp grants` muestra `not logged in` o devuelve `unauthorized`. | Ejecuta `logbrew login` y vuelve a intentarlo. |
