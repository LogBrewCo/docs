La interfaz de línea de comandos (CLI) de LogBrew lee logs, incidencias,
trazas y acciones desde una terminal. También puede actualizar el estado de una
incidencia. Usa `--json` para obtener salida estructurada para scripts y
agentes de IA.

Sustituye cada marcador de posición entre corchetes angulares antes de
ejecutar un comando. Usa los ID
de proyecto, incidencia y traza que devolvió LogBrew.

## Instala la CLI

Elige un método de instalación.

macOS o Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
```

Homebrew:

```bash
brew install LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install logbrew-cli
```

En Windows, también puedes instalar el MSI desde el
[último release](https://github.com/LogBrewCo/cli/releases/latest).

<Note>
  Cargo necesita Rust 1.87 o posterior. Los demás métodos instalan un binario
  nativo y no necesitan Rust.
</Note>

## Actualiza la CLI

La CLI no se actualiza sola. Usa el mismo método con el que la instalaste.

Homebrew:

```bash
brew update && brew upgrade LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install --locked logbrew-cli
```

Si usaste el instalador de shell o de PowerShell, vuelve a ejecutarlo.

Después, lee la versión. Compárala con el
[último release](https://github.com/LogBrewCo/cli/releases/latest):

```bash
logbrew version --json
```

El JSON incluye `ok`, `name`, `version`, `binary`, `os` y `arch`.

## Inicia sesión y comprueba la sesión

Lee la cuenta de la terminal actual:

```bash
logbrew status --json
logbrew whoami --json
```

Si `whoami` muestra la cuenta esperada, continúa. Si no, inicia sesión. Una
persona completa el inicio de sesión del proveedor en el navegador. Un agente
de programación debe pedirle a una persona que haga este paso.

```bash
logbrew login --provider github
```

El proveedor es `github` (predeterminado), `gitlab`, `bitbucket` o `google`. Usa
`--no-open` para imprimir la URL de inicio de sesión sin abrir un navegador.
`--json` también imprime los datos para completar el inicio de sesión sin
abrir un navegador.

Después de iniciar sesión, vuelve a ejecutar `status` y `whoami`. No pongas
credenciales de la cuenta en un prompt, un informe ni un archivo de código
fuente.

## Planifica la configuración del SDK

Ve al directorio que contiene el manifiesto de paquetes o de compilación de la
app. En un monorepo, elige una app o un servicio. Después, ejecuta:

```bash
logbrew setup --json
```

Lee `detected`, `install_ready`, `install_plan` y `next`. El plan indica el
runtime, el framework, el gestor de paquetes y el comando de instalación. La
CLI no instala paquetes ni cambia archivos. `logbrew init`, `install`,
`configure` y `sdk` dan el mismo plan.

<Warning>
  Pon una clave de ingesta del proyecto en la configuración del SDK. Nunca uses
  una credencial de la cuenta como clave del SDK. Mantén las claves de ingesta
  fuera del control de versiones.
</Warning>

Consulta [Integración del SDK](/es/guides/sdk-ingestion) para ver los
pasos de cada runtime. Ejecuta `logbrew examples` para ver una lista corta de
comandos habituales.

## Lee, crea y configura proyectos

Lista los proyectos activos de tu cuenta:

```bash
logbrew projects --json
```

Elige un ID de proyecto del resultado. Úsalo para las claves y las lecturas.

Para crear una clave de ingesta para un proyecto existente, elige un archivo
nuevo fuera del control de versiones. La CLI escribe la clave en ese archivo,
que solo puede leer su propietario. No imprime la clave ni la ruta del
archivo.

```bash
logbrew projects keys create "<project_id>" --ingest-key-file "<private_key_file>" --json
```

| Opción | Valor |
| --- | --- |
| `--kind` | `sdk` (predeterminado), `browser`, `server`, `cli` o `artifact`. Una clave `artifact` sube mapas de origen y archivos de depuración nativos. No puede enviar telemetría. |
| `--label` | Un nombre para la clave, de hasta 120 caracteres. El valor predeterminado es `CLI-created SDK key`. |

El resultado JSON tiene `status`, `project_id`, `ingest_key`, `checks` y
`next`. `ingest_key` contiene `id`, `label`, `kind`, `created_at` y
`expires_at` de la clave. Para sustituir una clave, consulta
[Rotar una clave de ingesta](/es/guides/rotate-ingest-key).

Este comando crea una credencial. Antes de ejecutarlo, comprueba que el
proyecto es el correcto. Si el resultado es dudoso, vuelve a ejecutar el mismo
comando. La CLI reutiliza entonces el intento pendiente. Usa
`--abandon-retry` solo para empezar un intento nuevo.

Para crear un proyecto nuevo, sigue el [Inicio rápido](/es/quickstart). Usa
`logbrew projects create "<name>" --ingest-key-file "<private_key_file>"`,
que guarda la primera clave de la misma forma. Ejecuta
`logbrew setup --create-project` para leer la ayuda sobre la creación de
proyectos. Ese comando no crea ningún proyecto.

Después de un paso de configuración, puedes registrarlo en el proyecto. El
valor de `--source` es `api`, `cli` o `sdk`:

```bash
logbrew projects setup "<project_id>" --source cli --environment production --json
```

Después, lee si el proyecto está listo:

```bash
logbrew doctor --project "<project_id>" --json
```

El código de salida `0` no significa que todas las comprobaciones pasaran. Lee
el `status` del informe y cada comprobación. Consulta la
[referencia del informe de doctor](/es/reference/cli#read-a-project-doctor-report).

## Lee el uso de la cuenta

Lee el uso y los límites. Esto no cambia el estado de la cuenta ni de la
facturación.

```bash
logbrew usage --json
```

`logbrew account usage --json` da el mismo resultado. La respuesta indica el
plan, el estado de la cuota, la fecha de reinicio, el uso total por proyecto y
por tipo de telemetría, y un siguiente paso. Los campos incluyen `plan`,
`state`, `reset_at`, `by_project`, `by_stream` y `next`.

## Investigaciones habituales

Filtra cada lectura por proyecto. Añade filtros de release, entorno, tiempo o
severidad cuando el comando los admita. Consulta
[Filtros](/es/reference/cli#filters).

## Observa los eventos en vivo

Usa watch para ver eventos nuevos mientras pruebas un cambio. Pulsa Ctrl+C
para detenerlo.

```bash
logbrew watch --severity error,critical --json
```

Watch solo transmite JSON. Sin `--json`, el comando se detiene con un error.
Añade `logs`, `issues` o `actions` para seguir un solo tipo, como
`logbrew watch logs --json`. Watch no admite trazas ni spans.

Watch no tiene filtro de proyecto, release ni entorno. Para un solo proyecto,
usa las lecturas anteriores. Consulta
[Observación en vivo](/es/reference/cli#live-watch) para ver los recursos y
filtros admitidos.

## Entiende el problema antes de cambiar el código

Lee el contexto antes de proponer una corrección.

<Steps>
  <Step title="Lee la incidencia">
    ```bash
    logbrew read issue "<issue_id>" --json
    ```
  </Step>

  <Step title="Lee la traza">
    Haz este paso solo si la incidencia tiene un ID de traza. Una incidencia
    sin traza sigue siendo válida.

    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Step>

  <Step title="Lee la explicación">
    ```bash
    logbrew explain issue "<issue_id>" --json
    ```

    Para un log, usa `logbrew explain log "<log_id>" --json`. Para una acción,
    usa `logbrew explain action "<action_id>" --json`.
  </Step>

  <Step title="Resuelve después de verificar">
    ```bash
    logbrew set issue "<issue_id>" resolved --json
    ```

    Para cambiar el estado, la prioridad o el responsable de muchas
    incidencias, consulta
    [Cambia el estado y la prioridad de una incidencia](/es/reference/cli#change-issue-status-and-priority)
    y [Gestionar incidencias](/es/guides/issue-workflow).
  </Step>
</Steps>

## Salida JSON

- Pon `--json` antes o después del comando, como `logbrew --json status` o
  `logbrew status --json`.
- Lee el código de salida antes de usar la salida.
- Los errores JSON tienen `ok`, `error`, `message` y `next`. Un tiempo de
  espera agotado no demuestra que una escritura fallara. Antes de repetir una
  escritura, lee sus reglas de reintento.
- No automatices con salida sin `--json`. Puede cambiar.

Consulta [Lee resultados y errores](/es/reference/cli#read-results-and-errors)
para ver los códigos de salida y ejemplos de errores.
