تقرأ واجهة سطر الأوامر (CLI) في LogBrew السجلات والمشكلات والتتبّعات والإجراءات
من الطرفية. ويمكنها أيضًا تحديث حالة المشكلة. استخدم `--json` للحصول على مخرجات
منظّمة تناسب البرامج النصية ووكلاء الذكاء الاصطناعي.

استبدل كل عنصر نائب بين قوسين زاويين قبل أن تشغّل أي أمر. استخدم معرّفات
المشاريع والمشكلات والتتبّعات التي أرجعها LogBrew.

## <span id="install-the-cli">تثبيت CLI</span>

اختر طريقة تثبيت واحدة.

macOS أو Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
```

Homebrew:

```bash
brew install LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install logbrew-cli
```

على Windows، يمكنك أيضًا تثبيت ملف MSI من
[أحدث إصدار](https://github.com/LogBrewCo/cli/releases/latest).

<Note>
  يحتاج Cargo إلى Rust 1.87 أو أحدث. أما الطرق الأخرى فتثبّت ملفًا تنفيذيًا أصليًا
  ولا تحتاج إلى Rust.
</Note>

## <span id="update-the-cli">تحديث CLI</span>

لا يحدّث CLI نفسه تلقائيًا. استخدم الطريقة نفسها التي ثبّتها بها.

Homebrew:

```bash
brew update && brew upgrade LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install --locked logbrew-cli
```

إذا ثبّتها بمثبّت الصدفة (shell) أو PowerShell، فشغّل المثبّت مرة أخرى.

ثم اقرأ رقم النسخة، وقارنه مع
[أحدث إصدار](https://github.com/LogBrewCo/cli/releases/latest):

```bash
logbrew version --json
```

يعرض JSON الحقول `ok` و`name` و`version` و`binary` و`os` و`arch`.

## <span id="sign-in-and-verify-the-session">تسجيل الدخول والتحقق من الجلسة</span>

اقرأ الحساب المستخدم في الطرفية الحالية:

```bash
logbrew status --json
logbrew whoami --json
```

إذا أظهر `whoami` الحساب المتوقع، فتابع. وإلا، فسجّل الدخول. يُكمل شخص تسجيل
الدخول لدى المزوّد في المتصفح. ويجب على وكيل البرمجة أن يطلب من شخص تنفيذ هذه
الخطوة.

```bash
logbrew login --provider github
```

المزوّد هو `github` (الافتراضي) أو `gitlab` أو `bitbucket` أو `google`. استخدم `--no-open`
لطباعة رابط تسجيل الدخول دون فتح المتصفح. ويطبع `--json` أيضًا بيانات تسليم
تسجيل الدخول دون فتح المتصفح.

بعد تسجيل الدخول، شغّل `status` و`whoami` مرة أخرى. لا تضع بيانات اعتماد الحساب
في موجّه (prompt) أو تقرير أو ملف مصدري.

## <span id="plan-sdk-setup">التخطيط لإعداد SDK</span>

انتقل إلى المجلد الذي يحتوي على ملف الحزمة أو ملف البناء الخاص بالتطبيق. في
المستودع الموحّد (monorepo)، اختر تطبيقًا واحدًا أو خدمة واحدة. ثم شغّل:

```bash
logbrew setup --json
```

اقرأ `detected` و`install_ready` و`install_plan` و`next`. تحدد الخطة بيئة
التشغيل وإطار العمل ومدير الحزم وأمر التثبيت. لا يثبّت CLI أي حزم ولا يغيّر أي
ملفات. وتعطي الأوامر `logbrew init` و`install` و`configure` و`sdk` الخطة نفسها.

<Warning>
  ضع مفتاح استيعاب المشروع في إعدادات الـ SDK. لا تستخدم أبدًا بيانات اعتماد
  الحساب مفتاحًا للـ SDK. وأبقِ مفاتيح الاستيعاب خارج نظام إدارة الشيفرة المصدرية.
</Warning>

راجع [دمج SDK](/ar/guides/sdk-ingestion) لمعرفة الخطوات
الخاصة بكل بيئة تشغيل. شغّل `logbrew examples` لعرض قائمة قصيرة بالأوامر الشائعة.

## <span id="read-create-and-configure-projects">قراءة المشاريع وإنشاؤها وإعدادها</span>

اعرض المشاريع النشطة في حسابك:

```bash
logbrew projects --json
```

اختر معرّف مشروع من النتيجة، واستخدمه للمفاتيح والقراءات.

لإنشاء مفتاح استيعاب لمشروع موجود، اختر ملفًا جديدًا خارج نظام إدارة الشيفرة
المصدرية. يكتب CLI المفتاح في هذا الملف الذي لا يقرؤه إلا مالكه. ولا يطبع
المفتاح أو مسار الملف.

```bash
logbrew projects keys create "<project_id>" --ingest-key-file "<private_key_file>" --json
```

| الخيار | القيمة |
| --- | --- |
| `--kind` | `sdk` (الافتراضي) أو `browser` أو `server` أو `cli` أو `artifact`. يرفع مفتاح `artifact` خرائط المصدر وملفات التصحيح الأصلية، ولا يمكنه إرسال بيانات القياس. |
| `--label` | اسم للمفتاح، حتى 120 حرفًا. القيمة الافتراضية هي `CLI-created SDK key`. |

تحتوي نتيجة JSON على `status` و`project_id` و`ingest_key` و`checks` و`next`.
ويحتوي `ingest_key` على `id` و`label` و`kind` و`created_at` و`expires_at`
الخاصة بالمفتاح. لاستبدال مفتاح، راجع [تدوير مفتاح الاستيعاب](/ar/guides/rotate-ingest-key).

ينشئ هذا الأمر بيانات اعتماد. قبل أن تشغّله، تأكد من أن المشروع صحيح. إذا لم
تكن النتيجة مؤكدة، فشغّل الأمر نفسه مرة أخرى. سيعيد CLI حينها استخدام المحاولة
المعلّقة. استخدم `--abandon-retry` فقط لبدء محاولة جديدة.

لإنشاء مشروع جديد، اتبع [البدء السريع](/ar/quickstart). يستخدم
`logbrew projects create "<name>" --ingest-key-file "<private_key_file>"`،
الذي يخزّن المفتاح الأول بالطريقة نفسها. شغّل `logbrew setup --create-project`
لقراءة تعليمات إنشاء المشروع. هذا الأمر لا ينشئ مشروعًا.

بعد أي خطوة إعداد، يمكنك تسجيلها للمشروع. قيمة `--source` هي `api` أو `cli` أو
`sdk`:

```bash
logbrew projects setup "<project_id>" --source cli --environment production --json
```

ثم اقرأ جاهزية المشروع:

```bash
logbrew doctor --project "<project_id>" --json
```

رمز الخروج `0` لا يعني أن كل الفحوص نجحت. اقرأ `status` في التقرير وكل فحص على
حدة. راجع [مرجع تقرير التشخيص](/ar/reference/cli#read-a-project-doctor-report).

## <span id="read-account-usage">قراءة استخدام الحساب</span>

اقرأ الاستخدام والحدود. هذا لا يغيّر حالة الحساب أو الفوترة.

```bash
logbrew usage --json
```

يعطي `logbrew account usage --json` النتيجة نفسها. تعرض الاستجابة الخطة، وحالة
الحصة، وتاريخ إعادة التعيين، وإجمالي الاستخدام حسب المشروع وحسب نوع بيانات
القياس، والخطوة التالية. تشمل الحقول `plan` و`state` و`reset_at` و`by_project`
و`by_stream` و`next`.

## <span id="watch-live-events">مشاهدة الأحداث المباشرة</span>

استخدم watch لرؤية الأحداث الجديدة أثناء اختبار تغيير ما. اضغط Ctrl+C للإيقاف.

```bash
logbrew watch --severity error,critical --json
```

يبث watch مخرجات JSON فقط. ومن دون `--json`، يتوقف الأمر مع خطأ. أضف `logs` أو
`issues` أو `actions` لمشاهدة نوع واحد، مثل `logbrew watch logs --json`. لا يدعم
watch التتبّعات أو الـ Spans.

لا يحتوي watch على عامل تصفية للمشروع أو الإصدار أو البيئة. لمشروع واحد، استخدم
القراءات السابقة. راجع [المتابعة المباشرة](/ar/reference/cli#live-watch) لمعرفة الموارد
وعوامل التصفية المدعومة.

## <span id="explain-before-you-change-code">افهم المشكلة قبل تغيير الشيفرة</span>

اقرأ السياق قبل أن تقترح إصلاحًا.

<Steps>
  <Step title="قراءة المشكلة">
    ```bash
    logbrew read issue "<issue_id>" --json
    ```
  </Step>

  <Step title="قراءة التتبّع">
    نفّذ هذه الخطوة فقط إذا كان للمشكلة معرّف تتبّع. المشكلة التي ليس لها تتبّع
    تظل صالحة.

    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Step>

  <Step title="قراءة الشرح">
    ```bash
    logbrew explain issue "<issue_id>" --json
    ```

    للسجل، استخدم `logbrew explain log "<log_id>" --json`. وللإجراء، استخدم
    `logbrew explain action "<action_id>" --json`.
  </Step>

  <Step title="الحلّ بعد التحقق">
    ```bash
    logbrew set issue "<issue_id>" resolved --json
    ```

    لتغيير الحالة أو الأولوية أو المسؤول لعدد كبير من المشكلات، راجع
    [تغيير حالة المشكلة وأولويتها](/ar/reference/cli#change-issue-status-and-priority)
    و[إدارة المشكلات](/ar/guides/issue-workflow).
  </Step>
</Steps>

## <span id="json-output">مخرجات JSON</span>

- ضع `--json` قبل الأمر أو بعده، مثل `logbrew --json status` أو
  `logbrew status --json`.
- اقرأ رمز الخروج قبل أن تستخدم المخرجات.
- تحتوي أخطاء JSON على `ok` و`error` و`message` و`next`. انتهاء المهلة لا يثبت
  أن عملية الكتابة فشلت. قبل أن تكرر عملية كتابة، اقرأ قواعد إعادة المحاولة الخاصة
  بها.
- لا تعتمد في الأتمتة على مخرجات من دون `--json`، فقد تتغير.

راجع [قراءة النتائج والأخطاء](/ar/reference/cli#read-results-and-errors) لمعرفة رموز
الخروج وأمثلة الأخطاء.
