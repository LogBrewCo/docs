LogBrew CLI (antarmuka baris perintah) membaca log, masalah, trace, dan aksi
dari terminal. CLI juga dapat memperbarui status masalah. Gunakan `--json`
untuk output terstruktur bagi skrip dan agen AI.

Ganti setiap placeholder dalam kurung sudut sebelum menjalankan perintah.
Gunakan ID proyek, masalah, dan trace yang dikembalikan LogBrew.

## Instal CLI

Pilih satu metode instalasi.

macOS atau Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/LogBrewCo/cli/releases/latest/download/logbrew-cli-installer.ps1 | iex"
```

Homebrew:

```bash
brew install LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install logbrew-cli
```

Di Windows, Anda juga dapat menginstal MSI dari
[rilis terbaru](https://github.com/LogBrewCo/cli/releases/latest).

<Note>
  Cargo memerlukan Rust 1.87 atau yang lebih baru. Metode lain menginstal
  biner native dan tidak memerlukan Rust.
</Note>

## Perbarui CLI

CLI tidak memperbarui dirinya sendiri. Gunakan metode yang sama dengan saat
Anda menginstalnya.

Homebrew:

```bash
brew update && brew upgrade LogBrewCo/tap/logbrew
```

npm:

```bash
npm install -g logbrew-cli@latest
```

Cargo:

```bash
cargo install --locked logbrew-cli
```

Jika Anda memakai installer shell atau PowerShell, jalankan installer itu
lagi.

Lalu baca versinya. Bandingkan dengan
[rilis terbaru](https://github.com/LogBrewCo/cli/releases/latest):

```bash
logbrew version --json
```

JSON-nya berisi `ok`, `name`, `version`, `binary`, `os`, dan `arch`.

## Masuk dan verifikasi sesi

Baca akun untuk terminal saat ini:

```bash
logbrew status --json
logbrew whoami --json
```

Jika `whoami` menampilkan akun yang diharapkan, lanjutkan. Jika tidak, masuk
terlebih dahulu. Manusia menyelesaikan login penyedia di browser. Agen coding
wajib meminta manusia melakukan langkah ini.

```bash
logbrew login --provider github
```

Penyedianya adalah `github` (default), `gitlab`, `bitbucket`, atau `google`. Gunakan
`--no-open` untuk mencetak URL login tanpa membuka browser. `--json` juga
mencetak data handoff login tanpa membuka browser.

Setelah login, jalankan `status` dan `whoami` lagi. Jangan masukkan kredensial
akun ke prompt, laporan, atau file sumber.

## Rencanakan penyiapan SDK

Pindah ke direktori yang berisi manifes paket atau manifes build aplikasi. Di
monorepo, pilih satu aplikasi atau layanan. Lalu jalankan:

```bash
logbrew setup --json
```

Baca `detected`, `install_ready`, `install_plan`, dan `next`. Rencana ini
berisi runtime, framework, package manager, dan perintah instalasi. CLI tidak
menginstal paket atau mengubah file. `logbrew init`, `install`, `configure`,
dan `sdk` memberikan rencana yang sama.

<Warning>
  Masukkan kunci ingest proyek ke konfigurasi SDK. Jangan pernah memakai
  kredensial akun sebagai kunci SDK. Jangan simpan kunci ingest di source
  control.
</Warning>

Lihat panduan [Integrasi SDK](/id/guides/sdk-ingestion) untuk langkah khusus
setiap runtime. Jalankan `logbrew examples` untuk melihat daftar singkat
perintah umum.

## Baca, buat, dan konfigurasikan proyek

Tampilkan daftar proyek aktif di akun Anda:

```bash
logbrew projects --json
```

Pilih ID proyek dari hasilnya. Gunakan ID itu untuk kunci dan pembacaan data.

Untuk membuat kunci ingest bagi proyek yang sudah ada, pilih file baru di luar
source control. CLI menulis kunci ke file itu, yang hanya dapat diakses
pemiliknya. CLI tidak mencetak kunci atau path file-nya.

```bash
logbrew projects keys create "<project_id>" --ingest-key-file "<private_key_file>" --json
```

| Flag | Nilai |
| --- | --- |
| `--kind` | `sdk` (default), `browser`, `server`, `cli`, atau `artifact`. Kunci `artifact` mengunggah source map dan file debug native. Kunci ini tidak dapat mengirim telemetri. |
| `--label` | Nama kunci, maksimal 120 karakter. Nilai default-nya `CLI-created SDK key`. |

Hasil JSON berisi `status`, `project_id`, `ingest_key`, `checks`, dan `next`.
`ingest_key` berisi `id`, `label`, `kind`, `created_at`, dan `expires_at` dari
kunci tersebut. Untuk mengganti kunci, lihat
[Rotasikan kunci ingest](/id/guides/rotate-ingest-key).

Perintah ini membuat kredensial. Sebelum menjalankannya, pastikan proyeknya
benar. Jika hasilnya tidak pasti, jalankan perintah yang sama lagi. CLI lalu
memakai ulang percobaan yang masih tertunda. Gunakan `--abandon-retry` hanya
untuk memulai percobaan baru.

Untuk membuat proyek baru, ikuti panduan [Mulai cepat](/id/quickstart). Panduan itu
memakai
`logbrew projects create "<name>" --ingest-key-file "<private_key_file>"`,
yang menyimpan kunci pertama dengan cara yang sama. Jalankan
`logbrew setup --create-project` untuk membaca bantuan pembuatan proyek.
Perintah itu tidak membuat proyek.

Setelah menyelesaikan satu langkah penyiapan, Anda dapat mencatatnya untuk
proyek. Nilai `--source` adalah `api`, `cli`, atau `sdk`:

```bash
logbrew projects setup "<project_id>" --source cli --environment production --json
```

Lalu baca kesiapan proyek:

```bash
logbrew doctor --project "<project_id>" --json
```

Kode keluar `0` tidak berarti semua pemeriksaan lolos. Baca `status` laporan
dan setiap pemeriksaan. Lihat
[Baca laporan doctor proyek](/id/reference/cli#read-a-project-doctor-report).

## Baca penggunaan akun

Baca penggunaan dan batas. Perintah ini tidak mengubah status akun atau
penagihan.

```bash
logbrew usage --json
```

`logbrew account usage --json` memberikan hasil yang sama. Respons berisi
paket, status kuota, tanggal reset, total penggunaan per proyek dan per jenis
telemetri, serta langkah berikutnya. Kolomnya meliputi `plan`, `state`,
`reset_at`, `by_project`, `by_stream`, dan `next`.

## Investigasi umum

Filter setiap pembacaan menurut proyek. Tambahkan filter rilis, lingkungan,
waktu, atau tingkat keparahan jika perintahnya mendukung. Lihat
[Filter](/id/reference/cli#filters).

  <Card title="Masalah dalam satu rilis" icon="tag">

  <Card title="Satu permintaan yang gagal" icon="route">

## Pantau peristiwa langsung

Gunakan perintah watch untuk melihat peristiwa baru saat Anda menguji
perubahan. Tekan Ctrl+C untuk berhenti.

```bash
logbrew watch --severity error,critical --json
```

Perintah watch hanya men-stream JSON. Tanpa `--json`, perintah berhenti dengan
error. Tambahkan `logs`, `issues`, atau `actions` untuk memantau satu jenis
saja, misalnya `logbrew watch logs --json`. Perintah watch tidak mendukung
trace atau span.

Perintah watch tidak punya filter proyek, rilis, atau lingkungan. Untuk satu
proyek, gunakan perintah baca di atas. Lihat
[Pantauan langsung](/id/reference/cli#live-watch) untuk resource dan filter
yang didukung.

## Minta penjelasan sebelum mengubah kode

Baca konteksnya sebelum mengusulkan perbaikan.

<Steps>
  <Step title="Baca masalah">
    ```bash
    logbrew read issue "<issue_id>" --json
    ```
  </Step>

  <Step title="Baca trace">
    Lakukan langkah ini hanya jika masalah memiliki ID trace. Masalah tanpa
    trace tetap valid.

    ```bash
    logbrew read trace "<trace_id>" --project "<project_id>" --json
    ```
  </Step>

  <Step title="Baca penjelasan">
    ```bash
    logbrew explain issue "<issue_id>" --json
    ```

    Untuk log, gunakan `logbrew explain log "<log_id>" --json`. Untuk aksi,
    gunakan `logbrew explain action "<action_id>" --json`.
  </Step>

  <Step title="Selesaikan setelah verifikasi">
    ```bash
    logbrew set issue "<issue_id>" resolved --json
    ```

    Untuk mengubah status, prioritas, atau penanggung jawab banyak masalah,
    lihat
    [Ubah status dan prioritas masalah](/id/reference/cli#change-issue-status-and-priority)
    dan panduan [Kelola masalah](/id/guides/issue-workflow).
  </Step>
</Steps>

## Output JSON

- Letakkan `--json` sebelum atau sesudah perintah, misalnya
  `logbrew --json status` atau `logbrew status --json`.
- Baca kode keluar sebelum memakai output-nya.
- Error JSON berisi `ok`, `error`, `message`, dan `next`. Timeout tidak
  membuktikan bahwa operasi tulis gagal. Sebelum mengulang operasi tulis, baca
  aturan percobaan ulangnya.
- Jangan membuat otomatisasi dengan output tanpa `--json`. Output itu dapat
  berubah.

Lihat [Baca hasil dan error](/id/reference/cli#read-results-and-errors) untuk
kode keluar dan contoh error.
