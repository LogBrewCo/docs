Gunakan API akun untuk membaca penggunaan, status kuota, riwayat penggunaan,
dan kesiapan langganan, serta untuk keluar. Pembacaan akun memakai bearer
akun atau sesi browser. Jangan pernah memakai kunci ingest proyek untuk
permintaan akun. Jangan pernah memakai kredensial akun sebagai konfigurasi SDK
atau ingest.

| Tugas | Endpoint |
| --- | --- |
| Baca penggunaan dan status kuota saat ini | `GET /api/account/usage` |
| Baca penggunaan dari waktu ke waktu | `GET /api/account/usage/history` |
| Baca kesiapan langganan dan organisasi | `GET /api/account/subscription` |
| Baca paket dan kuotanya | `GET /api/billing/catalog` |
| Baca daftar undangan organisasi yang dikirim kepada Anda | `GET /api/account/invitations` |
| Baca satu undangan yang dikirim kepada Anda | `GET /api/organizations/{organization_id}/invitations/{invitation_id}` |
| Keluarkan satu login aplikasi atau CLI | `POST /api/auth/logout` |
| Cabut semua login LogBrew | `POST /api/auth/logout-all` |
| Hapus sesi browser | `POST /api/auth/web/logout` |

Error memakai [envelope error API](/id/reference/api-errors) standar.
Pembacaan tanpa autentikasi akun yang valid mengembalikan `401` dengan
`code: "unauthorized"`. Jangan tampilkan kegagalan itu sebagai penggunaan
nol, grafik kosong, atau paket gratis. Metode yang tidak didukung
mengembalikan `405` dengan `code: "method_not_allowed"`, dan `next`
menyebutkan permintaan yang didukung.

API akun melaporkan penggunaan telemetri, bukan uang. API ini tidak
melaporkan biaya, faktur, atau status pembayaran.

## <span id="account-usage">Penggunaan akun</span>

`GET /api/account/usage` adalah endpoint kanonis untuk penggunaan dan kuota.
Gunakan endpoint ini untuk total penggunaan, waktu reset, status kuota, serta
rincian per proyek dan per stream telemetri. Jangan menghitung penggunaan dari
file SDK, file CLI, atau penghitung di klien. Perintah CLI `logbrew usage`
membaca endpoint ini. Lihat [Referensi CLI](/id/reference/cli).

```bash
curl "https://api.logbrew.co/api/account/usage" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

Contoh respons dengan nilai sintetis. Akun gratis ini punya 1 proyek dan hanya
mengirim log pada periode saat ini:

```json
{
  "period_start": "2026-06-01T00:00:00Z",
  "period_end": "2026-07-01T00:00:00Z",
  "reset_at": "2026-07-01T00:00:00Z",
  "plan": { "tier": "free", "status": "free" },
  "limits": { "events": null, "bytes": null, "projects": null, "retention_days": 30 },
  "usage": { "events": 27000, "bytes": 10485760, "projects": 1 },
  "state": "ok",
  "warning_threshold": 0.8,
  "percent_used": 0.02,
  "warning": false,
  "blocked": false,
  "limit": null,
  "next": "continue sending telemetry",
  "next_action": {
    "code": "continue_sending_telemetry",
    "target": "telemetry_ingest",
    "state": "ok",
    "limit": null,
    "reset_at": "2026-07-01T00:00:00Z"
  },
  "by_project": [
    { "project_id": "00000000-0000-4000-8000-000000000001", "events": 27000, "bytes": 10485760 }
  ],
  "by_stream": [
    { "kind": "logs", "events": 27000, "bytes": 10485760 }
  ]
}
```

| Kolom | Arti |
| --- | --- |
| `period_start`, `period_end` | Periode penggunaan saat ini. Akhir periode bersifat eksklusif. |
| `reset_at` | Waktu kuota penggunaan direset. Nilainya sama dengan `period_end`. |
| `plan.tier` | Pengenal paket: `free`, `pro`, atau `scale`. |
| `plan.status` | `free`, `trial`, `active`, `past_due`, atau `disabled`. |
| `limits.events`, `limits.bytes`, `limits.projects` | Kolom kompatibilitas. Nilainya `null`. `null` tidak berarti tanpa batas. Gunakan `state`, `limit`, dan `percent_used` untuk status kuota. |
| `limits.retention_days` | Retensi data akun, dalam hari. Nilainya yang lebih besar antara paket dan penawaran untuk akun baru yang aktif. Nilainya `null` untuk paket Enterprise, yang retensinya ditetapkan kontrak. Lihat [Retensi data](#data-retention). |
| `usage.events`, `usage.bytes` | Total untuk semua stream telemetri dalam periode ini. |
| `usage.projects` | Jumlah proyek yang dimiliki akun. |
| `state` | `ok`, `warning`, atau `blocked`. |
| `warning_threshold` | Bagian kuota yang memicu status `warning`, dalam bentuk pecahan. |
| `percent_used` | Bagian tertinggi dari kuota mana pun, dalam persen. Misalnya, `80` berarti 80%. |
| `warning`, `blocked` | Bentuk kompatibilitas dari `state`. |
| `limit` | Kuota yang menyebabkan status tersebut: `events`, `bytes`, atau `null`. |
| `next`, `next_action` | Teks pemulihan dan tindakan bertipe untuk status saat ini. |
| `by_project` | Penggunaan per proyek. Ada 1 baris untuk setiap proyek yang dimiliki, termasuk saat penggunaannya nol. Cocokkan baris berdasarkan `project_id`, bukan posisi di array. |
| `by_stream` | Penggunaan per `kind` stream telemetri, seperti `logs`, `issues`, `actions`, atau `traces`. |

### Peristiwa yang dibuang SDK

Kirim `response_version=2` agar juga menerima `sdk_dropped_events`. Tanpa parameter ini, atau dengan `response_version=1`, respons tidak berisi kolom ini.

```bash
curl "https://api.logbrew.co/api/account/usage?response_version=2" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

`sdk_dropped_events` mencantumkan peristiwa yang dilaporkan SDK sebagai dibuang sebelum dikirim pada periode saat ini, misalnya karena antrean klien penuh. Ada 1 baris untuk setiap proyek dan alasan:

```json
{
  "sdk_dropped_events": [
    { "project_id": "00000000-0000-4000-8000-000000000001", "reason": "queue_overflow", "events": 12 }
  ]
}
```

| Kolom | Arti |
| --- | --- |
| `project_id` | Proyek yang SDK-nya membuang peristiwa. |
| `reason` | Kode alasan yang dikirim SDK, seperti `queue_overflow`. |
| `events` | Jumlah peristiwa yang dibuang. |

Peristiwa yang dibuang tidak pernah sampai ke LogBrew. Peristiwa ini tidak ditagih dan tidak dihitung dalam `usage`, `by_project`, atau `by_stream`. Array kosong jika tidak ada SDK yang melaporkan peristiwa yang dibuang.

Array ini juga menghitung record OTLP yang ditolak LogBrew, dengan alasan `otlp_rejected_record`, atau `usage_limit_exceeded` saat batas paket tercapai. Record ini sudah sampai ke LogBrew, tetapi LogBrew tidak menyimpannya. Record ini tidak ditagih. Lihat [OpenTelemetry (OTLP)](/id/guides/opentelemetry).

### <span id="new-account-offer">Penawaran untuk akun baru</span>

Akun yang dibuat sebelum 2026-10-26 mendapat kuota Pro gratis selama 6 bulan, dihitung sejak pendaftaran, atau sejak 2026-10-22 untuk akun yang sudah ada saat itu. Akun yang lebih baru mulai dengan paket Free dan tidak mendapat penawaran ini. Kirim `response_version=3` untuk mendapatkan `offer` juga. Versi 1 dan 2 tidak memiliki kolom ini. Versi 3 juga memiliki `sdk_dropped_events`.

```bash
curl "https://api.logbrew.co/api/account/usage?response_version=3" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

`offer` bernilai `null` jika tidak ada penawaran yang aktif. Jika ada, isinya memiliki kolom berikut:

```json
{
  "offer": {
    "kind": "public_beta",
    "tier": "team",
    "starts_at": "2026-10-22T00:00:00Z",
    "ends_at": "2027-04-22T00:00:00Z"
  }
}
```

| Kolom | Arti |
| --- | --- |
| `kind` | Alasan kuota berlaku. Nilainya `public_beta`. |
| `tier` | Paket yang kuotanya berlaku. `team` adalah paket Pro. |
| `starts_at`, `ends_at` | Periode penawaran. Akhir periode bersifat eksklusif. |

Selama penawaran aktif, `limits.retention_days`, `state`, `limit`, `percent_used`, dan `next_action` memakai kuota yang lebih besar antara paket milik akun dan penawaran. `plan` tetap menampilkan paket milik akun. Setelah `ends_at`, akun kembali memakai paketnya sendiri. Versi 1 dan 2 mengikuti kuota yang sama, tetapi tidak menampilkan penawaran. Ringkasan penagihan `GET /api/billing/overview` memiliki kolom `offer` yang sama.

### Status kuota

Gunakan `state` untuk percabangan utama. `limit` bernilai `null` hanya jika
`state` bernilai `ok`.

| `state` | `warning` | `blocked` | `limit` | `next_action.code` | `next_action.target` |
| --- | --- | --- | --- | --- | --- |
| `ok` | `false` | `false` | `null` | `continue_sending_telemetry` | `telemetry_ingest` |
| `warning` | `true` | `false` | `events` atau `bytes` | `reduce_usage_or_upgrade` | `pricing` |
| `blocked` | `false` | `true` | `events` atau `bytes` | `wait_until_reset_or_upgrade` | `pricing` |

Tabel ini berlaku untuk versi 2 dan 3. Versi 1, yang default, punya 2 perbedaan:
`warning` juga `true` pada status `blocked`, dan pada status `warning`,
`next_action.target` adalah `account_usage`.

`next_action.state`, `next_action.limit`, dan `next_action.reset_at`
mengulang nilai di tingkat teratas. Nilai `next_action.code` juga mencakup
`check_usage_limits` dengan target `account_usage`. Jika klien menerima
pasangan itu, baca penggunaan lagi dan tampilkan `next`.

LogBrew mengukur setiap jenis telemetri terhadap kuotanya sendiri. `limit`
mengelompokkannya:

- `events` mencakup peristiwa masalah dan span trace.
- `bytes` mencakup byte log dan byte metrik.

Jika satu kuota diblokir dan kuota lain dalam status peringatan, `limit`
menyebutkan kuota yang diblokir. Status `warning` dimulai saat penggunaan
mencapai `warning_threshold` dari suatu kuota. Status `blocked` dimulai saat
penggunaan mencapai kuota.

Teks `next` bisa berubah, misalnya saat paket tidak dijual. Nilai
`next_action` tidak berubah. Buat teks terjemahan berdasarkan `next_action`.
Jangan mem-parse `next`.

Batas penggunaan akun bukan batas laju API. Saat ingest melebihi kuota,
permintaan ingest mengembalikan `429` dengan `usage_limit_exceeded`, dan body
menambahkan `limit` dan `reset_at`. Dalam error itu, `limit` menyebutkan kuota
yang tepat: `issue_events`, `log_bytes`, `metric_bytes`, atau `trace_spans`.
LogBrew menolak seluruh permintaan. Jangan kirim jenis telemetri itu lagi
sampai `reset_at` atau sampai paket berubah. Saat klien mengirim terlalu
banyak permintaan, API mengembalikan `rate_limited`. Lihat
[Error API](/id/reference/api-errors#retry-rules).

Respons ini adalah snapshot. Baca lagi setelah akun berubah.

<Note>
  `GET /api/logs/usage` adalah respons kompatibilitas lama untuk aplikasi
  seluler, dengan `bytes_used`, `limit_bytes`, dan `month`. Gunakan
  `GET /api/account/usage` untuk integrasi baru.
</Note>

## Riwayat penggunaan

`GET /api/account/usage/history` mengembalikan interval waktu penggunaan
dalam jumlah terbatas untuk grafik dan laporan. Interval waktu tanpa
penggunaan bernilai nol. Isi `interval` dengan salah satu nilai yang didukung.
Jika Anda tidak mengisi `interval`, API memakai `monthly`. Rute ini tidak
menerima kunci kueri lain.

```bash
curl --get "https://api.logbrew.co/api/account/usage/history" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER" \
  --data-urlencode "interval=daily"
```

| `interval` | Jumlah interval waktu | Awal interval waktu |
| --- | ---: | --- |
| `daily` | 30 | 00:00 UTC |
| `weekly` | 12 | Senin, 00:00 UTC |
| `monthly` | 12 | Hari pertama setiap bulan, 00:00 UTC |
| `yearly` | 5 | 1 Januari, 00:00 UTC |

| Kolom | Arti |
| --- | --- |
| `interval` | Interval yang diminta. |
| `period_start`, `period_end` | Awal dan akhir eksklusif dari rentang waktu riwayat. |
| `current` | Respons `GET /api/account/usage` lengkap untuk periode saat ini, pada versi 3. Respons ini selalu memuat `sdk_dropped_events` dan `offer`. |
| `buckets` | Interval waktu sesuai urutan waktu, yang terlama lebih dulu. Setiap interval waktu punya `period_start`, `period_end`, `usage`, `by_project`, dan `by_stream`. |

Respons `yearly` ini memakai data sintetis untuk permintaan pada Juni 2026.
Semua penggunaan terjadi pada bulan Juni:

    }

Gunakan `current.reset_at` untuk waktu reset kuota. Jangan pakai akhir rentang
waktu riwayat. `current` bukan jumlah dari semua interval waktu, dan
tanggalnya bisa berbeda dari tanggal rentang waktu riwayat.

Interval waktu terakhir berisi periode kalender saat ini, yang belum lengkap.
Waktu akhirnya yang ada di masa depan tidak berarti LogBrew mengukur
penggunaan di masa depan. Interval waktu yang berisi nol berarti LogBrew tidak
mencatat penggunaan apa pun di interval itu.

Di dalam satu interval waktu, `usage.projects` menghitung proyek yang punya
penggunaan di interval itu. Jangan jumlahkan angka ini untuk mendapatkan
jumlah proyek. Gunakan `current.usage.projects` untuk jumlah proyek yang
dimiliki.

Tampilkan peristiwa dan byte sebagai deret terpisah di grafik, karena
satuannya berbeda. Interval waktu berisi penggunaan, bukan biaya. Jangan beri
grafik label pengeluaran, faktur, atau permintaan API.

Interval yang tidak didukung mengembalikan `422`:

```json
{
  "error": "Unsupported usage history interval",
  "code": "validation_failed",
  "next": "use interval=daily, weekly, monthly, or yearly",
  "next_action": {
    "code": "fix_request",
    "target": "request"
  }
}
```

Kunci kueri yang tidak dikenal juga mengembalikan `422` dengan
`validation_failed`.

## Paket dan kuota

`GET /api/billing/catalog` mencantumkan paket. Endpoint ini tidak memerlukan autentikasi. Setiap paket memiliki semua fitur. Setiap paket memiliki anggota dan proyek tanpa batas. Paket berbeda dalam volume dan retensi. Kuota direset setiap bulan penagihan. 1 GB sama dengan 1.000.000.000 byte.

Anda dapat membeli paket Pro dan Business melalui checkout, dan `checkout_available` bernilai `true`. Untuk Enterprise, kirim email ke alamat `quote_email` paket tersebut untuk meminta penawaran harga. Akun dengan [penawaran untuk akun baru](#new-account-offer) yang aktif mendapat kuota Pro gratis sampai penawaran berakhir.

| Paket | `tier` | Harga per bulan | Log | Metrik aplikasi | Span trace | Peristiwa masalah | Masa simpan |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Free | `developer` | $0 | 50 GB | 50 GB | 50 juta | 100.000 | 30 hari |
| Pro | `team` | $25 | 500 GB | 500 GB | 500 juta | 2 juta | 90 hari |
| Business | `business` | $80 | 2.000 GB | 2.000 GB | 2 miliar | 10 juta | 365 hari |
| Enterprise | `enterprise` | Sesuai penawaran | Khusus | Khusus | Khusus | Khusus | Khusus |

Katalog dan ringkasan penagihan memakai nilai `tier` `developer`, `team`, `business`, dan `enterprise`. Respons penggunaan dan langganan memakai `free`, `pro`, dan `scale`. Paket Business dan Enterprise sama-sama `scale`.

```bash
curl "https://api.logbrew.co/api/billing/catalog"
```

Respons mencantumkan paket dalam urutan ini. Contoh ini menampilkan paket Pro:

```json
{
  "response_version": 1,
  "currency": "usd",
  "interval": "month",
  "checkout_available": true,
  "plans": [
    {
      "tier": "team",
      "monthly_price_cents": 2500,
      "activation": "checkout",
      "quote_email": null,
      "limits": {
        "issue_events": 2000000,
        "log_bytes": 500000000000,
        "metric_bytes": 500000000000,
        "trace_spans": 500000000,
        "retention_days": 90,
        "unlimited_projects": true
      }
    }
  ]
}
```

| Kolom | Arti |
| --- | --- |
| `checkout_available` | `true` jika Anda dapat membeli paket berbayar. Nilainya `false` jika checkout tidak tersedia. |
| `monthly_price_cents` | Harga dalam sen dolar AS. Nilainya `null` untuk paket sesuai penawaran. |
| `activation` | `included`, `checkout`, atau `quote`. |
| `quote_email` | Alamat email tujuan Anda menulis untuk meminta penawaran harga. Nilainya `null` untuk paket lain. |
| `limits` | Kuota untuk 1 bulan penagihan. Nilai `null` ditetapkan melalui kontrak. |

### <span id="data-retention">Retensi data</span>

Retensi adalah jumlah hari LogBrew menyimpan telemetri sebuah akun. Retensi akun
adalah yang lebih besar antara paketnya dan penawaran untuk akun baru yang aktif. Kontrak
Enterprise menetapkan retensinya sendiri.

- Pembacaan hanya mengembalikan telemetri di dalam retensi.
- Setiap hari, LogBrew menghapus telemetri akun yang lebih lama dari retensi
  ditambah 1 hari.
- Setelah paket diturunkan atau penawaran berakhir, retensi yang lebih pendek
  berlaku pada penghapusan harian berikutnya.

## Kesiapan langganan

`GET /api/account/subscription` bersifat hanya baca. Gunakan endpoint ini untuk memutuskan apakah kontrol organisasi diaktifkan. Gunakan endpoint penggunaan untuk status kuota.

```bash
curl "https://api.logbrew.co/api/account/subscription" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

Akun gratis mengembalikan respons ini. Nilai `account_id` di bawah ini
sintetis:

```json
{
  "account_id": "00000000-0000-4000-8000-0000000000aa",
  "tier": "free",
  "billing_interval": "none",
  "state": "free",
  "access_state": "active",
  "current_period_start": null,
  "current_period_end": null,
  "renews_at": null,
  "cancels_at": null,
  "organization_creation_allowed": true,
  "organization_creation_blocker": null,
  "limits": {
    "organizations": 1,
    "members_per_organization": 9007199254740991,
    "projects_per_organization": 9007199254740991,
    "invitations_per_day": 20
  },
  "next": "<display text>",
  "next_action": {
    "code": "create_or_manage_organization",
    "target": "organization"
  }
}
```

Nilai `9007199254740991` pada `members_per_organization` dan `projects_per_organization` berarti tanpa batas. Ini adalah bilangan bulat terbesar yang dibaca persis oleh klien JSON. Tampilkan "Tanpa batas" untuk nilai ini. Hanya jumlah organisasi yang dimiliki akun yang dapat memblokir pembuatan organisasi.

`next` adalah teks tampilan. Tampilkan teks yang dikembalikan, atau lokalkan dari `next_action`. Jangan menulis tetap nama paket dari `next` di kode.

Nilai enum:

| Kolom | Nilai |
| --- | --- |
| `tier` | `free`, `pro`, `scale` |
| `billing_interval` | `none`, `monthly`, `yearly` |
| `state` | `free`, `trialing`, `active`, `past_due`, `paused`, `canceled` |
| `access_state` | `active` untuk `free`, `trialing`, dan `active`. `paused` untuk `past_due`, `paused`, dan `canceled`. |
| `organization_creation_blocker` | `organization_limit_exceeded` atau `null` |

API tidak mengembalikan penghambat `subscription_required` dan `subscription_inactive`. Setiap penghambat punya satu pasangan `next_action`:

| `organization_creation_blocker` | `next_action.code` | `next_action.target` |
| --- | --- | --- |
| `null` | `create_or_manage_organization` | `organization` |
| `organization_limit_exceeded` | `manage_organization_limit` | `organization` |

Nilai tier adalah pengenal, bukan nama tampilan. Jangan ubah nilai itu di klien yang dilokalkan. Periksa `organization_creation_allowed` sebelum Anda mengaktifkan pembuatan organisasi.

Endpoint ini tidak membuat organisasi, mengirim undangan, mengubah peran, atau
mengubah penagihan.

## Undangan organisasi

Pemilik atau admin organisasi mengundang rekan tim lewat email. LogBrew mengirim email berisi tautan ke undangan itu. Undangan kedaluwarsa setelah 7 hari. Endpoint ini menampilkan undangan kepada akun yang diundang sebelum akun itu menerimanya. Undangan adalah milik Anda jika dikirim ke alamat email akun Anda atau metode masuk yang ditautkan ke akun Anda.

Baca daftar undangan Anda yang menunggu:

```bash
curl "https://api.logbrew.co/api/account/invitations" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

Respons berisi undangan menunggu yang belum kedaluwarsa, dari yang terbaru, hingga 100. ID-nya sintetis:

```json
{
  "invitations": [
    {
      "id": "00000000-0000-4000-8000-0000000000c1",
      "organization_id": "00000000-0000-4000-8000-0000000000b1",
      "organization_name": "Example Org",
      "role": "member",
      "state": "pending",
      "created_at": "2026-10-22T12:00:00Z",
      "expires_at": "2026-10-29T12:00:00Z",
      "inviter_name": "Example Owner",
      "accept_path": "/api/organizations/00000000-0000-4000-8000-0000000000b1/invitations/00000000-0000-4000-8000-0000000000c1/accept"
    }
  ]
}
```

Baca satu undangan dari tautannya:

```bash
curl "https://api.logbrew.co/api/organizations/$ORGANIZATION_ID/invitations/$INVITATION_ID" \
  -H "Authorization: Bearer $LOGBREW_ACCOUNT_BEARER"
```

Respons berupa satu undangan dengan kolom yang sama.

| Kolom | Arti |
| --- | --- |
| `organization_name` | Nama organisasi yang mengundang Anda. |
| `role` | Peran yang Anda dapat saat menerima: `admin` atau `member`. |
| `state` | `pending`, `accepted`, `expired`, atau `revoked`. Undangan yang menunggu setelah `expires_at` menjadi `expired`. |
| `inviter_name` | Nama tampilan akun yang mengirim undangan, atau `null`. |
| `accept_path` | Kirim `POST` ke path ini untuk menerima undangan. |

Hanya akun yang diundang yang dapat membaca undangan. Akun lain, ID undangan yang tidak dikenal, dan organisasi yang tidak dikenal semuanya mendapat `404` yang sama dengan `code: "not_found"`. Masuk dengan alamat email yang diundang, lalu coba lagi.

Untuk menerima, kirim `POST` ke `accept_path` dengan akun yang diundang. Penerimaan kedua oleh akun yang sama mengembalikan keanggotaan yang sama. Undangan yang kedaluwarsa atau dicabut mengembalikan `422` dengan `code: "invite_invalid"`. Minta undangan baru kepada pemilik atau admin.

Satu akun bisa mengirim paling banyak 20 undangan per hari UTC, di semua organisasinya. Undangan berikutnya mengembalikan `429` dengan `code: "invitation_limit_exceeded"` dan `limit: "invitations_per_inviter_per_day"`. Tunggu sampai `reset_at`. Lihat [Error API](/id/reference/api-errors#limit-fields).

## Keluar

Pilih lingkup terkecil yang sesuai dengan tugas. Endpoint ini tidak menghapus
akun atau proyeknya, tidak merotasi kunci ingest, dan tidak mencabut izin yang
diberikan penyedia login pihak ketiga.

| Lingkup | Endpoint | Kredensial |
| --- | --- | --- |
| Satu login aplikasi atau CLI | `POST /api/auth/logout` | Refresh token milik klien itu di body JSON. Tanpa bearer. |
| Semua login LogBrew | `POST /api/auth/logout-all` | Bearer akun atau sesi browser. Tanpa body. |
| Sesi browser saat ini | `POST /api/auth/web/logout` | Tidak ada. Respons menghapus cookie browser. |

### Satu login aplikasi atau CLI

Kirim permintaan dari klien yang memegang refresh token. Atur
`Content-Type: application/json`:

```json
{
  "refresh_token": "<current refresh token>"
}
```

Jangan pernah meminta orang atau agen untuk mencetak atau menempelkan refresh
token. Respons yang berhasil adalah `200`:

```json
{
  "revoked": true,
  "next_action": {
    "code": "clear_local_session",
    "target": "local_credentials"
  }
}
```

Permintaan ini mencabut satu keluarga refresh token. LogBrew menolak refresh
berikutnya untuk login itu. Login lain di akun tidak berubah. Token akses yang
sudah dimiliki klien tetap valid sampai kedaluwarsa. Jika kredensial akun
mungkin bocor, gunakan [Semua login LogBrew](#every-logbrew-login).

Setelah respons, klien menghapus kredensial lokalnya. Jika Anda mengirim lagi
refresh token valid yang sama, responsnya tetap `200` yang sama. Jika token
tidak valid, kedaluwarsa, atau berupa token akses, responsnya `401` dengan
`code: "unauthorized"` dan `next_action.code: "authorize_request"`. Dalam
kasus itu, hapus juga kredensial lokal. `logbrew logout` memakai endpoint ini.

### <span id="every-logbrew-login">Semua login LogBrew</span>

<Warning>
  Permintaan ini mengeluarkan semua klien di akun. Dapatkan persetujuan
  pemilik akun sebelum agen mengirimnya.
</Warning>

Respons yang berhasil adalah `200`:

```json
{
  "revoked": true,
  "revoked_before": "2026-09-07T12:00:00.123Z",
  "next_action": {
    "code": "clear_local_session",
    "target": "local_credentials"
  }
}
```

`revoked_before` bersifat inklusif dan punya presisi milidetik. LogBrew
menolak token akses, sesi browser, dan refresh token dari login pada atau
sebelum waktu itu. Token yang kemudian di-refresh dari login seperti itu juga
ditolak. Sesi feed langsung yang sedang berjalan berakhir, dan respons
menghapus cookie sesi browser. Login setelah waktu itu tetap valid. Setiap
klien harus menghapus kredensial LogBrew lokalnya dan masuk lagi.

Jangan masuk lagi lalu mengulangi permintaan ini secara otomatis. Permintaan
baru juga mencabut login yang baru.

Jika respons hilang, jangan laporkan bahwa semua login sudah dicabut. `401`
yang muncul kemudian dari kredensial lama tidak menggantikan respons sukses.
Untuk langkah pemulihan lainnya, baca
[Amankan akun yang disusupi](/id/guides/troubleshooting#secure-a-compromised-account).

### Sesi browser

`POST /api/auth/web/logout` menghapus cookie browser `logbrew_session` dan
mengembalikan `204 No Content` tanpa body. Panggil endpoint ini dari browser.
Jangan salin cookie sesi ke dalam perintah. Permintaan ini tidak mengeluarkan
klien lain, dan tidak mencabut salinan nilai cookie. Untuk mencabut setiap
sesi, gunakan [Semua login LogBrew](#every-logbrew-login).

### Pulihkan dari error saat keluar

| Hasil | Pemulihan |
| --- | --- |
| `401` dari `POST /api/auth/logout` | Hapus kredensial lokal klien. Jangan kirim jenis kredensial lain. |
| `401` dari `POST /api/auth/logout-all` | Masuk dari klien tepercaya jika pengguna masih memerlukan akses. Minta persetujuan lagi sebelum Anda mengulangi permintaan. |
| `405` | Gunakan metode yang disebutkan `next`, dan hanya untuk lingkup yang disetujui pengguna. |
| `invalid_json` dari `POST /api/auth/logout` | Kirim objek JSON dengan `refresh_token` berupa string dan `Content-Type: application/json`. Jangan cetak token. |
| Timeout atau status `5xx` | Jangan laporkan sukses. Jangan memulai loop masuk dan keluar otomatis. Ikuti [aturan operasi tulis](/id/reference/api-errors#writes). |

Untuk rute telemetri, filter, dan paginasi, baca
[API Telemetri](/id/reference/telemetry-api).
