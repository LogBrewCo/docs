---
title: "Terminology"
description: "The exact meaning of the observability and product analytics terms used by LogBrew."
---

LogBrew uses one term for each product concept. API fields, CLI flags, enum
values, event names, and attribute keys remain unchanged in every language.

## Observability signals

<AccordionGroup>
  <Accordion title="Issue">
    A grouped problem that can contain multiple occurrences. An occurrence is
    one captured instance of that issue.
  </Accordion>

  <Accordion title="Log">
    One timestamped event record. A log can carry severity, service, release,
    environment, trace context, and privacy-bounded attributes.
  </Accordion>

  <Accordion title="Trace and span">
    A trace follows work across a request or operation. A span is one timed
    operation inside that trace. A correlation to a trace is evidence of shared
    context; it is not proof of cause.
  </Accordion>

  <Accordion title="Metric">
    A runtime measurement with a defined unit, type, aggregation, and time
    window. Metric points are not interchangeable with log, trace, or issue
    counts.
  </Accordion>

  <Accordion title="Release">
    A deployed application or service version reported with telemetry. A release
    is not the same object as a project or repository.
  </Accordion>

  <Accordion title="Action">
    A classified product event, such as a signup, checkout, import, or failed
    job. An action is not an automated command that LogBrew runs.
  </Accordion>
</AccordionGroup>

## Scope and data quality

| Term | Meaning |
| --- | --- |
| Project | The primary owned product boundary. One project can contain multiple services or repository components. |
| Service | A reporting runtime or component inside a project. |
| Environment | An exact reporting context, such as production or staging. |
| Ingested | Accepted by the ingestion contract. It does not promise indefinite retention. |
| Indexed | Available to the specified index or query. It is not a synonym for ingested. |
| Retained | Present in the evaluated data window. |
| Sampled | Some telemetry was selected before or during collection. |
| Coverage | A measured share with an explicit numerator and denominator. |
| Truncated | The response reached a bound. Omitted data is not necessarily absent. |
| Approximate | Estimated by the documented method rather than counted exactly. |

## Evidence states

These states are not interchangeable:

- **Captured:** the evidence is present.
- **Missing:** the evidence was not captured.
- **Redacted:** the evidence was deliberately concealed.
- **Truncated:** the evidence exceeded a response or capture bound.
- **Unavailable:** the read could not provide the evidence.

`Likely cause` and `likely fix area` describe bounded diagnostic evidence, not a
proven root cause. `Reported impact` is supplied by the reporting application
unless a contract explicitly describes a LogBrew measurement.

## Product analytics

| Term | Meaning |
| --- | --- |
| Event | Classified product activity with an exact stable name. |
| Property | A context key used to describe or filter an event. |
| Session | A visit or app session, not a person. |
| Cohort | A bounded group defined by exact criteria. |
| Funnel | Ordered steps used to measure progression or conversion. |
| Retention | Return behavior measured with an explicit period and denominator. |
| Paths | Session journeys before or after a selected event. |
| Lifecycle | Fixed-period active, returning, resurrected, and dormant states. |
| New in observed history | Active without an earlier selected event in the bounded history window. It does not mean lifetime-new. |

Partial periods, missing identity, incomplete property capture, sampling, and
truncation qualify the result. LogBrew surfaces those limits rather than
turning them into zero or certainty.
