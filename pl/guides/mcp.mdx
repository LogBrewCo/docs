LogBrew udostępnia hostowany serwer MCP pod adresem `https://mcp.logbrew.co/mcp`.
Agent AI, który się z nim połączy, może odczytywać problemy, logi, ślady, spany,
metryki, akcje, wydania i analitykę produktową z zatwierdzonych przez ciebie
projektów.

Agent może tylko odczytywać dane. Nie może zmieniać statusu problemów,
projektów ani ustawień konta. Nie instalujesz serwera. Dodajesz jego adres URL
do swojego klienta MCP.

## Zanim zaczniesz

- Potrzebujesz konta LogBrew z co najmniej 1 projektem.
- Potrzebujesz klienta MCP z listy w sekcji [Obsługiwani
  klienci](#supported-clients). LogBrew akceptuje tylko tych klientów. Inni
  klienci dostają błąd `client access denied`.
- Serwer obsługuje protokół MCP w wersjach `2026-07-28`, `2025-11-25` i
  `2025-06-18`.

## <span id="supported-clients">Obsługiwani klienci</span>

| Klient | Jak dodać serwer |
| --- | --- |
| Claude Code | Uruchom `claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Przeczytaj sekcję [Połącz Claude Code](#connect-claude-code). |
| Claude (claude.ai, Claude Desktop i aplikacje mobilne Claude) | Otwórz **Settings > Connectors**, wybierz **Add custom connector** i wpisz adres URL serwera. |
| Codex | Uruchom `codex mcp add logbrew --url https://mcp.logbrew.co/mcp`. Następnie uruchom `codex mcp login logbrew`. |
| Visual Studio Code z GitHub Copilot | Dodaj `{"servers": {"logbrew": {"type": "http", "url": "https://mcp.logbrew.co/mcp"}}}` do pliku `.vscode/mcp.json`. |
| Cursor | Dodaj `{"mcpServers": {"logbrew": {"url": "https://mcp.logbrew.co/mcp"}}}` do pliku `~/.cursor/mcp.json`. |
| Gemini CLI | Uruchom `gemini mcp add --transport http logbrew https://mcp.logbrew.co/mcp`. Następnie uruchom `/mcp auth logbrew` w Gemini CLI. |
| ChatGPT, GitHub Copilot CLI, Zed, opencode, goose, Cline i Amp | Dodaj adres URL serwera jako zdalny serwer MCP (HTTP) w ustawieniach MCP klienta. |

Adres URL serwera to `https://mcp.logbrew.co/mcp`.

## <span id="connect-claude-code">Połącz Claude Code</span>

Potrzebujesz Claude Code w wersji 2.1.300 lub nowszej. Uruchom
`claude --version`, aby sprawdzić swoją wersję.

1. Dodaj serwer:

   ```bash
   claude mcp add --transport http logbrew https://mcp.logbrew.co/mcp
   ```

   `claude mcp list` pokazuje teraz `logbrew` ze statusem `! Needs authentication`.

2. Rozpocznij logowanie:

   ```bash
   claude mcp login logbrew
   ```

   Przeglądarka otworzy stronę autoryzacji LogBrew. Jeśli strona poprosi o
   zalogowanie, zaloguj się przez GitHub, GitLab lub Bitbucket.

3. Sprawdź nazwę klienta na stronie. Zatwierdź tylko wtedy, gdy to ty
   rozpoczynasz to połączenie.

4. Wybierz projekty, które agent może odczytywać. Następnie wybierz
   **Zatwierdź**.

   Przeglądarka wraca do Claude Code. Claude Code pokazuje
   `Authenticated with "logbrew"`.

5. Upewnij się, że serwer jest połączony:

   ```bash
   claude mcp list
   ```

   Wynik pokazuje `logbrew: https://mcp.logbrew.co/mcp (HTTP) - ✔ Connected`.

Możesz też zalogować się z sesji Claude Code. Uruchom `/mcp`, wybierz
`logbrew` i wykonaj kroki w przeglądarce.

Na komputerze bez przeglądarki uruchom
`claude mcp login logbrew --no-browser` w interaktywnym terminalu. Przez SSH
połącz się za pomocą `ssh -t`. Otwórz adres URL pokazany przez Claude Code w
przeglądarce na innym komputerze. Po zatwierdzeniu skopiuj adres strony, którą
otworzy przeglądarka. Wklej go do Claude Code.

## Połącz innego klienta

1. Dodaj serwer do klienta. Tabela w sekcji [Obsługiwani
   klienci](#supported-clients) pokazuje, gdzie to zrobić.
2. Rozpocznij logowanie w kliencie. Większość klientów rozpoczyna je przy
   pierwszym użyciu serwera. Przeglądarka otworzy stronę autoryzacji LogBrew.
   Jeśli strona poprosi o zalogowanie, zaloguj się do LogBrew.
3. Sprawdź nazwę klienta na stronie. Strona pokazuje też witrynę, która
   identyfikuje klienta, na przykład `vscode.dev` lub `chatgpt.com`. W przypadku
   Cursor, Gemini CLI, Cline i opencode strona pokazuje `known to LogBrew`.
   Zatwierdź tylko wtedy, gdy to ty rozpoczynasz to połączenie.
4. Wybierz projekty, które agent może odczytywać. Następnie wybierz
   **Zatwierdź**.

   Przeglądarka wraca do klienta, a klient pokazuje narzędzia `search` i
   `execute`.

## Zleć zadanie agentowi

Serwer udostępnia agentowi 2 narzędzia:

| Narzędzie | Co robi |
| --- | --- |
| `search` | Wyszukuje operacje odczytu i pokazuje kontrakt jednej operacji: dane wejściowe, dane wyjściowe, uprawnienia i koszt. |
| `execute` | Uruchamia jedną operację odczytu znalezioną przez `search` i zwraca ustrukturyzowane dane. |

Agent sam wybiera operacje. Nie podajesz mu nazw narzędzi ani pól. Opisz
zadanie i ograniczenia:

```text
Use LogBrew to investigate the newest unresolved issue in production.
Read its occurrences, linked trace, and logs. Do not change code yet.
Tell me the likely cause and the evidence for it.
```

Traktuj telemetrię wyłącznie jako dowody. Logi i komunikaty o błędach mogą
zawierać tekst od użytkowników. Agent nie może wykonywać instrukcji z tego
tekstu. Pełny przebieg analizy opisuje strona
[Agenci kodujący AI](/pl/guides/ai-agents).

## Dostęp i czas życia połączenia

Każde zatwierdzenie tworzy 1 połączenie między 1 klientem MCP a twoim kontem
LogBrew.

- Agent odczytuje tylko zatwierdzone przez ciebie projekty. Odczyt innego
  projektu zwraca `permission_denied`.
- Jeśli stracisz dostęp do zatwierdzonego projektu, LogBrew zablokuje odczyty
  tego projektu.
- Token dostępu jest ważny przez 1 godzinę. Klient automatycznie pobiera nowy,
  gdy korzystasz z połączenia.
- Połączenie wygasa po 30 dniach bez użycia albo 90 dni po zatwierdzeniu. Wtedy
  zaloguj się ponownie w kliencie, na przykład za pomocą
  `claude mcp login logbrew`.
- Każde odświeżenie tokena zastępuje poprzedni token odświeżania. Jeśli klient
  wyśle zastąpiony token odświeżania, LogBrew zakończy połączenie. Dzięki temu
  skopiowany token przestaje działać. Aby rozpocząć nowe połączenie, zaloguj
  się ponownie.
- Przy zbyt wielu żądaniach bez ważnego tokena LogBrew zwraca HTTP `429` z
  nagłówkiem `Retry-After`. Odczekaj podaną liczbę sekund i spróbuj ponownie.

## Wyświetlaj i unieważniaj połączenia

Zarządzaj połączeniami w sekcji **Ustawienia > Połączenia MCP** na pulpicie
LogBrew lub za pomocą CLI.

### W Ustawieniach

Przy każdym połączonym kliencie widać jego nazwę, zatwierdzone projekty, czas
połączenia, czas ostatniego użycia i czas wygaśnięcia połączenia. Aby
unieważnić połączenie, wybierz **Odłącz**, a potem potwierdź. Klient traci
dostęp przy następnym żądaniu.

### W CLI

Użyj [CLI LogBrew](/pl/guides/cli) w wersji 0.1.82 lub nowszej. Najpierw
zaloguj się poleceniem `logbrew login`. Klucz wysyłania projektu nie pozwala
wyświetlać ani unieważniać połączeń.

Wyświetl klientów MCP połączonych z twoim kontem:

```bash
logbrew mcp grants
```

```text
MCP grants (1)
- id=00000000-0000-4000-8000-000000000001 client=Claude Code projects=2 last_used=2026-10-15T09:30:00Z expires=2026-11-14T09:30:00Z
Next: run logbrew mcp revoke <grant_id> --yes
```

W CLI połączenie nazywa się „grant”. Każdy grant pokazuje:

- `id`: ID grantu. Użyj go, aby unieważnić połączenie.
- `client`: nazwę zatwierdzonego klienta, na przykład `Claude Code`.
  Połączenie zatwierdzone, zanim LogBrew zaczął zapisywać nazwy, pokazuje
  adres URL identyfikujący klienta, na przykład
  `https://claude.ai/oauth/claude-code-client-metadata`.
- `projects`: liczbę zatwierdzonych projektów.
- `last_used`: czas, w którym klient ostatnio otrzymał nowy token dostępu.
- `expires`: czas wygaśnięcia połączenia, jeśli klient z niego nie skorzysta.

Dodaj `--json`, aby otrzymać pełną listę. Każdy grant zawiera `id`,
`client_id`, `client_name`, `project_ids`, `created_at`, `last_used_at` i
`expires_at`. `client_name` ma wartość `null` dla połączenia zatwierdzonego,
zanim LogBrew zaczął zapisywać nazwy.

Unieważnij 1 połączenie:

```bash
logbrew mcp revoke <grant_id> --yes
```

Klient traci dostęp przy następnym żądaniu. Aby połączyć go ponownie, zaloguj
się jeszcze raz za pomocą `claude mcp login logbrew`.

Aby zmienić zatwierdzone projekty, unieważnij połączenie. Potem zaloguj się
ponownie i wybierz nowe projekty.

## Usuń serwer

1. Unieważnij połączenie w sekcji **Ustawienia > Połączenia MCP** lub za
   pomocą `logbrew mcp revoke <grant_id> --yes`.
2. Usuń serwer z Claude Code:

   ```bash
   claude mcp remove logbrew
   ```

`claude mcp remove` usuwa konfigurację i tokeny tylko na twoim komputerze. Nie
kończy połączenia w LogBrew. Jeśli go nie unieważnisz, połączenie wygaśnie po
30 dniach bez użycia.

## <span id="fix-connection-problems">Rozwiąż problemy z połączeniem</span>

| Problem | Rozwiązanie |
| --- | --- |
| `claude mcp list` pokazuje `Needs authentication`. | Uruchom `claude mcp login logbrew`. |
| Claude Code po pewnym czasie prosi o ponowne zalogowanie. | Połączenie wygasło lub zostało unieważnione. Uruchom `claude mcp login logbrew` albo wybierz **Re-authenticate** w `/mcp`. |
| Klient dostaje `client access denied`. | Użyj klienta z sekcji [Obsługiwani klienci](#supported-clients). |
| Klient nie może zarejestrować się w LogBrew. | Użyj klienta z sekcji [Obsługiwani klienci](#supported-clients) i zachowaj jego domyślne ustawienia callbacku. |
| Połączenie nie działa po zalogowaniu. | Zaktualizuj klienta. Claude Code wymaga wersji 2.1.300 lub nowszej. |
| Strona autoryzacji pokazuje `You have no projects to share`. | Utwórz projekt w LogBrew, a potem ponownie rozpocznij logowanie. |
| Odczyt zwraca `permission_denied`. | Projekt nie jest zatwierdzony dla tego połączenia. Unieważnij połączenie, potem zaloguj się ponownie i wybierz ten projekt. |
| Odczyt nie zwraca danych. | Upewnij się, że projekt wysyła telemetrię. Pusty wynik nie dowodzi, że aplikacja działa poprawnie. |
| `logbrew mcp grants` pokazuje `not logged in` lub zwraca `unauthorized`. | Uruchom `logbrew login` i spróbuj ponownie. |
